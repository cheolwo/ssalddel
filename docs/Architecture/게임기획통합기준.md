## 목적과 문서 권위

이 문서는 여러 기획서에 흩어진 타로, 광복기·암흑기, 심리 영역, 업무 영역, 세계 사건, WI와 플레이어 선택의 **상호 관계**를 한곳에서 관리한다. 세부 카드 수치, 공간 조립법, E/G/H 완료 관문과 구현 현황은 각 전문 문서가 계속 소유한다.

개별 게임 기획의 현행 답변·미정·판본은 이 아키텍처 문서나 새 D 항목에 누적하지 않는다. 예를 들어 오행 순환·회복·광복기의 현재 기획 본문은 `PLAN-GAME-COMMON-PURPOSE-001`의 [전용 기획](../AI/게임상위목적-오행순환과광복기-기획-2026-09-02.md)이 소유하며, 이 문서는 여러 기획이 함께 읽는 개념 관계와 구현 경계만 제공한다.

문서나 코드가 충돌하면 다음 순서로 판단한다.

1. 실제 계약·Domain·시험과 저장·재생 형식
2. [확정 결정](../AI/DECISIONS.md)
3. 이 통합 기획 기준
4. 카드·공간·시나리오별 세부 설계
5. 과거 제안서와 변경 기록

이 문서는 기존 세부 문서를 삭제하거나 내용을 모두 복제하지 않는다. 대신 공통 개념의 이름, 관계와 책임을 소유하고 세부 문서가 어느 질문에 답하는지를 고정한다.

## 게임의 중심 약속

> 게임의 상위 목적은 플레이어가 **나의 오행과 내가 대하는 상대의 오행이 각자의 조건에 맞게 다시 순환하도록 돕고**, 그 순환 개선이 권위 결과로 확인될 때 관련 회복을 쌓아 개인과 공동체가 광복기(회복 우세기)를 맞이할 가능성을 넓히는 것이다.

플레이어는 Nature에서 생존 기반을 만들고 여러 업무 영역에서 선택과 작업을 수행한다. 그 결과는 개인·대상·공동체·세계의 관련 회복과 위협에 누적되고, 카드와 사건은 달라진 상황을 해석할 새로운 선택을 제안한다. Simulation은 조건·비용·시간·결과를 판정하고 Unity는 이를 탐색하고 이해하고 조작할 수 있게 표현한다.

### 나와 상대의 오행 순환이 회복을 높인다

기획에서 `상대` 또는 쉬운 말인 `너`는 플레이어와 상호작용하는 **대상**을 뜻한다. 사람만 가리키지 않는다.

| 상대 종류 | 예 | 오행이 잘 순환한다는 뜻 | 회복을 읽는 기존 상태 |
| --- | --- | --- | --- |
| 사람·집단 | NPC, 동행자, 주민, 조직, 적대자 | 필요·역량·관계·역할이 실제 행동과 결과로 이어지고 중단·갈등 뒤에도 회복 경로가 남음 | 개인 회복·위협, 관계, 숙련, 공동체 관점별 조회 |
| 사물·자원·시설 | 손도끼, 나무, 약초, 밭, 집, 창고, 도로 | 쓰임·상태·내구·생산·수리·운송 관계가 막히지 않고 손상 뒤 복구 또는 적절한 소모·갱신이 가능함 | 내구·기능·용량·품질·생산 상태와 복구 가능성 |
| 환경·공간·생태 | 숲, 농장 경계, 물길, 기상, 서식지 | 접근·순환·생장·안전·위협 관계가 한쪽의 무분별한 소모로 붕괴하지 않고 다시 이어짐 | 생태·공간·경로·안전·생산의 상태와 회복성 |

사물·환경을 `상대`라고 부르더라도 사람처럼 의도·감정·동의가 있다고 가정하지 않는다. 사람과 조직의 주체성·거절 가능성은 보존하고, 적대 대상을 무조건 강화하거나 플레이어에게 복종시키는 것도 오행 순환이 아니다. 위협 상황에서는 피해 중단·격리·분리·퇴로 확보·생태 관계 복구처럼 현재 맥락에 맞는 해결이 순환 회복이 될 수 있다.

`회복`은 실제 결과로 현재 상태가 나아지거나 회복 기여가 쌓이는 것을 뜻한다. 플레이어·NPC·공동체의 회복, 사물의 내구·기능 복구, 시설의 운영 정상화, 환경의 생태·경로 복원이 각각의 기존 소유 상태에서 구체 판정을 담당한다. 모든 대상에 공통인 새 단일 회복 수치나 권위 상태를 만들지 않는다.

`회복역량`은 회복과 구별한다. 손상·실패·위기 뒤에 얼마나 회복할 수 있는지, 어떤 회복 선택지를 열 수 있는지, 회복을 얼마나 지속하거나 효율적으로 수행할 수 있는지를 나타내는 능력·여지다. 회복 결과 하나가 회복역량까지 자동으로 성장시키지는 않는다. 플레이어에게는 **명상 역량의 성장**을 개인 회복역량을 높이는 대표 경로로 둔다. 숙련·시설·관계·지식·비축처럼 해당 역량의 근거와 별도 규칙이 확인될 때만 회복역량 변화 후보가 된다. 현재 공통 회복역량 수치는 구현돼 있지 않으며, 문맥별 기존 상태를 우선 재사용한다.

명상 역량이 높아져 회복역량이 오르더라도 현재 회복을 즉시 채우지는 않는다. 이후 명상·휴식·정신 정리에서 회복 가능한 폭·효율·선택지를 넓히는 방향으로 적용하며, 정확한 변환식·상한·해금 항목은 명상 기획 Profile에서 별도로 확정한다. 현재 회복이 명상 진입을 돕는 기존 관계와 명상 역량이 장기 회복역량을 높이는 관계는 서로 다른 방향이므로, 같은 사건을 왕복시켜 무한 증폭하지 않는다.

`나의 오행`과 `상대의 오행`은 각 개체에 목·화·토·금·수 수치 다섯 개를 저장한다는 뜻이 아니다. [WI 괘성 분류 체계](WI괘성분류체계.md)의 행위·작용·대상·보조 관계로 현재 순환에서 필요한 역할과 결손을 읽는 메타데이터다. 적용되지 않는 괘를 억지로 채우거나 괘성만으로 효율·도덕성·회복량을 계산하지 않는다.

오행이 잘 돈다는 판정은 다섯 값을 같은 양으로 채우는 일이 아니다. 현재 WI에서 필요한 행위·작용·대상·보조 관계가 실제 조건과 권한을 지키고, 결과·피드백·회복 또는 다음 선택까지 같은 판본으로 이어졌는지를 본다. **완료 자체가 아니라 순환 개선이 확인된 완료**만 대상 종류별 판본화된 회복 기여 후보가 된다. 화면 열람·Preview·취소·중복 Confirm·Save 재조회만으로 회복을 반복 지급하지 않는다.

### 공통 목적 정렬 관문

핵심 진행·성장·광복기 기여로 삼는 기획은 [게임 상위 목적 기획](../AI/게임상위목적-오행순환과광복기-기획-2026-09-02.md#하위-기획의-목적-관문)에 따라 `나의 현재 막힘 → 나의 회복 행동과 대가 → 상대에게 적용할 기여 자원 → 상대의 실제 필요 → 권위 결과 → 나와 공동체에 돌아오는 환류`를 설명한다. 단순 관찰·장식·설명·Preview처럼 이 사슬에서 직접 회복을 만들지 않는 부분도 따로 표시한다.

모든 콘텐츠에 회복 수치나 오행 다섯 칸을 강제로 붙이지 않는다. 경관·음악·유머·탐색처럼 세계를 이해하고 머물 이유를 주는 보조 층은 그대로 허용한다. 다만 보조 층을 핵심 회복 기여로 승격하거나 표시·애니메이션·대화 열람을 권위 결과로 치환하지 않는다. 기획 판본, Graph Map 레벨 1과 개발 slice는 이 구분을 잃지 않고 같은 의미를 단계별로 참조한다.

### 한 결과의 행위자·대상·영향 범위를 분리한다

| 구분 | 답해야 하는 질문 | 중복 방지 경계 |
| --- | --- | --- |
| 관점 플레이어 | 누구의 선택과 플레이 경험을 설명하는가 | 플레이어가 관찰했다는 이유만으로 실행자 보상을 받지 않음 |
| 실제 실행 Actor | 플레이어·NPC·세계 중 누가 행동을 수행했는가 | 위임한 플레이어와 수행한 NPC를 같은 Actor로 합치지 않음 |
| 직접 대상 | Actor가 무엇을 직접 사용·소비·수리·보호·제압했는가 | 여러 대상이면 각각의 안정 식별자와 결과를 보존 |
| 영향 범위 | 그 결과로 어떤 개인·집단·시설·경로·생태가 달라졌는가 | 직접 대상과 간접 수혜·피해 범위를 자동으로 같게 보지 않음 |
| 회복 판정 대상 | 누구 또는 어느 범위의 기존 상태가 실제로 개선됐는가 | 한 원인을 개인·공동체·대상 회복에 원시값으로 중복 합산하지 않음 |
| 결과 근거 | 어떤 WI·ActionRecord·Session·Revision·상태 차이가 이를 입증하는가 | 같은 결과의 재조회·재생·재전송으로 다시 지급하지 않음 |

위임에서는 `나`가 관점 플레이어이자 지시자일 수 있지만 실제 실행 Actor는 NPC다. NPC의 완료가 플레이어의 직접 행동으로 바뀌지는 않는다. 플레이어에게 관계·지휘·약속 이행 같은 별도 회복 기여를 줄지는 해당 Profile이 실제 위임·완료·검토 관계를 명시한 경우에만 판단한다.

### 소모·손실·제압도 순환 안에서 별도로 기록한다

모든 직접 대상이 동시에 좋아져야만 순환이 성립하는 것은 아니다. 필요한 소모와 손실을 숨기지 않고, 대상별 결과와 보충·복구 경로가 같은 인과 안에서 보이는지가 중요하다.

- 벌목에서는 개별 나무가 소모되고 목재가 늘어난다. 조림·자연 갱신·허용량이 확인되지 않았다면 숲이나 환경의 회복까지 자동 선언하지 않는다.
- 전투에서는 적대 개체가 피해를 입거나 제거될 수 있고 주민·경로의 안전은 개선될 수 있다. 안전 회복을 적대 개체 자신의 회복으로 바꾸지 않는다.
- 제작에서는 재료가 소모되고 도구·물약·시설 기능이 생길 수 있다. 재료 손실, 생산 결과와 실제 수혜자의 회복을 서로 다른 결과로 남긴다.
- 수리에서는 사물·시설 기능이 회복될 수 있지만 소유자 관계나 공동체 회복은 실제 영향이 확인될 때만 별도 기여가 된다.

회복 기여 후보는 최소한 다음을 모두 만족한다.

1. 같은 WI·Actor·직접 대상·Session·Revision에 결속된 권위 결과 또는 판본화된 부분·실패 결과가 있다.
2. 해당 WI의 기여 Profile이 회복 판정 대상·적격 결과·원인 코드·상한·반복 방지 방식을 명시한다.
3. 전후 상태 차이 또는 확인된 피해 예방으로 실제 개선을 판독할 수 있다.
4. 직접 대상과 영향 범위별 `개선 / 유지 / 손실 / 미확인`을 구분하고 불리한 결과를 지우지 않는다.
5. 개인 기여와 공동체 기여의 원인·대상·범위를 분리하고 같은 원인을 다시 합산하지 않는다.

개인 광복기와 공동체 광복기는 기존처럼 독립 판정하며, 사물·시설·환경 자체를 심리적 광복기 상태로 의인화하지 않는다. 실제 공동체 문제를 완화하고 참여자·대상·영향 범위가 확인된 결과만 별도 공동체 회복 기여 후보가 된다. 광복기는 한 번 도달하면 끝나는 최종 승리 상태가 아니라 회복을 유지·확장하거나 다시 위협에 대응할 수 있는 판본화된 기간 상태다. 메인 스토리의 최종 결말 조건은 별도 기획이 소유한다.

### 현재 구현선과 열린 결손

현재 [SimulationNatureMind](../../Ssalddel.Simulation.Domain/UnityPackage/Runtime/SimulationNatureMind.cs)는 플레이어별 회복·위협 효과와 균형을, [SimulationNaturePeriod](../../Ssalddel.Simulation.Domain/UnityPackage/Runtime/SimulationNaturePeriod.cs)는 플레이어별 평시·광복기·암흑기 전이를 구현한다. 일부 Farm·지역 사건은 현재 구성된 모든 플레이어에게 사건 효과를 배분한다. 이것은 특정 기존 회복 규칙의 구현이며, 영향받은 사람·사물·환경 전반의 회복이나 별도 회복역량이 공통 계약으로 구현됐다는 뜻이 아니다.

후속 구현은 기존 `NatureMind`, 업무 상태와 ActionRecord를 재사용하되, 대표 WI별로 실제 실행 Actor·직접 대상·영향 범위·회복 판정 대상이 동결된 기여 Profile을 먼저 확정해야 한다. 구성원·체류·관측 범위를 확인하지 않은 채 기존 전체 플레이어 배분을 일반 공동체 기여로 확대하지 않는다. 공동체 집계, 사물·환경 상태 연결과 상충 결과 피드백은 현재 열린 결손이다.

현재 첫 실제 플레이 폐루프는 다음과 같다.

```text
안전 빈터 등장
  └─ 도끼 획득
     └─ 벌목과 통나무 획득
        └─ 오두막 건설
           └─ 황혼 위협
              ├─ 전투
              └─ 후퇴
                 └─ 회복과 재출발
```

과거의 `14일 동안 감자 300kg을 농장에서 마트까지 공급` 시나리오는 일반 타로와 경영 규칙을 검증하는 참고 세로 조각이다. 현재 게임 전체의 시작 조건이나 Farm·Hub·City의 의존 순서를 뜻하지 않는다.

### 메인 스토리는 기능의 의미와 다음 선택을 연결한다

메인 스토리는 개별 WI를 대체하는 별도 권위나 강제 진행 순서가 아니다. 제1괘부터 제64괘까지의 제작 순서와 괘→육효 이야기 주계층을 사용하되, 실제 플레이 순서는 별도 승인 전 강제하지 않는다. 괘·효·사건 마디가 [지금·여기·나·너·이렇게의 하위 기획](플레이어중심게임개발업무구조.md#기획의-쉬운-말--지금여기나너이렇게-d394), 기존 PlayableLoop·WI와 표현 근거를 참조하여, 플레이어가 왜 그 기능을 선택하고 결과가 세계에서 어떤 의미를 갖는지 함께 읽게 한다. 기존 Act·Chapter는 호환 묶음으로 유지한다. 단일 기준은 [메인 스토리와 플레이 기능 결속 체계](메인스토리와플레이기능결속체계.md)다.

## 세계 영역과 인과

### 심리 영역

Nature 중심의 상시 체류 세계를 `심리 영역`이라 부른다. 이것은 외부 세계가 플레이어의 마음에서 만들어진다는 설정이 아니다. 업무와 생존 결과가 플레이어의 회복력과 위협 상태에 남긴 영향을 공간과 플레이로 읽을 수 있게 만든 영역이다.

회복과 위협은 하나의 양끝 점수가 아니라 별도 축이다.

- 기여 Profile이 적격으로 판정한 개선 결과는 회복을 강화하고 위협을 완화할 수 있다.
- 손실·실패·기한 초과 결과는 대상과 영향 범위에 따라 회복을 약화하거나 위협을 강화할 수 있다.
- Preview 차단, 단순 취소와 아직 일어나지 않은 제안은 회복·위협 입력이 아니다.
- 심리 영역의 행동은 피해 확산을 완충할 수 있지만 업무 사건의 직접 원인을 종료하지 않는다.

### 업무 영역

Farm·Town·Hub·City는 각각 독립적인 `업무 영역`이다. 각 영역은 내부 선택 폐루프, Fixture, 상태·저장 경계와 완료 증거를 먼저 가진다. 한 영역의 결과를 다른 영역 개발의 필수 시작 상태로 사용하지 않는다.

업무 사건의 원인 해결은 사건이 발생한 업무 영역의 WI가 담당한다. 그 확정 결과만 심리 영역의 회복·위협에 전달한다.

### 평시·광복기·암흑기

세 상태는 전 세계에 일괄 적용되는 역사 시대가 아니다. 개인과 공동체의 관점별 상태를 서로 분리해 판정하며, 아래 표의 `80% / 75%`는 **플레이어 개인의 심리 기간에 적용하는 현행 규칙**이다.

| 상태 | 뜻 | 현재 개인 규칙 |
| --- | --- | --- |
| 평시 | 회복과 위협 어느 쪽도 기간 전환 기준을 충족하지 않음 | 기본 상태 |
| 광복기 | 회복이 우세해 복구·확장 기회가 열리는 시기 | 회복 비중 `80% 이상` 진입, `75% 미만` 이탈 |
| 암흑기 | 위협이 우세해 생존·방어·복구가 중심이 되는 시기 | 위협 비중 `80% 이상` 진입, `75% 미만` 이탈 |

`광복기`는 역사적 시대 재현을 뜻하지 않도록 사람이 읽는 문서와 UI에서 처음 한 번 `광복기(회복 우세기)`로 병기한다. `암흑기`도 단순한 화면 색상이나 분위기가 아니라 Simulation이 판정한 위협 우세 기간이다.

현재 개인 규칙의 `80% / 75%`는 구현된 정책 개정의 값이다. 이후 플레이테스트로 변경할 수 있지만, 변경할 때는 규칙 개정·저장 호환·결정성 시험을 함께 갱신한다. 공동체 광복기·암흑기는 별도 공동체 회복·위협 원인과 집계 Profile로 판정하고 개인 상태를 덮어쓰지 않는다. 개인 문턱을 공동체에 자동 복사하지 않으며, 공동체 전용 판본에서 확정·시험하기 전에는 후보로만 유지한다.

### 두 발전소

`회복 발전소`와 `위협 발전소`는 회복·위협 상태를 읽고 대응할 수 있게 만드는 심리 영역의 H2 복합 공간 후보다.

- 발전소는 업무 성공이나 실패의 원인을 만들지 않는다.
- 발전소 표현이 업무 원장을 변경하지 않는다.
- 회복·위협 상태를 같은 수치나 하나의 발전소로 합치지 않는다.
- 실제 H1 등록, H2/H3 조립, Scene 배치와 Game View는 각각 별도 증거가 필요하다.

## 카드 체계

### 카드의 공통 역할

카드는 세계 상태를 직접 확정하는 버튼이 아니라 상황을 읽고 선택을 구성하는 게임 문법이다.

```text
카드 또는 문맥 제안
  → 플레이어가 의미와 대가를 비교
  → 허용된 대응 선택
  → WI Preview
  → 명시적 Confirm
  → Task 또는 WorldTick
  → 확정 상태 재조회
```

카드가 자원·생산량·재고·사건·H 공간을 직접 생성해서는 안 된다. 권한, 수량 보존, 단위, 용량, 상태 전이와 Simulation·Operational 경계를 우회할 수도 없다.

### 타로 여정 의미

- `바보`는 항상 활성인 `JourneyRoot`다. 뽑기 결과나 능력치 보정 카드로 사용하지 않는다.
- 다른 메이저 아르카나는 현재 상황을 해석하는 `ActiveMajorArcana` 프레임이다.
- 기존 `learning:hongik.fool.beginner-mind` 고유 식별자는 저장 호환을 위해 유지하지만 일반 타로 전체를 학당 콘텐츠로 만들지는 않는다.
- 여정 루트와 현재 아르카나는 제안·사건·Effect를 직접 만들지 않는다.

### 일반 경영 타로

첫 규칙 뼈대는 여제·전차·정의·절제다.

| 카드 | 중심 질문 |
| --- | --- |
| 여제 | 무엇을 돌보고 길러야 하는가? |
| 전차 | 얼마나 빠르게, 어떤 통제로 이동할 것인가? |
| 정의 | 무엇을 같은 기준으로 검증하고 나눌 것인가? |
| 절제 | 어떤 자원을 섞고 아껴 균형을 맞출 것인가? |

Simulation은 seed·턴·덱 개정·선택 이력으로 세 장을 결정한다. 기존 세션은 호환을 위해 seed 기반 방향 판정을 기본으로 유지한다. 세계 문맥형 프로필에서는 플레이어가 메이저 아르카나의 정체성만 선택하고, 방향은 활성화 시점의 권위 세계 상태로 Simulation이 판정한다. 정방향과 역방향은 같은 값을 단순 반전하지 않고 서로 다른 기회·부담 묶음을 가진다. 선택한 카드는 허용된 하위 업무 규칙에 보정선을 제공하며 실제 결과는 하위 규칙과 불변 조건 검증을 통과해야 한다.

### 메이저 아르카나 활성화와 방향 가변성

- 카드의 정체성은 지속되지만 정·역방향은 카드 고유 식별자의 영구 속성이 아니다. 방향은 각 `MajorArcanaActivationStableId`에 귀속된다.
- 같은 카드도 서로 다른 활성화에서는 판정 당시 세계 상태에 따라 다른 방향이 될 수 있다. 활성화 중에는 Tick·NPC 상태·심리 기간이 바뀌어도 방향을 다시 계산하지 않는다.
- 카드 교체·해제·향후 재방향 판정은 기존 활성화 값을 수정하지 않는다. 기존 활성화를 종료하고 새 활성화·판정·상속 계보를 만든다.
- 첫 세계 문맥형 정책 `RecoveryShare51`은 `회복 출력 ÷ (회복 출력 + 위협 출력)`을 백만분율 고정 정밀도로 판정한다. `510000` 이상은 정방향, `509999` 이하는 역방향이며 분모가 0이거나 근거 hash가 없으면 활성화를 거부한다.
- 방향은 하위 카드 계층을 재귀 순회하지 않는다. 활성화에서 각 최종 카드로 `Numeric | Interpretive | Ordering | DirectionOnly` 영향을 한 번만 펼치고, 결정적 상속 고유 식별자의 중복은 오류로 처리한다.
- 수치 영향은 허용된 Effect 연결점에만 적용한다. 첫 Town 생활복구 Fixture는 `기본값 × 하위 카드 × 방향 × 심리 기간`을 조립한 뒤 `0.75~1.30` 제한을 정확히 한 번 적용하고 계산 계보를 저장한다.
- 활성 아르카나가 없으면 저장용 중립 상속 객체를 만들지 않는다. 계산 시에만 중립 방향과 `1.0` 기본값을 사용한다.

첫 Town 자동시험 Fixture는 공동상점 직원 1명, 주민 2명과 비상식량·휴대용 배터리·방수포를 사용한다. 욕구 평가는 `WorldDerived`, 주문·수령·소비는 `NpcDriven`, 아르카나 선택은 `PlayerDriven`으로 구분하며 배터리 경쟁은 욕구 심각도→요청 개정→NPC 고유 식별자 순으로 결정한다. `WI-ORDER-01~07` 이후 소비 Effect가 욕구를 바꾸고 다음 목표 평가로 돌아간다. 이 물품은 브랜드·가격·실구매를 포함하지 않는 Simulation 전용 Fixture이며 플레이어에게 NPC 예약·수령·소비·목표 덮어쓰기 명령을 노출하지 않는다.

### 생존 타로

생존 타로는 주기와 식량 위기 같은 Session 조건에서 기회를 제안한다. 안전 거점에 참여자가 모이고 같은 제안에 합의한 뒤에만 확정하며, 효과는 다음 Tick에 한 번 적용한다. 재고를 새로 만들거나 접근·용량 규칙을 우회하지 않는다.

### 다른 카드군

| 카드군 | 역할 | 직접 하지 않는 일 |
| --- | --- | --- |
| 팀 역할 카드 | 탐험·농업·건설·전투·물류 같은 역할 배정 | 물리 아이템 소유권 대체 |
| 수집 보상 카드 | 탐험·농사 결과의 개인 수집과 표현 | 초기 규칙에서 수치 효과·기능 해제 |
| 학당·문화 카드 | 철학·문화·교육의 선택형 콘텐츠 | 일반 타로 기본 덱 대체 |
| 근거·지식 카드 | 출처·관측 시각·판본·한계 설명 | 사건이나 Effect 직접 생성 |

카드군 사이에는 고유 식별자, 저장 의미와 승격 절차를 공유하지 않는다. 같은 그림이나 원형을 사용하더라도 게임 역할이 다르면 별도 정의로 관리한다.

## 현실 문맥·사건·WI·Effect

다음 다섯 단계를 섞지 않는다.

| 단계 | 의미 |
| --- | --- |
| 현실·관측 문맥 | 세션 시작 때 승인 자료에서 동결한 읽기 전용 근거 |
| 상황 제안 | 사건 또는 행동 후보를 검토하도록 제공한 미확정 문맥 |
| 세계 사건 | Simulation Session에서 조건과 개정이 확정된 기회·문제 |
| WI | 주체가 사건이나 목표에 대응하는 실행 단위 |
| Effect | Confirm·Task·WorldTick을 통과해 세계 상태에 남은 결과 |

현실자료는 `ContextProposal`이며 `Incident`나 `Effect`가 아니다. 자료의 값만으로 생산량·수익·사건·공간 배치를 바꾸지 않는다.

WI 실행 인스턴스의 발생원은 네 가지다.

```text
데이터 발생 DataDriven
플레이어 발생 PlayerDriven
NPC 발생 NpcDriven
세계 종합 발생 WorldDerived
```

WI 정의는 허용 발생원 목록을 갖고, 실행 인스턴스는 실제 발생원을 기록한다. 공개 Confirm 요청에서 클라이언트가 발생원 코드를 임의 선택하지 않는다. 발의·수행·진행·권위 같은 실행 상세는 발생원과 별도로 보존한다.

## 공간과 플레이의 연결

영역 안의 건물 발전은 [영역별 건물 발전 테크트리 계획](영역별건물발전테크트리계획.md)을 따른다. Nature·Farm·Town·Hub·City는 독립된 누적 테크트리를 가지며, 플레이어의 H1 건설이 H2·H3 성장을 유도하더라도 상위 공간 성립은 Simulation 규칙이 별도로 판정한다. 첫 실제 세로 조각은 Nature이고 다른 네 영역은 현재 공통 카탈로그 기준선이다.

H는 카드 등급이나 증거 성숙도가 아니라 공간의 의미 깊이다.

| H | 게임 기획 의미 |
| --- | --- |
| H1 | 플레이어가 직접 사용·배치·복구하는 작업공간과 객체 |
| H2 | 여러 H1이 기능과 연결구를 갖춰 형성한 블록 |
| H3 | H2 사이의 이동·위협·회복·생산 폐루프가 닫힌 경관 |
| H4 | Nature·Farm·Town·Hub·City 같은 AreaSet |
| H5 | AreaSet과 전이 관계를 배치한 세계 |

카드 제안이나 발전소 이미지가 존재한다는 이유만으로 H1~H3가 성립하지 않는다. H 공간은 필요한 WI, 자원·시간·배치 조건, 연결구, 귀환 경로와 Simulation 계보를 함께 가져야 한다.

## 실행 권위와 저장

- Solo는 Unity 프로세스의 `LocalProcess`, Hosted는 Simulation 서버의 `RemoteHost`에서 같은 Simulation Core를 실행한다.
- Unity는 선택 입력과 표현을 담당하지만 운영 원장이나 Simulation 결과를 독자적으로 확정하지 않는다.
- `Proposal != Incident != Effect`를 유지한다.
- 상태 변경은 `Preview → Confirm → Task/WorldTick → 기준 상태 재조회`를 따른다.
- 카드 제안, 방향, 선택, 기간 상태, WI 발생원과 확정 결과는 해당 저장 판본의 Save/Replay 정규형에 포함한다.
- 새 관측이나 Provider 응답은 이미 시작한 세션의 동결 문맥과 재생 결과를 바꾸지 않는다.

## 현재 기획 우선순위

1. Nature 생존 생활거점의 선택·대가·귀환 폐루프를 실제 플레이로 닫는다.
2. 회복·위협과 평시·광복기·암흑기의 피드백을 플레이어가 이해할 수 있게 연결한다.
3. 카드가 사건과 WI 사이에서 어떤 선택을 여는지 좁은 세로 조각으로 검증한다.
4. Farm·Town·Hub·City의 독립 내부 폐루프를 각각 완성한다.
5. 독립 영역 준비가 확인된 뒤 Nature↔Farm 같은 영역 간 통합을 연결한다.

다음 항목은 현재 통합 기준의 완료를 뜻하지 않는다.

- 타로 78장 전체 데이터와 최종 밸런스
- 여러 활성 타로의 중첩 우선순위
- 두 발전소의 실제 H 승격과 최종 Scene 배치
- 광복기·암흑기의 최종 UI·음향·환경 연출
- 대표 WI별 실행 Actor·직접 대상·영향 범위·회복 판정 대상의 정확 기여 Profile
- 공동체 집계와 사물·환경 상태를 잇는 상충 결과·중복 방지 규칙
- 전체 카드군의 Play Mode·Game View 검증
- 운영 Provider 호출이나 운영 상태 변경

## 변경 관리

새 카드·시기·영역·사건 개념을 추가할 때는 다음 순서를 따른다.

1. 이 문서의 기존 개념으로 설명 가능한지 확인한다.
2. 새 개념이 플레이어에게 여는 선택과 다음 선택을 적는다.
3. `상황 제안 / 세계 사건 / WI / Effect` 중 어디에 속하는지 정한다.
4. 권위 소유자와 Save/Replay 영향을 정한다.
5. 필요한 H 공간과 E 증거 목표를 분리해 적는다.
6. 세부 수치·자산·API는 해당 전문 문서와 코드에 둔다.
7. 장기 결정이 바뀌면 `DECISIONS.md`에 대체 관계를 남긴다.

기존 전문 문서를 삭제할 때는 이 문서가 그 세부 책임까지 실제로 흡수했는지, 외부 링크와 확정 결정이 새 경로를 가리키는지 먼저 확인한다. 단순 중복처럼 보여도 구현 이력과 호환 근거를 가진 문서는 바로 삭제하지 않고 `세부 기준`, `구현 기록` 또는 `대체됨`으로 역할을 먼저 표시한다.
