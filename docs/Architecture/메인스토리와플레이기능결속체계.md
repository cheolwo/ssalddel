# 메인 스토리와 플레이 기능 결속 체계

> 현행 기준(2026-09-05): [스토리 영감과 플레이 진행 분리](스토리영감과플레이진행분리.md). 인물·사건·선택과 인과를 먼저 구성하고 괘·효는 선택적 참고로 사용한다. 아래 기존 판본의 고정 64캠페인·육효 진행·순차 제작 관문은 대체된 이력이며 신규 기획과 실행 규칙으로 적용하지 않는다.

## 현행 제작 흐름

이야기 씨앗 → 인물의 목적·갈등 → 선택·대가·결과·회복 → 사건 구성 → 개별 PLAN → 준비된 주체·WI → 필요한 공간·표현·검증. 괘·효 자료는 이 과정 어디에서나 참고할 수 있다. 원문과 각색 차이를 기록하며 기존 안정 ID와 승인된 구체 사건은 보존한다.

## 이전 제작 체계와 참조 이력

- 문서 성격: 메인 스토리·하위 기획·PlayableLoop·WI를 함께 읽는 공통 기준
- 적용 범위: Simulation과 Unity 게임 기획
- 비적용 범위: 스토리 문장만으로 권위 상태·퀘스트 완료·E 성숙도를 변경하는 것

## 목적

메인 스토리는 플레이어에게 **왜 지금 이 장소에서 이 대상과 상호작용하는지** 의미를 제공한다. 스토리의 제작은 [역경 64괘 기반 게임 스토리 기획·제작 체계](../AI/Planning/스토리/PLAN-STORY-HEXAGRAM-SEQUENCE-001/README.md)에 따라 역경의 괘·효를 게임의 상황·주체·변화로 번역하며 제1괘부터 한 괘씩 진행하지만, 개별 기능과 실제 플레이를 그 번호의 일직선 순서로 강제하지 않는다. 이미 기획된 `지금·여기·나·너·이렇게 → 결과 → 다음 선택` 문서를 하위 근거로 참조해 주체와 WI가 하나의 세계 변화로 읽히게 한다. 여러 WI의 성공·실패·회복·귀환을 함께 검증해야 할 때만 PlayableLoop를 추가한다.

스토리는 기능 권위가 아니다. 실제 수행 가능 여부·비용·결과·완료는 기존 Simulation 상태, WI, 행위 기록과 판본이 판정한다. 스토리 표식·대사·카메라·연출만으로 퀘스트를 생성하거나 완료하지 않는다.

## 계층

```text
메인 스토리
├─ 제1괘 건·제2괘 곤: 정식 제작 순서의 기반 흐름
│  └─ 효: 이후 구체 서사가 따라야 할 여섯 거시 국면
└─ 제3괘 수뢰둔 이후: 인물·장소·사건의 구체 서사 괘
   └─ 효사 기획(Line Plan): 안정 기획 ID로 추적하는 여섯 변화
      └─ 사건 마디(Story Beat): 플레이어가 알아차리고 선택하는 한 인과
         ├─ 하위 기획: 지금·여기·나·너·이렇게·결과·다음 선택
         ├─ 등장 주체 후보: Actor·대상·시설·환경·세계 규칙
         ├─ WI: 준비된 주체 사이에서 실제로 수행하는 행위와 직접 결과
         ├─ 선택적 PlayableLoop: 여러 WI의 성공·실패·회복·귀환 검증 묶음
         └─ 표현: 대상·H·자산·UI·대사·카메라 후보와 E 근거
```

- 기존 장(Act)·장면(Chapter)은 삭제하거나 재번호화하지 않고 출판·탐색·과거 링크를 위한 호환 묶음으로 유지한다. 새 제작 순서의 주계층은 괘 이야기→효 이야기다.
- 제1괘 건과 제2괘 곤의 효는 거시 국면이므로 필수 Story Beat나 WI를 직접 요구하지 않는다. 제3괘 이후에는 모든 효에 `PLAN-STORY-HEX##-LINE-###` 안정 기획 ID를 부여하고, 실제 문답이 시작된 효만 독립 문서로 펼친다. 한 효사 기획은 하나의 필수 주 Story Beat를 가지며 필요하면 보조 Story Beat를 하위에 둘 수 있다. 효 문장만으로 Story Beat·WI·H를 자동 생성하지 않는다.
- 효사 기획은 주체·WI·H1~H4·Graph Map·배치 맵의 필요성을 `Required`, `Optional`, `NotApplicable`로 선언한다. 이는 구현 요구사항이며 실행 권위가 아니다. `Required` 항목이 `ExistingReused` 또는 승인된 새 정의로 해소되기 전에는 `ReadyForDevelopment`가 될 수 없다.
- 하나의 효사 기획이 여러 WI를 요구할 수 있지만 개발 Goal 하나는 WI 하나만 소유한다. H2 이상은 하위 H와 관계 조건에서 파생하며 효사 기획이 직접 생성하거나 승격하지 않는다.
- 메인 스토리는 여러 독립 영역을 설명할 수 있지만 Farm·Town·Hub·City의 독립 실행성을 없애지 않는다.
- 장면은 반드시 하나의 선형 퀘스트만 요구하지 않는다. 같은 준비 목적을 대화·조사·운반·제작·전투 같은 대체 WI로 충족할 수 있다.
- 사건 마디는 기능을 새로 발명하는 단위가 아니다. 기존 WI를 재사용할지, 조합 WI가 필요한지, 새 WI 검토가 필요한지를 명시한다.
- 하위 기획 문서는 스토리의 구체 상황을 소유한다. 메인 스토리 문서는 하위 문장의 원문을 복제하지 않고 판본 링크와 채택 의미만 가진다.

## 플레이 순서를 보이되 자유를 보존한다

`제작 순서`와 `실제 플레이 순서`를 분리한다. 제작 순서는 64괘 정식 순서이며, 현재 괘의 여섯 효 이야기와 전체 인과가 기획 승인을 통과하면 다음 괘의 제작을 연다. 실제 플레이 순서는 별도 기획이 승인할 때까지 `DeferredBranchable`이며, 괘 번호만으로 해금·자동 수락·강제 이동을 만들지 않는다.

메인 퀘스트와 연결된 기획은 플레이어가 현재 위치와 앞뒤 관계를 알 수 있도록 `괘·효 위치`, `메인 위치`, `순서 유형`, `필수 선행`, `현재 사건`, `다음 후보`, `이탈·귀환 조건`을 함께 표시한다. 괘·효 배정이 아직 승인되지 않았다면 임의 번호를 만들지 않고 기존처럼 `서장 후보`, `초반 생활 인과`, `후속 귀환 후보`를 사용한다.

| 순서 유형 | 의미 |
| --- | --- |
| 필수 선행 | 해당 사건의 권위 결과를 성립시키려면 먼저 충족해야 하는 상태·지식·관계 |
| 권장 순서 | 이야기를 가장 자연스럽게 이해하게 돕지만 건너뛰거나 나중에 돌아올 수 있는 경로 |
| 선택 분기 | 같은 목적을 다른 행동·대가·관점으로 수행하는 대안 |
| 병행 가능 | 다른 Area·일반 퀘스트·자유 WI와 함께 진행해도 되는 준비 |
| 조건부 귀환 | 이탈 뒤 보존된 결과와 재진입 조건으로 다시 이어지는 사건 |
| 자유 | 메인 경로와 연결되지 않아도 독립적으로 완결되는 활동 |

이 표시는 기획과 플레이 안내를 위한 순서다. 목록에 먼저 나온 사건을 자동 수락·강제 이동·유일한 WI·완료 처리로 바꾸지 않는다. 실제 해금과 완료는 권위 상태가 판정하고, UI에서 어디까지 보여 줄지는 별도 Presentation 기획과 증거가 필요하다.

## 사건 마디의 필수 기록

| 항목 | 기록할 내용 |
| --- | --- |
| `StoryBeatStableId` | 판본과 무관하게 추적할 사건 마디 식별자 |
| 괘·효 참조 | 승인된 `HEX-##-*`와 `HEX-##-*-L#`. 미정·프로토타입이면 상태를 함께 기록 |
| 플레이 순서 | 메인 위치, 순서 유형, 필수 선행, 현재 사건, 다음 후보, 이탈·귀환 조건 |
| 이야기 약속 | 플레이어가 이 장면에서 느끼고 이해할 핵심 의미 |
| 시작 지식 | 장면 전 플레이어가 실제로 발견·공개받은 사실 |
| 하위 기획 참조 | 지금·여기·나·너·이렇게·결과·다음 선택을 소유하는 문서·판본 |
| 주체 참조 | 기존 주체 재사용 후보, 새 주체 필요 여부, Actor·직접 대상 역할과 권위·저장 경계 |
| 기능 참조 | WI·Goal·작업 명세와 선택적 PlayableLoop. 미정이면 미정으로 남김 |
| 선택과 대가 | 선택지, 필요한 시간·재료·위험·포기하는 기회 |
| 권위 결과 | 같은 판본의 상태 변화·행위 기록·실패·회복·귀환 |
| 이야기 변화 | 결과 뒤 플레이어가 새로 아는 사실과 세계·관계의 의미 변화 |
| 다음 갈래 | 새 후보, 보류, 다른 영역 이동, 자유 탐색으로 돌아가는 길 |
| 표현 준비 | VisualKey·대상/H·자산 후보·UI/대사·카메라·fallback과 현재 Presentation E |
| 경계 | 강제 진행, 자동 수락, 현실 자료 필수화, 권한 누출 등 금지 사항 |

## 기능과 스토리를 함께 판정하는 방법

1. 먼저 하위 기획에서 지금·여기·나·너·이렇게와 원하는 결과를 확인한다.
2. 등장 주체를 식별하고 기존 `Ready` 주체를 재사용할지, 구체 정체성을 가진 새 주체가 필요한지 판정한다.
3. 준비된 주체 사이에서 같은 의미를 가진 기존 WI를 찾는다. 이름이 비슷하다는 이유만으로 연결하지 않는다.
4. WI 하나를 Goal로 고정하고 직접 결과를 먼저 닫는다. 주변·공동체 효과는 별도 파생 작용으로 최대 2-hop까지만 연다.
5. 둘 이상의 WI를 반복 폐쇄성으로 함께 검증할 필요가 있을 때만 기존 PlayableLoop를 연결하거나 새 묶음을 검토한다.
6. 플레이어가 장면 전에 알 수 있는 사실만 시작 조건으로 사용한다. 개발 문서의 내부 상태를 캐릭터 지식으로 자동 공개하지 않는다.
7. 일반 퀘스트·자유 행동·관찰은 메인 사건의 **준비 경험**이 될 수 있지만 원시 완료 횟수로 해금하지 않는다.
8. 메인 사건은 권위 결과가 성립한 뒤에만 이야기 변화를 만든다. 실패·중단·보류도 후속 선택을 가진 정상 갈래로 남긴다.
9. Presentation E4는 사건의 판독 순간과 후보를 준비한다. E5는 [E1~E4 전체 맥락 소비 관문](플레이폐루프논리시각이중순환체계.md#e5는-e1e4-맥락을-소비하는-실제-결속-관문이다)을 통과해 실제 자산·배치·입력과 결속한다.
10. 실제 Game View가 이야기 의도와 다르면 화면에 맞춰 스토리를 소급 변경하지 않는다. 가장 이른 기획·Logic·Presentation E를 다시 연다.

## 메인과 일반 플레이의 관계

- **일반 퀘스트와 자유 WI:** 사람·시설·환경·문제 원인을 알아가고 필요한 준비를 쌓는 대체 가능한 경험이다.
- **메인 퀘스트:** 세계의 공통 문제나 관계 변화처럼 다음 장의 의미를 여는 사건이다. 금색 표식은 해금 후보이며 수락과 완료는 별도다.
- **자유 탐색:** 메인 진행을 멈추고 다른 Area나 관심 활동으로 이동할 수 있다. 복귀할 때 이미 확인한 사실과 권위 상태를 재사용한다.
- **현실 자료:** 관심이 생겼을 때 별도로 여는 설명층이다. 게임 완료의 필수 조건이나 정답·수익 보장이 아니다.

## 문서 연결 규칙

메인 스토리 문서는 각 장면마다 다음 링크를 둔다.

```text
괘 이야기 → 효 이야기 → 메인 스토리 사건 마디
  → 하위 지금·여기·나·너·이렇게 기획
  → 관련 질문/결정
  → 등장 주체와 WI Goal
  → 선택적 PlayableLoop 검증 묶음
  → E7 작업 명세와 EvidencePackage
  → 실제 표현·Game View 근거(존재할 때만)
```

제3괘 이후의 현행 추적 경로는 다음처럼 구체화한다.

```text
괘 이야기 → 효사 기획 ID·판본·hash → 원문 적합도 → 필수 Story Beat
  → 준비된 주체 → 필요한 WI → 필요한 H1~H4
  → Graph Map·배치 맵 영향 → WI별 개발 Goal → Evidence
```

`StoryApproved`는 원문과 게임 이야기의 결속 승인이고, `ReadyForDevelopment`는 필수 주체·WI·H와 인계 판본까지 해소된 상태다. 두 상태를 합치지 않는다.

반대 방향도 유지한다. 하위 기획이나 작업 명세에는 자신이 어떤 사건 마디를 지원하는지 선택적으로 기록한다. 스토리와 연결되지 않은 독립 WI도 허용하며 억지로 메인 스토리에 편입하지 않는다.

## 원작이 따로 있는 경우의 결속 관문

외부 프로젝트·소설·과거 기획처럼 별도 원작이 메인 스토리 기준이면, 원문을 읽기 전의 기존 게임 기획은 `임시 결속 골격`으로만 유지한다. 원작 제목이나 짧은 설명만으로 인물·사건·반전·결말을 추정하지 않는다.

원작 확인 뒤에는 다음 순서로 판정한다.

1. 원작의 사실·관점·인물 관계·핵심 사건·결말을 출처 판본과 함께 추출한다.
2. 게임에 그대로 유지할 것, 매체에 맞게 각색할 것, 추가 확인할 것, 제외할 것을 나눈다.
3. 채택한 사건만 하위 `지금·여기·나·너·이렇게` 기획과 연결한다.
4. 기존 PlayableLoop/WI가 같은 의미를 갖는지 대조하고, 이름이 비슷하다는 이유로 자동 결속하지 않는다.
5. 원작과 게임 기능이 충돌하면 권위 규칙을 스토리에 맞춰 조용히 변경하지 않고 기획 선택을 다시 연다.

## 현재 첫 적용

[메인 스토리 기준선](../AI/메인스토리-거울의흐름-기획-2026-09-01.md)은 ChatGPT 개인 프로젝트 `흑막상인`의 원문 결속을 기다리는 임시 골격이다. 정식 제작은 `HEX-01-QIAN` 제1괘 중천건부터 시작하되, 제1괘 건과 제2괘 곤은 전체 이야기의 거시 흐름을 정하는 기반층이고 실제 인물·장소·사건의 구체 서사는 `HEX-03-ZHUN` 제3괘 수뢰둔부터 시작한다. 기존 [한스 농장 기획](../AI/한스농장-첫벌목과울타리수리-기획-2026-09-02.md)의 수뢰둔 배정은 첫 구체 서사 후보인 `PrototypeReference`로 보존하지만 제3괘 제작 승인이나 순서 해제의 근거로 사용하지 않는다. 이는 이야기 제작 구조와 원작 결속 준비이며 전체 스토리, 퀘스트 그래프, runtime 해금 또는 Unity 구현 완료가 아니다.
