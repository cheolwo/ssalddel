# 전 행위 몰입과 명상 숙련·행위 원장 통합 체계

## 목적

플레이어가 물질 획득, 전투, 건설, 학습처럼 서로 다른 행위를 하더라도 그 행위에 집중한 경험은 공통 `명상 숙련`으로 남긴다. 명상은 돈이나 자원을 대신하는 보상이 아니며, 물질 활동과 정신 활동을 서로 배척하는 규칙도 아니다. 플레이어가 무엇을 했는지는 분야 숙련이, 그 행위를 얼마나 몰입해서 수행했는지는 명상 숙련이 기록한다.

이 문서는 모든 플레이어 WI가 따라야 할 공통 행위 처리 경계와 현재 구현 범위를 정의한다. 첫 적용은 `WI-NATURE-06 벌목`이지만 카탈로그는 플레이어 분야 WI 전체를 빠짐없이 분류한다.

## 오행 분류와 명상 관계

현행 WI 105개의 오행 분류와 이 문서의 플레이어 명상 WI군은 서로 다른 책임을 가진다. 오행 분류는 주체가 무엇을 어떻게 어떤 대상에 수행했는지를 설명하고, 명상 WI군은 그중 실제 플레이어 경험을 같은 행위 기록에서 되돌아볼 수 있는지를 분류한다. 현재 명상 카탈로그가 판정하는 65개 플레이어 분야 WI는 현행 전체 WI의 부분집합이며, 두 수가 다르다고 누락이나 자동 적용을 의미하지 않는다.

공통 조회 순서는 `WI 오행 메타데이터 → 실제 Actor·발생원 → 권위 결과·ActionRecord → 명상 적용 상태 → 승인된 성장·회복·위협 Profile`이다. 오행이 분류됐다는 사실만으로 명상 보상이나 회복·위협 변화를 만들지 않고, 명상 Family에 결속됐다는 사실만으로 집중 Profile을 `Applied`로 승격하지 않는다. NPC·자동·운영 행위는 사유 있는 상태를 유지하며 플레이어의 직접 수행으로 치환하지 않는다.

주체가 실제로 수행한 행위의 오행 경향을 보여 주는 `오행 활동 발자국` 파생 투영을 같은 행위 계보에 추가한다. 이 투영은 `ActionRecordAppend` 후의 독립 소비자로 계획하며 기존 실행 Trace에 새 권위 단계를 끼워 넣지 않는다. `PlayerProgressionApply`·`MeditationProgressionApply`·`NatureMind` 회복·위협 적용과 동일한 기록을 읽을 수는 있지만 서로의 수치나 성공 판정을 대신하지 않는다.

## 비실행 상위 명상 WI군

모든 구체적 플레이어 WI는 `wi-family:meditation`이라는 상위 `명상(정신 차림) WI군`으로 분류한다. 이 WI군은 실행 가능한 World Interaction이 아니라 공통 성장·회복 관점을 제공하는 메타데이터 계층이다.

```text
wi-family:meditation (MetadataOnly)
├─ WI-NATURE-06 벌목
├─ WI-FARM-01 밭갈이
├─ WI-WORLD-05 탐사
└─ 그 밖의 구체적 플레이어 WI
        ↓ 자식 WI가 직접 실행
Preview → Confirm → Task/Effect → ActionRecord
        ↓ 같은 완료 계보
PlayerProgressionApply → MeditationProgressionApply
        └→ FiveElementActivityFootprintProject (기획·미구현)
```

- 상위 WI군은 `Preview`, `Confirm`, `Task`, `Effect`, 비용, 예약과 `WorldRevision`을 소유하지 않는다.
- 자식 WI를 감싸 다시 실행하거나 완료 뒤 두 번째 WI를 생성하지 않는다.
- `PlayerDirect`, `PlayerOrOperation`, `LearningOnly` WI 정의는 상위 WI군에 결속될 수 있지만 실제 실행 Actor와 발생원이 Player인지 다시 검사한다.
- `OperationOnly`, 자동 처리, 의미 있는 플레이어 행위가 아닌 WI는 같은 Catalog에서 사유 있는 `NotApplicable`로 남긴다.
- 현재 권위 Catalog는 `Simulation기본명상WiFamilyCatalog`, 계약은 `Simulation명상WiFamilyCatalogSnapshot`이 소유한다.

## 권위 처리 순서

`Preview → Confirm → 집중 근거 수집 → 권위 결과 확정 → 행위 기록 추가 → 분야 성장 적용 → 명상 성장 적용 → 결과 조회 → 엔진별 독립 소비`

각 단계의 책임은 다음과 같다.

1. `Preview`는 가능 여부와 비용만 계산하고 상태를 바꾸지 않는다.
2. `Confirm`은 기존 WI 규칙으로 Task와 Effect를 시작하거나 확정한다.
3. `FocusEvidenceCollect`는 활성 Profile에 따라 입력·품질 근거를 모은다. Profile이 아직 없으면 판본화된 `NotApplicable`을 남기고 보상을 추정하지 않는다.
4. `AuthorityCommit`은 기본 행위의 성공·실패를 판정한다. 집중 판정은 이 결과를 재정의하지 않는다.
5. `ActionRecordAppend`는 권위 결과와 같은 Command·Revision 계보에 변화 의미와 집중 근거를 멱등 추가한다.
6. `PlayerProgressionApply`와 `MeditationProgressionApply`는 같은 행위 기록을 근거로 분야 성장과 명상 성장을 각각 적용한다.
7. 계획된 `FiveElementActivityFootprintProject`는 실제 Actor와 같은 WI·ActionRecord·오행 분류·기여 Profile 판본을 대조해 재구성 가능한 조회를 만든다. 집중 품질은 명상·회복·위협 근거에 쓰일 수 있지만 행위 횟수를 부풀리지 않는다.
8. LH·Sky·실외 배치·실내 배치·World Presentation은 자신의 생명주기에서 행위 원장 또는 같은 Revision 상태 사본을 cursor로 읽는다. 엔진은 이 파이프라인을 호출해 세계 상태를 바꾸지 않는다.

## 적용 대상 판정

`meditation-wi-family-catalog.r1`은 65개 WI를 비실행 상위 WI군 결속 또는 사유 있는 제외로 먼저 전수 판정한다. 그 뒤 `focus-profile-catalog.r1`이 실제 집중 Profile 적용 상태를 다음 중 하나로 분류한다.

| 상태 | 의미 | 현재 처리 |
| --- | --- | --- |
| `Applied` | 권위 집중 Profile이 구현됨 | 판정 후 작은 명상·개인 회복 기여 가능 |
| `PendingProfile` | 플레이어 행위지만 판정 Profile 미정 | `NotApplicable`; 보상 없음 |
| `NpcOnly` | 운영·NPC 수행 경계 | 플레이어 명상 성장 없음 |
| `Automatic` | 자동 처리 | 플레이어 명상 성장 없음 |
| `Excluded` | 행위가 아니거나 명시적 제외 | 플레이어 명상 성장 없음 |

현재 `Applied`는 `WI-NATURE-06 벌목` 하나다. 나머지 WI는 카탈로그 누락 없이 분류되지만, 개별 행위의 자연스러운 몰입 방식과 악용 방지 규칙이 정해지기 전에는 수치를 지급하지 않는다.

상위 WI군 결속은 보상 승인이 아니다. `Bound`여도 해당 자식 WI의 완료 의미·Profile·반복 방지 규칙이 승인되지 않으면 기존처럼 명상·회복 기여를 추정하지 않는다.

## 작은 보상과 고정 정밀도

명상 경험은 정수 점수의 천분의 일 단위인 `Milli`로 저장한다. 작은 성공을 누적하되 부동소수점에 의존하지 않는다.

| 집중 결과 | 명상 경험 | 개인 회복 | 기본 행위 결과 |
| --- | ---: | ---: | --- |
| `Perfect` | `+250 Milli` (`+0.25`) | `+250 Milli` (`+0.25`) | 변경하지 않음 |
| `Good` | `+100 Milli` (`+0.10`) | `+100 Milli` (`+0.10`) | 변경하지 않음 |
| `Miss`·`NoInput` | `0` | `0` | 변경하지 않음 |
| `AssistedNeutral` | `0` | `0` | 변경하지 않음 |

집중 실패만으로 위협을 올리지 않는다. 위협은 실제 위험, 손실, 실패 Effect처럼 세계 안에서 설명 가능한 근거를 가진 별도 규칙이 담당한다. 취소·차단·Task 미완료는 명상 기여를 만들지 않는다.

단계 표시는 기존 `0/1/5/12` 점을 각각 `0/1000/5000/12000 Milli`로 환산한다. 호환 조회용 정수 `명상숙련도`는 `명상경험Milli ÷ 1000`의 내림값이며 권위 원본은 `명상경험Milli`다.

## 행위 기록과 원자성

집중 보상이 있는 권위 완료는 다음을 하나의 집계 잠금과 같은 완료 계보에서 처리한다.

- 기본 WI Effect
- `Simulation행위발현Record`
- 분야 숙련 기여
- 명상 숙련 기여
- 허용된 플레이어 개인 심리 Effect

행위 기록은 집중 Profile·Challenge·판정 결과·명상 기여 고유 식별자를 출처 참조로 남기고, `MeditationProgressChanged`와 필요하면 `PlayerRecoveryChanged` 변화 의미를 포함한다. 같은 행위 기록 또는 같은 명상 기여 고유 식별자의 재처리는 기존 결과를 반환하며 중복 지급하지 않는다.

엔진은 기록을 즉시 읽을 수도 있고 나중에 cursor로 읽을 수도 있다. 항상 읽어야 하는 것도, 파이프라인 안에서 직접 호출되어야 하는 것도 아니다. 소비 시점과 파생 캐시는 각 엔진이 소유하지만 Simulation `WorldRevision`은 바꿀 수 없다.

## 저장·재생과 증거

명상 기여와 진행 중 Challenge는 `simulation-save.v29`에 저장한다. v1~v28 읽기 호환을 유지하며 복원할 때 행위 원장, 분야 Profile, 명상 기여와 개인 심리 상태 hash를 검증한다. 완료된 Challenge는 활성 목록에 계속 쌓지 않고 행위 기록·기여·Effect 계보로 보존한다.

현재 자동 증거는 다음 범위다.

- `WI-NATURE-06`의 정수 판정, Task 완료 결속, 작은 기여, 멱등 처리와 v29 Save/Replay
- 플레이어 분야 WI 65개에 대한 집중 Profile 상태 완전 분류
- 공통 실행 Trace의 `FocusEvidenceCollect`, `ActionRecordAppend`, `PlayerProgressionApply`, `MeditationProgressionApply` 순서
- 표현 엔진이 읽어야 할 변화 의미와 출처 참조

이는 서버·LocalProcess의 Logic E5 근거다. 다른 WI의 개별 집중 Profile, Unity 실제 입력, 게이지·피드백, 상태창, 엔진별 실제 cursor 소비, Play Mode·Game View는 아직 구현·검증하지 않았다.

## WI 확장 관문

새 WI에 집중을 적용할 때는 같은 PlayableLoop Goal 안에서 다음을 결정한다.

1. 플레이어가 실제로 주의를 기울일 수 있는 행위인가.
2. 성공·의미 있는 실패·후퇴 중 어느 결과에 집중 기여를 허용하는가.
3. 타이밍, 관찰 선택, 정밀 조작 등 어떤 판정이 행위의 의미와 맞는가.
4. 자동·NPC 수행·접근성 건너뛰기를 어떻게 중립 처리하는가.
5. 반복 악용 없이 작은 보상을 지속적으로 체감할 수 있는가.
6. 어떤 행위 기록과 변화 의미를 엔진이 나중에 읽을 수 있어야 하는가.

이 검토가 끝난 WI만 `PendingProfile`에서 `Applied`로 승격한다.
