# Mirror 기획 인계 — 이 파일 하나부터

기준일: 2026-09-07, 자율 음식 배달 관찰 r6 완료 시점.

이 문서는 ChatGPT 채팅에 첨부하기 위한 **고정 시점 요약본**이다. 저장소의 기준 문서를 대체하지 않는다. 최근 현행화 작업 중심이며 프로젝트 전체를 새로 전수 조사한 결과는 아니다. 파일 하나만 첨부해도 아래 문답을 이어갈 수 있다. 시각 검토가 필요할 때만 함께 제공한 `two-receptions.png`를 추가한다. ChatGPT가 첨부하지 않은 저장소 파일·다른 대화·로컬 링크에 접근할 수 있다고 가정하지 않는다.

## 1. 우리가 만들려는 것

프로젝트 표시명은 **Mirror(거울)**이며 `Ssalddel`/살뜰은 기존 코드·폴더 이름이다. 사용자는 현실 업무와 크게 동떨어지지 않은 가상 세계를 Unity에서 관찰하고 싶어 한다. 주민·음식점·배달원·창고 작업자 등이 규칙에 따라 생활하고, 사용자는 가볍게 지켜보다 원할 때 직접 참여하거나 목표·운영 정책을 선택한다.

장기 이용 흐름은 **무료 관찰 → 선택적 가상 역할 체험 → 희망자의 기존 MAUI/Web 업무 도구 이용·현실 협업 준비**다. 게임을 반드시 해야 현실 앱을 사용할 수 있다는 뜻은 아니다. 기존 서버·업무 앱을 재사용하지만 현재 모든 모바일 앱의 빌드·설치·배포가 검증된 것은 아니다. GitHub 소스 공개 의향과 실제 라이선스·외부 자산 재배포 권한도 별개다.

플랫폼 전체의 정보 공개형 커뮤니티 목적과 현재 기본 공개 단계0.0은 유지한다. Unity 내부의 가상 업무 실험이 실제 자동 배차·거래·정산 서비스를 공개했다는 뜻은 아니다.

## 2. 이미 합의한 기획

- **세계 구축 우선, 스토리 후속 결속.** NPC의 작은 업무 흐름부터 자율 반복·관찰 가능하게 완성하고 그 인물과 사건에 이야기를 붙인다. 세계 전체가 완성될 때까지 이야기를 무기한 미루지는 않는다.
- 기존 수뢰둔·산수몽 이야기는 보존한다. 괘·효는 상황을 새롭게 생각하는 영감이며, 고정64개 캠페인·육효 순서·기능 제작 순서를 강제하는 규칙이 아니다.
- 판타지 통신구로 주문·연락하는 분위기는 채택했다. 다만 음식은 조리 시간이 들고 배달원은 길을 이동해 픽업·인계한다. 순간 조리/순간 배송은 이번 방향에 포함하지 않는다. **통신구 UI 자체는 아직 미구현**이다.
- 지금은 Synty 프리팹·Blender 모델링보다 기본3D 도형과 면별 명암, 위에서 비스듬히 내려다보는 구도로 충분하다. 음식점 빨강·주문자 파랑·창고 하양·기사 검정 등의 역할색을 유지한다.
- 맵은 축소하지 않는다. 배경 시설이 늘었다고 그곳에 업무·NPC·통행 기능이 연결됐다고 보지 않는다.
- 첫 기준은 **재생 한 번 이후 개별 업무 조작 없이 음식 주문→조리/배차→픽업→배송→수령→다음 주문이 반복되는 동네**다. 수락 뒤 조리와 배차는 병행할 수 있고 준비 완료 전 픽업은 금지한다.
- 이번 표현·자율 반복 보완은 사용자가 지정한 현재 `현행화` 스레드에서 직접 구현했다. 다음 구현도 자동으로 다른 개발 스레드에 보내지 않는다. 기존 개발 스레드에 요청한 읽기 조사와는 별개다.

## 3. 모듈을 이해하는 최소 구조

| 책임 | 기존 모듈과 역할 |
| --- | --- |
| 가상 초기 조건 | `가상배달관찰표본.CreateNeighborhoodLife`: 주민·음식점·기사·마트·창고와 유한 재고를 구성 |
| 가상 상태의 권위 | `경영SimulationSessionAggregate`와 공통 Simulation Core: Tick·주문 상태·정책·위치·행위 결과를 확정 |
| 업무 규칙 | `가상주문흐름`: 주기적 주문·수락→배차 대기 인계. `가상배달대기`: 기사 후보·이동 자원 점유·픽업/수령. `가상동네생활`/`가상동네보충`: 근무/휴식과 창고·마트 인계 |
| 실행·저장 연결 | `동네관찰SessionController` → Runtime Adapter → 기존 Session API. 명령 후 재조회·저장, 중복 실행 방지, 저장 실패 시 정지 |
| 화면용 조회 | `동네관찰Presenter`: 같은 Snapshot에서 주문·NPC·재고·주민별 음식 수령 횟수와 다음 대기를 파생. 상태를 변경하지 않음 |
| Unity 표현 | `가상배달관찰Controller`·`가상동네생활View`·`동네관찰휴대폰View`: 권위 위치를 도형과 카드로 표시. 화면/애니메이션이 업무 완료를 확정하지 않음 |

실제 업무는 별도로 `화면 → Controller API → UseCase/Command → Domain/Infrastructure → DB/Event/Outbox`를 따른다. 엔진은 후보를 계산하고 권한·현재 상태를 검증하는 업무 실행 계층이 확정한다.

**실행 경로를 혼동하지 말 것:**

- 프로필5: Unity 내부 공통 Local Runtime의 합성 생활. 이번 자율 반복 관찰은 이 경로다. 바닥90×58.
- 프로필6: 별도 격리 업무 서버 검증 결과를 HTTP로 조회하는 관찰 화면. 같은 주문에 Local Runtime을 중복 실행하지 않는다. 배경120×96이며 추가 주택14동·음식점4동·마트/창고는 미연동 배경이다.
- 둘은 같은 다중 주문 세계로 통합됐다는 증거가 없다. 공식 Scene은 `SimulationWorldShell` 하나지만 업무 상태의 출처와 범위는 다르다.

## 4. 현재 무엇이 실제로 되는가

**기존 구현:** 주민2명·음식점 주인·창고/마트 작업자·배달기사3명·화물기사 등9명의 직업 중심 합성 생활. 주문·수락·조리·배차·픽업·수령, 음식/마트 교대 주문, 창고 피킹·포장·보충 운송·입고, 일부 통로/정차점/출입구 점유, 근무·휴식, 정책 카드, 저장·재진입.

**최근 보완:**

1. Cube의 면별 명암·대각선 카메라·이름표·화면비 전체 맞춤. 원장·좌표·맵을 바꾸지 않았다.
2. 편집 Game View에도 같은 공간 조립을 쓰는 비저장 미리보기. 편집에서는 업무를 실행하지 않고, Play에 들어가면 미리보기를 제거하고 실제 NPC·휴대폰 UI를 표시한다. 프로필5의 편집/정지 Play에서 카메라·바닥 일치와 복귀를 확인했다. Game View 배율은1.0이다.
3. 기존 자율 엔진을 재사용하고 휴대폰 동네 화면에 **주민별 음식 수령 횟수·현재 단계·다음 주문 검토·마트 대기·정책 중단/마감 이유**를 추가했다. 이번에 음식 엔진 전체를 새로 만든 것은 아니다.

**검증 근거:**

- 자동300Tick: 사용자 업무 명령 없이 두 주민 각각 음식 수령2회 이상, 후속 음식 주문, 수락 이후 배차, 조리 준비 이후 픽업을 확인.
- 실제 관찰: 격리 새 표본에서 재생1회 후 관찰. **309.758초 동안 가상249Tick**, 두 주민 각각 음식2회 수령. 총 음식4건·마트2건·보충입고1건. 정지 호출 처리 때문에 목표300초를9.758초 초과했으며 정확히5분으로 보고하지 않는다.
- 실제 최종 Revision529, 저장 실패 없음. 원본 슬롯은 변경하지 않았고, Play 종료·기존 프로필/저장 경로·Scene clean 상태로 복원했다.
- 최종 Task 검증: Simulation1847/1847·Unity 공용 라이브러리744/744, 관련 Unity Editor 휴대폰7/7·컴파일 통과. 편집 미리보기의 별도 시험2/2도 통과했다. 자동 시험·실제 화면·운영 검증은 서로 다른 증거다.
- 최근 보완은 커밋·푸시하지 않았다. 저장소 전체가 깨끗하거나 모든 변경이 원격에 올라갔다고 가정하지 않는다.

현재 사용: Unity `SimulationWorldShell`에서 `NPC 직업 생활 · 30분` 프로필을 선택하고 Play → 휴대폰 → 동네 → 재생. 매 주문을 직접 처리할 필요는 없다. 현재 표본은1800Tick 제한, 마지막180Tick 신규 접수 중단, 완료 뒤 명시적 새 표본 시작이다. **무기한 세계·자동 재시작·Play 진입 시 자동 재생은 아직 아니다.** 앱 종료 시간도 따라잡지 않는다.

## 5. 부족한 점과 다음 기획 후보

아래는 **제안이지 다음 구현 승인 목록이 아니다.**

1. **저장 성능:** 실제 마지막 저장 약1.94초·최대2.29초. 실시간309.8초에 세계249Tick이므로 관찰 속도에 영향을 준다. 저장 검증을 끄거나 실패를 숨겨 해결하지 말고 원인·내구성·재처리 비용을 함께 검토할 필요가 있다.
2. **지속 가능한 반복 범위:** 30분 표본 종료 후 세계를 어떻게 이어갈지, 재고 소진·휴식·지연·부재 때 어떤 회복을 보장할지는 별도 기획이다. 모든 교착·기아·장시간 예외를 해결한 상태가 아니다.
3. **지도와 실제 업무 연결:** 커진 배경과 업무가 연결된 공간을 구별해야 한다. 프로필5/6을 어떤 역할로 유지하거나 연결할지도 미정이다. 연결되지 않은 건물을 임의의 주문 목적지로 바꾸지 않는다.
4. **판독성·세계관:** 전체 보기에서 이름표/NPC가 작고 일부 Unity 경고13건이 남아 있다. 원인 전체는 미확정이다. 통신구·관찰 안내·사건 알림은 이후 표현 후보이며 고급 자산이 필수는 아니다.
5. **스토리 진입:** 안정된 세계의 어느 인물·사건에 관심을 가지면 수뢰둔·산수몽 등의 이야기와 직접 플레이로 이어질지 아직 정하지 않았다. '마음이 통함'을 자동 가입·업무 참여 동의·친밀도 판정으로 바꾸지 않는다.

실제 업무 앱 배포·모바일 설치·자격/운영 준비·실제 거래/정산·Hosted 장기 검증·세계 전체 완성도는 이 결과로 증명되지 않는다. 가상 재고·주문·보상은 현실 원장으로 자동 전환하지 않는다.
