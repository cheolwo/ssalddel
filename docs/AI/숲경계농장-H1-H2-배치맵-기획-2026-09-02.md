## 목적

H1 하나를 장소 하나로 해석하지 않고, 같은 H1 정의의 여러 배치 인스턴스와 서로 다른 기능·표현 H1을 조합해 자연스러운 숲 경계 농장 H2를 만든다. Graph Map은 발견·이동·작업 관계를 유지하고, 별도 배치 맵은 반복 인스턴스·상대 구도·시야·통행·배치 제약을 관리한다.

## 지금·여기·나·너·이렇게

- 지금: 춘분 무렵, 나무꾼 몸에 빙의한 플레이어가 처음 Nature에서 Farm 경계에 도달하는 초반
- 여기: 숲길·완충지·손상된 울타리·한스의 생활 흔적·밭·작업마당이 이어지는 숲 경계 농장
- 나: 낡았지만 사용할 수 있는 개인 손도끼를 가진 초보 모험가
- 너: 아직 완전히 발견되지 않은 농장, 한스, 울타리, 밭, 작업마당과 배경 숲
- 이렇게: 이동하며 공간을 차례로 관찰하고 선택 카드를 통해 도움 여부를 정한다. 공간 의미는 Graph Map이, 구체적인 반복·배치는 배치 맵이 소유한다.

## 첫 H1·H2 조합 기준선

### H2 범위 — 한스의 집이 아니라 한스의 생활 농장

첫 대표 H2는 집 한 채만 확대해 해석하지 않는다. `gm-node:hans-house`를 생활·시야 기준점으로 삼고, 실제로 경작·보관·수리·휴식·이동이 가능한 농장 전체를 하나의 `h2-candidate:forest-edge-farm` 배치 범위로 구성한다.

- 한스 집: 생활·휴식·관찰·귀환의 중심 기준점
- 혼합 작물밭: 농장이 실제 생산 공간임을 보여 주는 필수 구획
- 손상 울타리와 출입구: Nature와 Farm의 경계 및 첫 도움 행동의 발생 지점
- 헛간·작업마당: 수확물·도구·수리 활동이 이어지는 작업 구획
- 농기구 보관·작업자 대기: 생활 농장의 지원 기능 후보
- 숲 경계·완충 식생: 농장 외곽과 발견 순서를 만드는 배경·차폐 구획

한스 집은 H2 전체를 대신하지 않으며, 밭·울타리·작업마당 역시 집의 장식이 아니다. 각 구획은 별도 H1 또는 안정 세계 객체를 참조하고 배치 맵이 관계와 상대 구도를 조립한다. 현행 H1 정의에는 한스 집과 정확히 대응하는 항목이 없으므로 기존 `farm-worker-waiting`의 생활 지원 범위를 그대로 집으로 확대하지 않는다. Graph Map의 `gm-node:hans-house`를 보존한 채 전용 H1 재사용 또는 신규 정의 필요성을 개발 조사로 반환한다.

## Graph Map과 별도 배치 맵

- Graph Map은 발견, 이동, 관찰, 작업 선택, 귀환과 주변 H1·H2 파급을 소유한다.
- 배치 맵은 `placementInstanceId`, `hDefinitionRef`, 반복 수, 상대 위치·방향·규모, 전경·중경·배경 역할, 기준점과 제약을 소유한다.
- 같은 `hDefinitionRef`를 여러 배치 인스턴스가 참조할 수 있다. H 정의·WI·Graph 엣지를 복제하지 않는다.
- 배치 인스턴스 사이의 통행·작업 연결은 대응 Graph Map 안정 엣지를 참조한다.
- 실제 World 지형이 동결되기 전에는 절대 좌표 대신 상대 구도와 수량을 사용한다.
- 배치 검증 실패는 Graph Map 의미를 조용히 바꾸지 않고 해당 질문·제약 판본으로 반환한다.
- 한스 집은 H2의 시각·생활 기준점이지만 농장 전체의 생산 권위나 모든 WI를 소유하지 않는다.
- 집·밭·작업마당은 서로 이어지되 주거 출입, 농작업 동선, 수확물 인계 동선이 한 점에 겹치지 않게 구획한다.
- 집과 밭 사이에는 일상적인 관찰과 짧은 도보 이동이 가능해야 하고, 헛간·작업마당은 집 전면 시야와 출입구를 막지 않는 측후면 후보로 둔다.

### Synty 표현 조사와 배치 태그

첫 배치 맵은 보유 Synty 자산을 우선 조사하되, 자산 이름으로 한스 농장의 구조를 역으로 결정하지 않는다. 각 배치 인스턴스는 필요한 표현 역할과 조사 상태를 태그로 남기고, 같은 역할에 여러 후보를 둘 수 있다.

| 배치 대상 | `visualRequirementTags` | 우선 조사 기능군 | 현재 조사 상태 |
| --- | --- | --- | --- |
| 한스 생활 주택 | `생활 주택`, `낡음`, `수리 상태 변형`, `휴식 기준점` | Farm/Town 실외 구조물, Construction 복구 상태 | `InventoryMatched / ExactPrefabPending` |
| 혼합 작물밭 | `경작`, `춘분`, `혼합 작물`, `생산 판독` | Farm 월드 지면·식생·실외 기능 소품 | `InventoryMatched / VisualCombinationPending` |
| 손상 울타리·출입구 | `경계`, `손상`, `수리 전후`, `통행` | Farm 실외 구조물, Construction 복구 상태 | `InventoryMatched / StateVariantPending` |
| 헛간·작업마당 | `보관`, `작업`, `목재 적치`, `측후면` | Farm 실외 구조물·기능 소품 | `InventoryMatched / CompositionPending` |
| 숲 완충 | `숲 가장자리`, `침엽수 후보`, `부분 차폐`, `춘분 색감` | Nature/Alpine Mountain 지면·식생 | `InventoryMatched / DensityAndPalettePending` |

모든 행의 기본 `sourcePreferenceCodes`는 `SyntyOwnedFirst`이며, 정확 후보가 없을 때만 프로젝트 소유 Wrapper·복사본·가공 계획 또는 fallback을 검토한다. `InventoryMatched`는 팩과 기능군이 존재한다는 뜻일 뿐 외형 조합·크기·피벗·Bounds·Collider·통행·Scene 적합성이 확인됐다는 뜻이 아니다. 정확 Prefab은 이미지 검토와 정적 적합성 검사를 거쳐 GUID·fingerprint로 동결하며, E5 실제 배치 전에는 할당 완료로 기록하지 않는다.

한스 생활 농장 H2의 `primarySyntyPackCode`는 `Farm`으로 확정한다. 건물·밭·울타리·농업 소품의 기본 형태와 색감은 Farm 팩을 먼저 사용해 한 장소로 읽히게 한다. 다른 팩은 다음 역할로만 보조한다.

- `Construction`: 울타리·집·작업 공간의 손상, 수리 중, 복구 완료 차이를 표현하는 상태 보조층
- `Nature`: 숲 경계의 식생·나무·바위와 농장 밖 완충 배경
- `AlpineMountain`: Farm·Nature만으로 북부 지형의 원경·경사·암반 표현이 부족할 때 검토하는 선택 후보
- `Town` 또는 다른 팩: Farm 후보가 없고 스타일·규모·재질 호환을 별도 확인한 경우에만 대체 후보

보조 팩은 Farm 팩의 건물 문법을 대체하거나 Area 정체성을 바꾸지 않는다. 한 배치 대상에 여러 팩을 섞을 때는 `supportRoleCode`와 사용 이유를 남기고, 색감·상대 규모·재질·피벗·Bounds가 주 팩과 어울리지 않으면 `Blocked` 또는 대체 후보로 돌린다.

### 첫인상 — 낡았지만 운영되는 생활 농장

한스 농장의 첫인상은 폐허나 방치 농장이 아니라 **낡았지만 실제로 운영되고 있는 생활 농장**으로 확정한다. 낡음과 운영 흔적을 같은 자산 하나에 모두 요구하지 않고 서로 다른 배치 단서로 조립한다.

- 낡음: 바랜 외벽·지붕, 부분 손상 울타리, 여러 차례 덧댄 흔적, 오래된 작업 소품
- 운영 중: 경작 흔적이 있는 밭, 최근 옮긴 도구, 정리 중인 목재·수확 바구니, 통행으로 눌린 동선, 연기·불빛 같은 선택 생활 신호
- 배제: 집 전체 붕괴, 잡초만 무성한 밭, 통행 불가능한 잔해, 모든 소품이 같은 방향으로 쓰러진 폐허 연출

플레이어가 울타리 수리를 마치기 전에도 농장은 운영되고 있어야 한다. 수리는 폐농장을 되살리는 행동이 아니라, 이미 살아 있는 장소에 플레이어가 자발적으로 기여하는 첫 행동이다.

운영 중이라는 핵심 단서는 **경작된 밭과 최근 사용한 농기구**로 확정한다. 두 단서는 장식이 아니라 플레이어가 이동하면서 시간의 흔적을 읽는 순서로 구성한다.

1. 숲길에서는 작은 지붕 구멍과 손상 울타리가 먼저 보여 `낡음`을 전달한다.
2. 농장 경계에 가까워지면 고랑·경작면·작물 줄이 보여 `방치되지 않은 밭`임을 알린다.
3. 경계 안쪽에서는 흙이 묻은 농기구 하나 또는 작은 도구 묶음이 밭과 작업마당 사이에 놓여 `최근 작업`을 전달한다.
4. 도구는 길 한가운데나 무작위 장식 지점이 아니라, 작업을 멈추고 다시 집어 들 수 있는 밭 가장자리·도구 받침·작업마당 진입부 후보에 둔다.
5. 플레이어는 이 단서만으로 한스의 정확 위치나 감정, 작업 완료 여부를 알 수 없다. 운영 중이라는 사실만 추론한다.

경작된 밭은 완벽하게 균일한 전시용 밭보다 일부 빈 고랑·작물 성장 차이·작업 중인 한 구획을 허용한다. 다만 잡초와 황폐함이 주된 인상이 되어서는 안 된다. 농기구는 여러 개를 흩뿌리지 않고 대표 도구와 보조 소품을 작은 군집으로 묶어, 최근 사용 흔적과 정돈된 생활 습관을 함께 보여 준다.

첫 방문에 보이는 농기구는 **관찰 가능한 한스의 생활 소유물**이며 즉시 획득 가능한 무료 아이템이 아니다. 플레이어가 조준하거나 가까이 가면 `최근 사용한 농기구` 정도의 짧은 관찰 정보만 읽을 수 있고, 집기·장착·사용 입력은 열지 않는다.

농기구 사용은 한스와의 관계 또는 명시적 허락을 통해 별도로 개방한다. 허락 전 상호작용은 실패 경고나 소유권 위반을 발생시키기보다 비활성 상태와 짧은 이유를 보여 주어, 플레이어가 실수로 절도 판정을 받지 않게 한다. 허락 뒤에도 모든 농기구가 자동으로 플레이어 소유가 되는 것은 아니며 `빌려 쓰기`, `지정 작업에 사용`, `수리 보상으로 양도`를 서로 다른 관계로 둔다.

배치 맵은 도구의 관찰 지점과 작업 동선을 준비하지만 소유권·허락·양도 상태를 결정하지 않는다. Graph Map은 한스 관계와 도구 사용 개방의 인과를 연결하고, 실제 권위 상태는 후속 WI·Simulation 계약이 소유한다.

추가 문답은 수평 순환 뒤 다시 이어간다. 현재 상태는 `PausedForHorizontalRotation`이며, 대표 농기구의 정확 종류와 허락 뒤 사용 범위를 재개 질문으로 남긴다. Graph Map·배치 프로필·개발 구현 인계는 즉시 반복하지 않고 후속 판본으로 묶는다. 기존 r21 개발 결과는 보존하지만 r22 이후의 새 기획을 이미 구현한 것으로 간주하지 않는다.

### Blender 보완 판단 사다리

Blender 보완 가능성은 인정하되 정확 Farm Prefab과 부족한 표현이 확인되기 전에는 제작을 시작하지 않는다. 배치 대상마다 다음 순서로 판정한다.

1. `ExistingPrefab`: Farm 원형과 기존 상태 변형만으로 표현 가능한지 확인
2. `CompositionOnly`: Construction의 판재·비계·사다리·천·목재와 생활 소품을 Wrapper 아래 조립해 해결 가능한지 확인
3. `ProjectOwnedVariant`: 원본 불변의 프로젝트 소유 Prefab 변형과 재질·Renderer 상태로 해결 가능한지 확인
4. `BlenderPlanRequired`: 지붕 구멍, 깨진 가장자리, 노출 단면처럼 메시 자체 변경이 꼭 필요한 결손만 기록
5. `BlenderValidatedCopy`: 정확 입력 FBX·출력 경로·축·단위·피벗·재질 슬롯·법선·UV·Collider/Bounds 검증 계획이 승인된 전용 복사본만 제작 후보로 전환

한스 집은 현재 `BlenderPlanRequiredCandidate`이며 실제 가공 확정 상태가 아니다. 우선 Synty 이미지·Prefab 구조를 비교해 조립만으로 가능한 단서와 메시 수정이 필요한 단서를 분리한다. Synty 원본 FBX·Prefab·Material은 수정하지 않고, 가공본이 필요하면 프로젝트 소유 경로에 별도 ID·fingerprint·원본 계보를 둔다. 제작 결과도 E5 실제 배치·Game View 증거를 대신하지 않는다.

첫 손상 단서는 숲길과 농장 경계에서 **멀리서도 식별 가능한 작은 지붕 구멍 하나**로 제한한다. 집의 벽체·출입구·주요 지붕 구조는 유지하고, 내부 전체가 노출되거나 붕괴 위험이 느껴질 정도로 확대하지 않는다. 구멍 주변에는 제한적인 낡은 가장자리 또는 임시 덧댐 흔적을 둘 수 있지만, 여러 손상 부위를 추가해 폐가처럼 만들지 않는다.

이 단서는 `PartialRoofVisibleFromForestTrail` 시야 의도와 연결한다. 수리 전에는 작은 구멍의 실루엣이나 명암 차이가 읽히고, 수리 후에는 같은 카메라·거리에서 지붕 윤곽이 이어지거나 호환되는 보강 흔적으로 바뀌어야 한다. 정확 크기·면 제거 방식·내부 차폐·비바람 효과는 후보 Prefab의 실제 지붕 구조를 확인한 뒤 결정하며, 이번 확정만으로 Blender 실행을 승인하지 않는다.

### 한스 생활 농장 삼중 균형 표본

이 기획은 [Graph Map 기획 인계 순환 체계의 삼중 균형](../Architecture/GraphMap기획인계순환체계.md#기획graph-map배치-맵-삼중-균형)을 첫 표본에 적용한다. 세 문서는 같은 내용을 복제하지 않고 다음 대응을 유지한다.

계획을 세우는 행위 자체는 목표와 경계를 세우는 간괘(☶)다. 그 행위로 검토·승인되어 동결된 기획 결과물은 플레이 의미를 밝히고 Graph Map·배치 맵 작업의 질서를 잡는 리괘(☲) 산출물로 읽는다. 그 뒤 관계와 경계를 고정하는 Graph Map의 간괘(☶), 실제로 읽히는 공간 구도를 만드는 배치 맵의 태괘(☱)가 이어진다. 이는 행위와 문서·맵 종류를 구분한 메타데이터이며 아래 벌목·수리 WI의 행위괘·작용괘·대상괘를 바꾸지 않는다.

각 괘상은 고정 본질이 아니라 관계 속 역할이다. 한스 집·밭·작업마당은 배치 인스턴스로 볼 때 태괘(☱)이고, 이들을 연결하는 안정 구조는 Graph Map의 간괘(☶)다. 숲길→농장 진입, 집↔밭 생활 이동, 밭→작업마당 수확물 이동처럼 공간 사이를 흐르는 관측·이동·운송 데이터는 감괘(☵) 관계 후보로 둔다. 이때 공공 경로 자료, 플레이어 실제 이동 기록, Simulation 후보 경로, 수동 기획은 같은 것으로 합치지 않고 출처·판본을 분리한다.

| 기획 약속 | Graph Map 대응 | 배치 맵 대응 | 현재 상태 |
| --- | --- | --- | --- |
| 숲에서 농장 흔적을 단계적으로 발견 | Nature→Farm 진입 관계와 발견 순서 | 숲길→완충지→손상 울타리, 지붕 일부의 단계적 시야 | `BalancedDraft` |
| 한스의 생활 농장에 진입 | 숲 경계 농장 H2와 한스 집 안정 객체 | 울타리 출입구, `농장 생활 주택` 인스턴스, 밭·마당의 상대 구도 | `BalancedDraft` |
| 나무를 베고 울타리를 도울 수 있음 | 벌목·운반·수리 WI 관계와 대상 연결 | 허용 나무·손상 구간·목재 도착점·작업 기준점 | 정확 WI·인스턴스 미결속 |
| 생산·생활·작업 기능을 구분 | `farm-production`, `farm-worker-waiting`, `farm-work-yard`, `farm-tool-storage`의 분리 관계 | 집·밭·헛간·작업마당 동선이 한 점에 겹치지 않는 제약 | `BalancedDraft` |
| 관찰 뒤 다음 선택을 알아차림 | 한스 관계·후속 발견 후보 | 집·밭을 읽는 시야와 후속 표식 후보 | 정확 표식·입력 미정 |

현재 표본은 세 관점의 대응을 만들었으므로 추적 준비 상태가 `BalancedDraft`다. 아직 Graph Map 안정 ID의 최종 대응, 한스 집 `placementInstanceId`, 주동선, 거리·높이·각도, 자산 fingerprint, 규칙성 검사 결과가 동결되지 않았으므로 `BalancedForE4`가 아니다. 두 값은 이 묶음의 추적 준비 상태이며 E 단계나 WI 실행 상태가 아니다.

## 대표 고정 배치 우선

첫 판본은 절차적 변형보다 비교 가능한 대표 고정 배치를 사용한다.

1. H1 인스턴스 수와 상대 위치를 동결한다.
2. 발견 순서, 가시선, 출입·통행, 작업 공간, 배경 밀도를 검토한다.
3. 같은 조건의 수정 전후를 비교할 수 있을 때만 대표 배치 판본을 올린다.
4. 대표 배치가 안정된 뒤 후속 판본에서 수량 범위와 결정적 seed 변형을 검토한다.
5. seed 변형은 Save/Replay와 같은 입력에서 같은 결과를 내야 하며 플레이 의미·권위 상태를 바꾸지 않는다.

## 첫 방문의 단계적 시야 공개

첫 배치 맵은 숲길 입구에서 농장 전체를 한 번에 보여 주지 않는다. 플레이어가 이동하면서 다음 순서로 공간의 의미를 알아차리게 한다.

1. 숲길 입구에서는 길과 숲의 깊이만 분명하게 읽힌다.
2. 탐색 완충지에서는 손상된 울타리와 한스 집 지붕 일부를 시야 단서로 보여 준다.
3. 숲·농장 경계에 도달하면 울타리의 손상과 통과 가능한 출입 방향을 구분해 읽게 한다.
4. 경계를 통과한 뒤에 혼합 작물밭과 한스의 생활 거점이 열린다.
5. 더 안쪽으로 이동해야 헛간·작업마당과 농기구 보관·작업자 대기 후보를 읽을 수 있다.

필수 제약은 숲길에서 농장 전체가 조기에 노출되지 않을 것, 손상된 울타리와 지붕 단서가 서로 겹쳐 사라지지 않을 것, 시야 차폐가 주 통행을 막지 않을 것, 경계 통과 뒤 다음 목적지가 최소 하나는 보일 것이다. 배경 밀도·나무 반복·건물 정렬처럼 기능 통행을 막지 않는 문제는 우선 `Warning`으로 기록하되 E5의 품질 근거로 사용하지 않는다. 정확 거리·높이·카메라 각도는 배치 맵 표본에서 비교한 뒤 별도 판본으로 확정한다.

## 한스 집 중심의 상대 구도

한스 집은 울타리 안쪽에서 주변보다 약간 높은 생활 기준점으로 둔다. 정확 고도·경사·미터 거리는 실제 지형 대조 전까지 확정하지 않고 다음 상대 제약을 사용한다.

- 집의 주 출입면이나 생활 관찰 지점에서 농장 출입구와 밭의 일부를 읽을 수 있어야 한다.
- 숲길 입구에서는 집 전체가 아니라 지붕 일부만 보여 단계적 공개를 보존한다.
- 밭은 집과 짧은 생활 동선으로 이어지되 집 출입구·마당과 겹치지 않는다.
- 헛간·작업마당은 집의 측후면 후보로 두어 전면 시야와 생활 출입을 막지 않는다.
- 수확물의 밭→작업마당 이동은 집 내부를 통과하지 않고 이어져야 한다.
- 농기구 보관은 밭과 작업마당에서 접근 가능하되 집의 휴식·귀환 동선과 충돌하지 않는다.
- 집의 높이 차이는 관찰성과 장소 구분을 위한 것이며 절벽·과도한 축대·통행 불가 경사를 자동 생성할 근거가 아니다.

### 첫 방문 Y자 주동선

농장 경계를 통과한 첫 갈림은 Y자 형태로 구성한다. 한스 집 방향을 첫 방문의 시각적 주동선으로 두고, 밭·작업마당 방향은 처음부터 통행 가능한 보조동선으로 둔다.

- 주동선은 한스 집 지붕·출입면·생활 흔적을 연속해서 읽게 하며 첫 관계 장면으로 이어진다.
- 보조동선은 밭과 작업마당을 자유롭게 관찰할 수 있고, 주동선을 선택하지 않았다는 이유로 잠기지 않는다.
- 두 길의 위계는 강제 벽이나 입력 차단이 아니라 노면의 연속성, 시야 단서, 식생 완충, 기준점 배치로 표현한다.
- 주동선이 집의 전면 출입과 충돌하지 않고, 보조동선이 수확물의 밭→작업마당 이동을 방해하지 않아야 한다.
- 두 길 사이의 후속 지름길 개방 여부와 조건은 아직 확정하지 않는다.

Graph Map은 집으로 향하는 첫 발견 관계와 밭·작업마당으로 향하는 선택 접근 관계를 각각 보존한다. 배치 맵은 두 관계를 하나의 Y자 갈림과 시각 위계로 표현한다. 이는 수동 기획에 따른 감괘 이동 관계 후보이며 실제 플레이어 이동 기록이나 통행 성공 증거는 아니다.

이 표본의 벌목·목재 운반·울타리 수리 WI는 순환 관점에서 진괘 계열의 실행 가능성으로 읽는다. 그러나 현재는 기획과 Graph·배치 준비뿐이므로 실제 실행으로 기록하지 않는다. 향후 같은 WI·Actor·대상·Session·Revision의 기존 행위 기록·권위 상태·EvidencePackage가 확인된 뒤에만 실행을 판정하고, 이를 위해 별도 `pipelineGwae`·`realizedGwae` 필드나 실행 원장을 만들지 않는다.

### 한스 농장 오행 결손 점검

아래 표는 새로운 성숙도 축이 아니라 각 원장의 현행 상태를 오행 관점으로 나란히 읽은 결손 점검표다.

| 오행 관점 | 현재 표본 | 기존 상태에서 읽은 근거·결손 |
| --- | --- | --- |
| 목·WI | 벌목·목재 운반·울타리 수리 WI 후보와 기존 WI 대조 | `Conditional` — 실제 실행·상태 변화 미확인 |
| 화·기획 | 한스 집 주동선, 열린 밭 보조동선, 농장 생활 주택 역할 | `Ready` — 이 기획 r17에서 동결 |
| 토·Graph Map | Nature→Farm 발견, 한스 집, 밭·작업마당 선택 접근 관계 | `Blocked` — 현행 기획과 기존 r10 기대 hash 재동결 필요 |
| 금·배치 맵 | 주택 인스턴스와 Y자 상대 구도 | `Conditional` — 정확 거리·수량·자산·제약 검사 미완료 |
| 수·근거·문맥 | 계획된 진입·생활·수확물 이동 관계 | `Conditional` — 수동 기획뿐이며 실제 이동·관측 기록 없음 |

현재는 기획 근거만으로 전체 완료를 주장하지 않는다. 가장 이른 차단인 Graph Map 재동결과 배치 제약 정밀화를 거친 뒤에도 실제 WI 실행과 결과 근거가 없으면 폐순환은 닫히지 않는다.

이 표는 E 성숙도표가 아니다. E1~E7은 같은 한스 농장 PlayableLoop의 계약·Adapter·결정성·실행 문맥·권위 발현·정제·실제 입력과 귀환을 별도로 판정한다. 현재 표본은 기획과 파일 기반 준비가 중심이므로 오행 관계를 정리했다는 이유만으로 E5~E7을 주장하지 않는다.

### 통합 의미 보존 검토

이번 통합에서 기존 의미를 훼손하거나 같은 책임을 중복하지 않도록 다음 경계를 확정했다.

1. WI의 구체 의미는 기존 `actionGwae`·`operationGwae`·`targetGwae`·`supportGwae`가 계속 소유한다. WI가 순환에서 진괘 역할을 한다는 설명은 별도 schema 필드가 아니다.
2. 실제 WI 실행은 기존 행위 기록·권위 상태·EvidencePackage로 판정한다. 오행 발현을 위한 두 번째 실행 상태나 원장을 만들지 않는다.
3. 오행 상생 순서는 설계 결손을 읽는 도식이다. 실제 Runtime의 `행동→기록·상태→후속 선택` 시간순서를 바꾸거나 스케줄러로 사용하지 않는다.
4. Graph Map·배치 맵·자산은 공간·시각 판독이 필요한 WI에만 요구한다. 비공간·비시각 WI는 사유 있는 기존 `NotApplicable`을 사용한다.
5. `BalancedDraft`·`BalancedForE4`는 삼중 산출물의 추적 준비 상태일 뿐 E/G/H 성숙도나 실제 Unity 성공이 아니다. `BalancedForE4`도 E4 통과가 아니라 E4 검토용 묶음의 동결을 뜻한다.
6. 감괘의 공공 데이터·Simulation 상태·플레이 기록은 필요한 E 단계에서 들어올 수 있고 선택 자료는 필수 자료로 승격하지 않는다.
7. 결과가 귀환·종결로 닫히면 다음 WI를 억지로 만들지 않는다. 다음 후보가 실제 파생된 경우에만 새 E1 계약을 시작한다.

## 기존 H1 재사용 조사 반환

개발의 파일 대조 결과는 `Integrated + Blocked`다.

- `gm-node:hans-house`는 수리 상태와 분리된 안정 WorldObject 정체성으로 재사용한다. 별도 집 Graph Map 노드는 만들지 않는다.
- `h1-stock:farm-worker-waiting`은 집 주변의 귀환·휴식·작업자 대기 행위 역할에만 재사용한다.
- `h1-stock:farm-tool-storage`는 도구 보관·반환을 계속 별도로 소유한다.
- `h1-stock:farm-production`과 `h1-stock:farm-work-yard`는 생산과 수확·집하 역할을 계속 소유한다.
- `h1-stock:nature-shelter`는 Nature 임시 대피·건설 공간이므로 한스의 Farm 생활 주택으로 전용하지 않는다.
- 현행 H1 재고에는 Farm의 영속 생활 주택, 건물 footprint, 출입구, 내부, 소유·이용 허락을 함께 정의하는 정확 항목이 없다.

따라서 집 자체를 담당할 재사용 가능한 **농장 생활 주택 H1**을 둔다. 안정 ID 후보는 `h1-stock:farm-residential-home`, 한국어 표시는 `농장 생활 주택`이다. 이 H1은 건물 정체성·footprint·출입구·내외부 경계·관찰 시야·소유/이용 허락 경계만 소유하고, 휴식·도구·생산·작업 WI를 흡수하지 않는다.

한스 집은 이 일반 H1을 참조하는 특정 배치 인스턴스로 둔다. 이번 한스 생활 농장 배치 맵에서는 필수 인스턴스지만, 모든 `h2-candidate:forest-edge-farm`에 주택을 일괄 강제하지 않는다. 일반 H2 정의에서는 선택 가능한 생활 주택 H1 관계로 검토하고, 이번 배치 맵의 기획 프로필이 한스 집 인스턴스를 필수로 요구한다. 정확 안정 ID 등록·H2 optional 결속·배치 인스턴스 ID는 Graph Map·개발 검증 뒤 확정한다.

### 개발 통합 인수

[농장 생활 주택 H1·한스 배치 준비 개발 검증](../Reports/농장생활주택-H1-한스배치프로필-개발검증-2026-09-02.md)은 다음 파일 기반 준비를 확인했다.

- 일반 H1 `h1-stock:farm-residential-home` 등록
- `h2-candidate:forest-edge-farm`의 선택 H1 관계 등록
- 한스 전용 배치 인스턴스 `placement-instance:forest-edge-farm:hans-residential-home`와 `gm-node:hans-house` 대응
- 한스 준비 프로필의 `artifactGwaeCode: TAE`, `dataSourceKindCode: ManualPlanning`, 근거 없는 `relationGwaeCode: null`
- 공간 지식·공간 자원 회귀 통과

따라서 H1 등록과 한스 주택 인스턴스 식별자 공백은 해소됐다. 다만 현재 기획 목차와 진행 중 Graph Map 판본이 기존 r10 인계의 기대 hash와 달라 공식 Graph Map 생성·전체 회귀는 조기 중단됐다. 이를 조용히 갱신하지 않으며, Graph Map 소유자가 현행 기획과 dirty 맵을 새 판본으로 동결해야 한다. 정확 주동선·거리·높이·수량·Prefab fingerprint·규칙성 검사·Unity 실제 적용이 남아 있으므로 상태는 계속 `BalancedDraft`이고 `BalancedForE4`나 E5가 아니다.

## Presentation E4→E5 배치 맵 관문

이 기획의 공간·배치 대상은 Presentation E4에서 배치 맵을 먼저 동결하고 규칙성 검사를 통과해야 E5 실제 배치 후보가 된다. 배치 맵에는 다음을 남긴다.

- 배치 맵 ID·revision·hash와 이를 만든 기획 revision·hash
- 참조 Graph Map ID·revision·hash 및 대상 노드·엣지
- H 정의 참조, 고유한 `placementInstanceId`, 반복 수와 상대 위치·방향·규모, 전경·중경·배경 역할
- 기준점, 접근·통행·지지·가림·완충·겹침 제약과 주·대체·fallback 자산 fingerprint
- 규칙성 검사 결과, `Blocking`·`Warning`, 열린 결함과 무효화 조건

필수 값이 없거나 참조 판본이 오래됐거나 제약이 충돌하면 E5를 시작하지 않고 표현 E4를 다시 연다. E5는 같은 배치 맵 판본을 실제 Prefab·World 배치·활성 Renderer와 필요한 Collider/Bounds에 결속한다. 실제 적용 중 인스턴스나 제약을 바꾸면 임의 좌표 수정으로 통과시키지 않고 새 배치 맵 판본을 만든다. 배치 맵의 구조 검사는 Unity Scene·Play Mode·Game View 증거가 아니다.

### 울타리 방어 병목 지점 H1 r2 시각 후보

`h1-node-candidate:farm-fence-defense-chokepoint`는 출입문만 떼어 놓은 장식이 아니라, 중앙 통과부와 좌우 울타리 연장을 함께 배치하는 하나의 H1 후보로 정리한다. 플레이어가 이후 배치할 수 있는 모듈의 기준점은 통과부 지면 중앙이며, 농장 안쪽을 `+Y`, 적 접근 바깥쪽을 `-Y`로 본다.

- 중앙 유효 통과 폭: `4.0m`
- 좌우 울타리 연장: 각 `2.5m`
- 문 개방: 농장 안쪽으로 `82°`

- 시각 자료: 표식 없는 `울타리-방어-병목지점-H1-r2-clean.png`와 적 접근·복귀·방어 위치를 보인 `울타리-방어-병목지점-H1-r2-overlay.png`
