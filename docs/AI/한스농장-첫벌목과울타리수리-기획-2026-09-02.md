## 통합 목적

이 문서는 이전에 여러 기획 문서와 D-524~D-542에 흩어진 첫 벌목·울타리 수리의 WI 및 구현 경계를 보존한다. 과거 결정을 삭제하거나 재번호화하지 않지만, 초구의 현재 이야기 순서·한스와의 관계 인과는 수뢰둔 캠페인이 소유한다.

핵심 보완은 다음과 같다. 플레이어는 처음부터 한스를 돕거나 울타리를 고치려고 나무를 베지 않는다. 나무꾼 몸에 밴 감각으로 자발적으로 벌목에 몰입한 뒤, 남은 목재와 망가진 울타리를 함께 알아차리고 `이왕 고치는` 선택으로 행동을 확장한다.

## 행동 후보를 보여 주는 방식

이 장면의 시스템은 정답을 대신 선택하지 않는다. 플레이어가 `지금·여기·나·너`를 보고 현재 목적에 가장 적절한 `이렇게`를 스스로 고를 수 있도록 다음 순서로 돕는다.

1. **환경이 먼저 말한다.** 나무꾼 몸의 익숙한 자세, 허용 나무의 상태, 손도끼, 남은 목재, 손상 울타리를 강제 설명창보다 먼저 판독하게 한다.
2. **조건이 모였을 때만 후보를 좁힌다.** 실제 벌목 완료와 사용 가능한 남은 목재, 접근 가능한 손상 구간을 함께 알아차렸을 때 `현재 보이는 손상 울타리를 모두 고친다`를 행동 후보 카드로 보여 준다.
3. **행동에 필요한 조건을 짧게 드러낸다.** 카드는 `남은 목재 활용`, `가까운 손상 구간`, `직접 수리 가능`처럼 현재 확인된 이유와 예상 시간·목재 소비를 보여 준다. 숨은 호감 보상이나 미래 집 수리를 선택 이유로 미리 공개하지 않는다.
4. **다른 유효 행동을 보존한다.** 보관·판매·그대로 두기·나중에 돌아오기도 같은 카드 묶음에 남기며, 수리를 고르지 않았다고 실패·관계 하락을 주지 않는다.
5. **선택 뒤에는 직접 행동과 결과로 확인한다.** 카드는 자동 수리를 실행하지 않는다. 플레이어가 이동·운반·수리를 수행하고 실제 울타리 상태가 바뀌어야 결과가 성립한다.

따라서 이 장면에서 `울타리 수리`는 현재 단서가 잘 맞을 때 가장 읽기 쉬운 대표 행동이지만 유일한 전역 최적해는 아니다. 목재가 부족하거나 손상 구간에 접근할 수 없거나 즉시 위협이 있다면 시스템은 수리보다 보관·이탈·준비 같은 현재 가능한 대안을 앞세운다. 정확 우선순위 점수·자동 추천 엔진·UI 강조 강도는 아직 만들지 않는다.

## 농장 체류와 메인 이동의 두 진행 방식

울타리 수리 후 플레이어는 한스 집·농장을 작은 생활 거점으로 삼아 머물 수 있고, 바로 메인 퀘스트 단서를 따라 다른 Area로 이동할 수도 있다.

- **농장 체류:** 한스 농장을 실제 생활 거점으로 삼고, `WI-FARM-01`로 선택한 한 구획을 밭갈기한 뒤 파종·관리·수확 또는 다시 다른 생활 행동을 고른다. 벌목·수리·보관·휴식·명상·한스와의 공동 행동도 계속하며 자원·숙련·관계·회복을 쌓는다.
- **메인 이동:** 현재 열린 단서·호송·경비대·Town·Hub 방향으로 출발해 세계의 더 넓은 인과를 따라간다.
- **공유 결과:** 어느 쪽을 고르더라도 이미 완료한 울타리 수리, 획득 자원, 도구 상태, 한스 관계, 행위 기록은 보존한다.
- **비강제:** 농장일을 완료해야만 메인 퀘스트가 열리거나, 메인 퀘스트를 따라야만 농장 기능을 계속 이용할 수 있는 구조로 만들지 않는다.
- **귀환:** 메인 이동 후에도 한스 농장으로 돌아와 남은 생활 일·관계·이상 흔적 조사를 이을 수 있다. 농장에 머물다 출발해도 동일하다.

두 방식은 초반에 영구 고정하는 직업·난이도 선택이 아니다. 플레이어가 현재 목적과 흥미에 따라 번갈아 사용하며, 농장 체류는 메인 스토리의 패널티가 아니라 자원·숙련·관계를 다른 방식으로 준비하는 플레이다.

### 첫 원자 생활 폐루프 — 한 구획 밭갈기

- 플레이어는 한스 관련 메인 퀘스트를 수락하거나 다음 Area로 떠나지 않아도 밭갈기를 선택할 수 있다.
- 한 번의 원자 행동은 선택한 한 Farm 구획을 `Untilled → Tilled`로 바꾸고 밭갈기 행위 기록을 남긴 뒤 농장 생활 선택으로 돌아온다.
- 작업 중단이나 도구·체력·접근·권한·판본 실패는 메인 퀘스트를 강제하지 않는다. 마지막으로 확정된 구획만 보존하고 다시 밭갈기·다른 농장일·휴식·이탈 중 하나를 고르게 한다.
- 같은 생활 거점 안에서 다른 구획에 반복할 수 있지만, 반복 횟수만으로 한스 관계나 메인 진행을 자동 지급하지 않는다.
- 이 원자 모듈은 기존 `WI-FARM-01`을 재사용하고 기존 `playable-loop:farm-crop-cycle.v1` 안에서 먼저 닫는다. 별도 중복 WI나 새 PlayableUnit은 만들지 않는다.

### 기획 E4 준비와 개발 E5 인계

- 기획 스레드는 이 원자 모듈의 E1 의미 계약과 Presentation E4 준비 묶음까지 정한다. 여기에는 Actor·대상 구획·시간·H 역할, Graph Map·배치 맵 관계, `VisualKey`, Synty/대체 후보, 작업 기준점, 접근·통행·지지·가림 제약, 실패·완료 피드백이 포함된다.
- 이 단계에서 E2·E3 코드·시험이 실제로 통과했다고 주장하지 않으며, 문서·후보·규칙성 검사만으로 E4나 E5를 자동 승격하지 않는다.
- 실제 Prefab·Terrain/Decal·Renderer·Collider·입력·권위 상태 사본을 Unity World에 결속하는 E5부터는 개발 통합 담당이 인수하고 월드·공간·배치 담당의 단독 Editor 실행과 증거를 조율한다.

#### E5 집중 질문 운영

- 문답은 당분간 새로운 세계관·경제·NPC 기능을 넓히지 않고, 대표 표본 하나의 Presentation E5를 막는 결정만 한 번에 하나씩 닫는다.
- 첫 추천 표본은 기존 `WI-FARM-01`의 `한 구획 밭갈기`다. 기존 PlayableLoop·상태 전이·Farm H2·배치 맵·자산 조사 계보를 재사용할 수 있어 새 울타리 WI와 관계 전파 규칙을 동시에 만드는 것보다 가장 짧은 검증 경로다.
- 기획이 닫아야 할 순서는 `정확 대상 구획 → 작업 전후 판독 상태 → 플레이어 접근·작업 기준점 → 도구·Actor·Animation 역할 → 입력·실패·완료 피드백 → VisualKey와 주/대체/fallback 후보 동결 → 개발 E5 인계`다.
- 개발 E5는 같은 권위 revision에서 실제 Prefab 또는 대체 표현, 활성 Renderer·Collider·Bounds, 실제 입력 발현, 작업 전후 상태와 귀환을 결속해야 한다. 문서·Graph Map·배치 맵·후보 이미지만으로 E5를 선언하지 않는다.
- 울타리 수리→한스 직접 회복→농장 공동체 간접 회복은 후속 E5 표본으로 보존한다. 첫 밭갈기 E5가 닫히기 전에 이 관계 전파의 새 코드·수치·전체 NPC UI를 선행 조건으로 만들지 않는다.
- E5 차단 질문과 관계없는 미정 항목은 삭제하지 않고 `Deferred`로 유지한다. 첫 표본의 인계가 준비되면 기획 스레드는 Unity 실행을 직접 수행하지 않고 개발 통합 담당에게 넘긴다.

### Farm 오행 공동 준비와 단계별 성장

밭갈기 하나만 E7까지 올린 뒤 같은 조사와 배치를 반복하지 않는다. `WI-FARM-01~06`을 `atomic-closure-cohort:farm-life-five-elements.v1`로 묶어 계절·밭·도구·Actor·Graph Map·배치 맵·표현 후보를 E4까지 함께 준비한다.

- 진괘는 경작·파종·관리·수확·집하·포장의 직접 행동과 작물 대상을 잇는다.
- 태괘는 밭 구획·도구·작업 기준점·접근·통행·배치 제약을 맡는다.
- 감괘는 절기·수분·생육·성숙도·Lot·재고·출하 정보를 맡는다.
- 리괘의 작업 지시·역할·예약·약속과 간괘의 집중·휴식·회복·한스 관계는 필요한 지원 문맥이지만 현행 생산 WI가 소유한다고 확대하지 않고 결손으로 추적한다.

E5 이후에는 경작·파종·생육·수확을 첫 파동, 집하·포장을 두 번째 파동으로 조율한다. 다만 각 WI의 실제 배치·입력·권위 결과·귀환은 독립 판정하고, 묶음의 현재 단계는 가장 낮은 구성 WI를 따른다. 이 기획 확정만으로 기존 WI나 PlayableUnit의 Evidence가 승격되지는 않는다.

### 논밭 오행 관리 H2

개별 작물 WI에만 오행을 붙이지 않고, 여러 H1을 조립해 한 논밭의 생육 순환을 관리하는 보편 H2 계약을 둔다. 새 H2를 중복 생성하지 않고 기존 `h2-candidate:farm-irrigation-service`를 **논밭 오행 관리 H2** 역할로 확장하는 방향을 확정한다. 현행 공간 정의의 실제 명칭·구성 변경은 Graph Map·공간 지식 담당의 재결속 전까지 보류한다.

| 계층 | 책임 |
| --- | --- |
| H1 | 농업 생산구획, 정비 작업장, 기상 보호, 선택적 농기구 보관처럼 플레이어가 직접 보고 접근하는 한 공간 단위와 작업 기준점을 제공 |
| H2 | H1들을 묶어 밭갈기·파종·생육 관리·수확의 조건, 오행 관계, 접근·통행·작업 연결을 한 논밭 관리 순환으로 판정 |
| H3 이상 | 서로 다른 논밭 관리 H2와 생활·집하·가공 H2를 조합해 농장 또는 계절 생산 영역을 형성하되, 하위 WI 결과를 대신 생성하지 않음 |

H2의 기본 역할은 `토(간괘)=토양 기반·운영 수용력`, `목(진괘)=씨앗·작물·생장`, `수(감괘)=관수·수분 흐름`, `금(태괘)=필요한 가지치기와 수확 분리`, `화(리괘)=온전한 생육·성숙 결과`로 둔다. 필수 관계는 `수생목`과 `토극수`, 품종·단계별 선택 관계는 `금극목`, 결과 관계는 `목생화`다.

H2가 성립하려면 필수 H1 구성, H1 사이 Graph Map 엣지, 작업 접근·통행·시야·배수 같은 배치 제약, 적용 WI와 오행 관계 판본이 함께 동결돼야 한다. 이 기획 계약은 H2 후보의 의미를 정리할 뿐 실제 H2 인스턴스, 작물 성장, Unity 배치 또는 Evidence를 자동 성립시키지 않는다.

#### 다음 질문 하나 — 물 공급원의 경계

- 질문 ID: `Q-FARM-H2-WATER-SOURCE-BOUNDARY-01.r1`

| 물류 단계 | 오행·관계 | 의미 |
| --- | --- | --- |

이번 흐름에서는 각 전환에 실제 기능 의미가 있으므로 `목생화→화생토→토생금→금생수`를 적용한다. 다만 이름을 맞추기 위해 상태를 만들지 않으며, 주문·재고·위치·용량·포장·운송 권위 상태가 실제로 분리되어야 한다.

### 오행 정밀화 재검토 — 괘상과 상생·상극의 분리

농장일을 모두 `직접 행동=진괘`로 묶는 분류는 재검토한다. 괘상은 행동의 주된 성격을 나타내고, 상생·상극은 두 괘 사이에서 실제로 일어나는 도움·전환·억제·분리 작용을 나타내는 별도 관계 메타데이터로 둔다.

| 농장 단계 | 주 괘 후보 | 관계 후보 | 기능적 해석 |
| --- | --- | --- | --- |
| 토양 안정·휴경·기르기 | 토(간괘) | 상황별 | 땅·머무름·축적·생육 기반 |
| 씨 뿌리기·싹틔우기 | 목(진괘) | 수생목 후보 | 물과 생육 조건이 씨앗의 성장을 도움 |
| 물주기·수분 이동 | 수(감괘) | 수생목 | 물이 작물의 생장을 도움 |
| 햇빛·열·성숙 전환 | 화(리괘) | 목생화 후보 | 성장한 생명력이 꽃·열매·성숙으로 전환 |
| 열매 따기·베기·수확 | 금(태괘) | 금극목 | 금의 분리·절단 작용이 성장한 작물을 수확물로 분리 |
| 수확물 선별·집하·보관 | 수(감괘) 또는 금(태괘) | 대상별 | 정보·흐름 관리와 물리적 분리·정돈을 구분 |

이 표는 다음 문답을 위한 후보이며 아직 괘성 원장의 확정 분류를 대체하지 않는다. 특히 전통 상생·상극의 이름을 붙였다는 이유만으로 생산량 증가·손실·성공·회복을 자동 계산하지 않는다. 실제 기능 효과는 WI의 권위 상태, 조건, 수치 Profile과 Evidence가 별도로 입증해야 한다.

표시 순서는 오행을 앞세워 `금(태괘)·목(진괘)·수(감괘)·화(리괘)·토(간괘)`로 쓴다. 관계도 괘 이름을 합성한 `감생진` 같은 표기 대신 `수생목·목생화·화생토·토생금·금생수`, `금극목·목극토·토극수·수극화·화극금`처럼 오행 이름으로 기록한다. 괘 코드는 내부 검색·기존 호환을 위해 유지한다.

- 추천: 그렇게 구분한다. 그러면 `태괘가 진괘를 극하여 죽이는 것`이 아니라, 성장 완료 대상을 필요한 수확물로 **분리·완결하는 제어 작용**으로 읽을 수 있다.
- 대가: 기존 `직접 행동=진괘`라는 단순 규칙을 버리고, 집하·포장처럼 혼합 성격의 작업도 단계별로 다시 검토해야 한다.

확정 결과는 `주 행위 금(태괘) / 대상 목(진괘) / 관계 금극목`이다. 해당 관계와 적용 WI 판본이 E4에서 동결되지 않으면 수확 표현은 E5로 진입하지 않는다. 이는 관계 메타데이터만으로 E5가 성립한다는 뜻이 아니라, E5가 실제 Prefab·배치·입력·권위 결과를 결속하기 전에 갖춰야 할 문맥 관문이다.

#### 보존 질문 — 과잉 물주기 결과

- 질문 ID: `Q-FARM-GWAE-GROWTH-PRIMARY-01.r1`
- 상태: `Confirmed`
- 질문: 생육 관리의 주 행위는 토(간괘)로 두고, 그 안의 물주기만 수(감괘)와 `수생목` 작용으로 분리할까?
- 추천: 그렇게 구분한다. 기르는 지속 행위와 물의 공급 행위를 분리하면 생육 관리 하나에 여러 의미를 뭉개지 않으면서도 같은 Farm 작업 묶음에서 함께 준비할 수 있다.
- 대가: `WI-FARM-03`이 단일 명령으로 남을지, 물주기 같은 세부 행동을 하위 계약이나 별도 WI로 나눌지는 후속 검토가 필요하다.

확정 결과는 `생육 운영 토(간괘) / 물주기 수(감괘) / 작물 목(진괘)`이다. 적정 수분은 `수생목`으로 생장을 돕고, 토양 수용력과 현재 수분 상태는 `토극수`로 과잉 공급을 제한한다. 정확 적정량·토양별 수용력·배수·날씨 보정과 과잉 결과는 판본화된 Profile로 남겨야 하며 현재 수치는 미정이다.

온전한 생육은 다음 입력과 제약을 모두 통과했을 때 발동하는 `목생화` 결과로 확정한다.

1. 품종·종자와 토양의 적합성이 확인된다.
2. 수(감괘)의 적정 공급이 `수생목`으로 목(진괘)의 생장을 돕는다.
3. 토(간괘)의 수용력과 현재 수분 상태가 `토극수`로 과잉 수분을 제한한다.
4. 해당 품종·생육 단계에 가지치기가 필요할 때만 금(태괘)의 `금극목` 관리가 적용된다.
5. 필수 조건과 필요한 관리 작업이 충족되면 목(진괘)이 화(리괘)로 이어지는 `목생화`, 즉 온전한 생육·성숙 전환이 열린다.

`금극목`은 모든 작물에 강제하는 상시 작업이 아니다. 가지치기가 필요하지 않은 작물은 해당 조건을 사유 있는 비적용으로 통과한다. 오행 관계는 조건의 의미를 조직하지만 정확 품종·토양·수분·작업 수치와 성공 판정은 별도 Profile과 WI 권위 결과가 소유한다.

#### 다음 질문 하나

- 질문 ID: `Q-FARM-GWAE-OVERWATER-CONSEQUENCE-01.r1`
- 상태: `Deferred / 씨앗·토양 관계 뒤`
- 질문: 물을 지나치게 주었을 때 즉시 작물을 잃게 하지 않고, 먼저 토양 과습 표시와 생육 효율 저하가 나타난 뒤 반복 과잉에서 뿌리 손상으로 진행하게 할까?
- 추천: 단계적으로 진행한다. 첫 실수는 알아차리고 회복할 수 있게 하고, 반복해서 토극수 한계를 무시했을 때만 실제 손상을 남긴다.
- 대가: 토양 수분 상태와 배수·회복 기간을 판독할 표현 및 상태 계약이 추가로 필요하다.

#### 후속 질문 — 씨앗과 토양의 목·토 관계

- 상태: `Asked / 다음 우선`

- 추천: 그렇게 구분한다. 씨앗·토양 적합성은 선행 조건으로 두고, 실제 뿌리 정착·양분 흡수가 시작된 뒤에만 `목극토`를 적용한다.
- 대가: 토양 비옥도·뿌리 정착·연작 소모를 어디까지 첫 Farm 범위에 포함할지 후속 범위 설정이 필요하다.

## 오행 관계

- 나의 행위괘는 벌목과 직접 행동의 진괘(☳)다.
- 금속 손도끼 사용과 울타리·집 수리의 작용은 태괘(☱)다.
- 직접 대상은 나무의 진괘(☳), 울타리·집의 태괘(☱), 사람인 한스와 관계의 간괘(☶)를 구분한다.
- 이 괘성은 `자원 획득→공간 회복→사람의 발견과 관계 형성`을 읽는 메타데이터다. 호감·회복·WI 완료를 자동 지급하지 않는다.

## 현행 초반 흐름

1. 플레이어는 의뢰·보상·선행 목표를 받지 않은 상태에서 숲과 농장 경계를 자유롭게 이동한다.
2. 나무꾼 몸에 밴 감각으로 채취가 허용된 가까운 나무를 알아보고, 개인 손도끼를 장착해 자발적으로 벌목에 몰입한다.
3. 벌목은 실제 접근·도끼질·완료·목재 생성·도구 내구도·시간·체력 소비를 남긴다. 카드 선택이나 연출만으로 끝나지 않는다.
4. 벌목을 마친 뒤 남은 목재와 근처의 망가진 울타리를 함께 알아차린다. 두 단서가 모이기 전에는 수리 카드를 앞세우지 않는다.
5. 이때 `남은 목재로 이왕 울타리도 고친다`를 행동 후보로, `목재를 보관하거나 판매한다`, `그대로 두고 이동한다`를 유효한 대안으로 카드에 보여 준다.
6. 수리를 고른 경우에만 플레이어가 목재를 울타리까지 직접 운반하고 손상 구간에 소비해 수리한다. 다른 선택을 했다고 실패·관계 하락을 주지 않는다.
7. 수리 현장에서는 한스가 바로 나타나거나 즉시 호감을 지급하지 않는다. 실제 수리 결과와 소비 계보만 남긴다.
8. 수리 뒤에도 목재가 남거나 추가로 벌목했다면 한스 집 옆의 안전한 지정 적재 지점에 두고 갈 수 있다. 이는 첫 수리와 분리된 선택이다.
9. 플레이어가 농장 경계를 실제로 벗어나면 사후 발견 구간이 열린다. 한스는 생활 동선에서 실제 수리 결과와 남겨진 목재에 접근할 수 있어야 하며, 경계 이탈만으로 보지 않은 일을 안 것으로 처리하지 않는다.
10. 날짜 변경을 요구하지 않는다. 수리 결과가 보존되고 한스의 사후 발견 조건이 성립한 뒤 플레이어가 농장 경계에 다시 들어오면 첫 직접 대면이 가능해진다. 수리하지 않은 재진입이나 메뉴·화면 재개방은 이 조건을 만들지 않는다.
11. 첫 재진입에서는 달라진 울타리와 한스의 새로운 위치·표식을 이동 중 먼저 관찰한다. 추가 목재·작업 시간 조건까지 성립한 경우에만 집 수리 단계도 별도 후속 귀환에서 드러난다.
12. 한스 머리 위의 `!` 확인 상호작용을 선택하면 한스가 실제 수리를 알아차렸다는 능글맞은 감사와 함께 첫 신뢰가 열린다. 식사·잠자리·허용 구역·주변 정보는 관계와 집 상태가 충족된 것부터 열린다. 새 일반·메인 의뢰는 실제 조건이 생겼을 때만 각각 파란·금색 `?`로 표시한다.

## 두 손도끼의 분리

| 대상 | 시작 상태 | 허용 범위 | 금지 해석 |
| --- | --- | --- | --- |
| 개인 손도끼 | 나무꾼 몸이 이미 소유한 낡았지만 사용 가능한 도구 | 첫 자유 벌목, 기본 운반·생활 작업 | 바닥에서 주워 자동 소유, 무제한 벌목, 완성 전투 숙련 |
| 부러진 농장 손도끼 | 울타리 부근에 놓인 별도 대상 | 조사, 그대로 두기, 인벤토리 보관, 후일 한스에게 명시적으로 수리 맡김 | 수리 전 장착·벌목·전투, 즉시 호감 보상, 새 도끼 생성 |

한스가 부러진 농장 손도끼를 수리하려면 관계와 집 접근, 같은 도끼의 실제 소지, 수리 재료, 한스의 작업 가능 시간, 플레이어의 명시적 맡김이 필요하다. 수리품은 개인 손도끼의 단순 상위 장비가 아니라 가벼운 정밀 목공·수리 작업용 별도 도구다. 한스의 손재주가 뛰어난 이유는 후속 환경·행동 단서로 남긴다.

## 목재 사용처와 관계 비독점

첫 벌목 목재는 한스 관계에 독점되지 않는다. 플레이어는 다음을 선택할 수 있다.

- 개인 보관
- 얼굴을 아는 벌목장 노동자에게 인계
- 목재 상인에게 판매
- 현재 장면에서 판독·접근 가능한 망가진 울타리 전체 수리
- 수리 뒤 남은 목재를 한스 집 옆에 추가 적재

판매나 보관을 선택해도 한스 관계가 실패하지 않는다. 이후 다른 목재를 마련해 울타리를 수리할 수 있고, 한스와 무관한 벌목·거래·운반 관계도 성장할 수 있다. 반대로 울타리를 수리했다고 벌목장·상인 관계나 보상까지 자동으로 열리지 않는다.

## 한스 집의 상태와 표현

권위 상태는 최소 `수리 필요 → 목재 확보 → 수리 중 → 수리됨`을 구분한다. 목재 적재만으로 집이 즉시 완성되지 않으며 한스의 발견·재료 사용·작업 경과가 필요하다.

- 손상 상태: 원본 Synty Farmhouse를 수정하지 않은 프로젝트 전용 Blender 복사본 후보
- 수리 중: Construction 계열 비계·사다리·판재·보강재를 덧입히는 후보
- 수리됨: 가능한 경우 원래 Farmhouse Prefab 재사용

이는 후보 방향이다. 정확 Farmhouse, 손상 부위, Blender 사용 가능 환경, Collider·Bounds·LOD·재질·통행, 단계별 Prefab과 Game View는 Presentation E4 조사와 E5 실제 결속 전까지 미확정이다.

## 집 이후의 플레이

수리된 집을 관찰하고 한스와 확인 대화를 거쳐 이용 허락을 받으면 한스 집은 Nature·Farm 인근의 첫 생활 거점이 된다. 안전할 때 휴식·기본 회복·소량 물자 정리·주변 정보 확인·다음 이동 준비를 지원하지만 경비대 지휘소·무제한 창고·무료 치료소·플레이어 소유 주택은 아니다.

첫날밤은 강제 습격 없이 평온하게 둔다. 실제 첫 벌목 완료 기록이 있다면 안전한 명상에서 도끼 각도·나뭇결·힘 전달·회수 동작을 성찰하는 첫 씨앗을 한 번 보장한다. 벌목하지 않았거나 NPC가 대신했다면 벌목 성찰을 만들지 않는다.

다음 날에는 농장 외곽의 이상 흔적을 관찰할 수 있다. 한스와 확인하거나 혼자 조사하거나 다른 일정을 먼저 수행할 수 있으며 즉시 전투를 강제하지 않는다. 이후 첫 경계 순찰, 한스의 은둔고수 단서, 관리된 검, 깊은 숲에서 밀려난 마수 흐름은 별도 후속 기획으로 유지한다.

### 후속 경계 조우와 전투 도끼술 이데아 연결

후속 경계 조우에서 모험가는 처음부터 완성된 전투 도끼술을 사용하지 않는다. 작은 마수의 접근에 대응하는 순간, 생활 벌목에서 몸에 밴 무게 중심·진입각·힘 전달·회수 동작 일부가 실제 방어·타격 행동으로 먼저 나타난다. 화면과 행위 기록은 이 동작이 우연한 완성 기술이 아니라 `생활 벌목 경험에서 나온 전투 응용`임을 판독할 수 있게 한다.

한스는 조우 뒤 그 동작의 장점과 위험 하나를 짧게 교정한다. 이 교정을 들은 모험가가 공통 원리를 의식하면 이데아 지도에서 별도 `생활 벌목` 노드와 `전투 도끼술` 노드 사이의 관계선이 발현된다. 관계선은 `몸에 밴 동작 관측 → 한스의 교정 → 공통 금 작용 인식`의 근거를 보존하며, 한스의 한마디만으로 완성 숙련·피해 보정·처치 능력을 지급하지 않는다. 한스의 숨은 실력은 이 장면에서 전면 공개하지 않는다.

## Graph Map·배치 맵 결속

- Graph Map은 한스 Actor, 한스 집, 허용 나무, 손상 울타리, 목재와 `벌목→남은 목재 판독→수리 선택→운반·수리→농장 경계 이탈→한스의 사후 발견→재진입→확인 대화·첫 신뢰→추가 적재→집 수리→이용 허락`의 인과 관계를 관리한다. 벌목과 수리 엣지는 현재 시간·공간·Actor·대상에서 가져온 행동에 필요한 조건, 선택 가능 조건, 보존할 대안과 실제 결과를 분리한다.
- 배치 맵은 숲길에서 손상 울타리와 지붕 일부가 단계적으로 보이고, 경계 뒤 Y자 길에서 집 방향 주동선과 밭·작업마당 보조동선이 모두 열리도록 구성한다. 농장 경계 출입 기준과 재진입 때 울타리 변화→한스 표식 순서가 강제 카메라 없이 판독되어야 한다.
- 허용 나무, 목재 도착점, 울타리 작업 기준점과 집 옆 적재 지점은 서로 겹치거나 출입·통행을 막지 않아야 한다.
- 한스 집은 일반 `농장 생활 주택 H1`의 특정 인스턴스이며 Farm 전체 생산 권위나 모든 WI를 소유하지 않는다.
- 이 기획 판본만으로 Graph Map·배치 맵·Prefab·Scene·Unity·E5가 성립하지 않는다.
