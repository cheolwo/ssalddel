## 첫 표본

가상 음식점 하나·주택 둘·기사 하나·오토바이 하나. 한 번에 주문 하나만 다루며 실제 지리·주문·결제·배차를 사용하지 않는다. 사용자는 전체/기사/목적지를 관찰하고 상태와 중단 이유를 읽는다. Farm이나 Hub에서 화물을 받아야 시작하는 구조가 아니다.

주문 → 준비 → 음식점 픽업 → 도로 이동 → 주택 인계 → 복귀를 목표로 한다. 현재 Core의 `Simulation음식배달Snapshot`과 별도 수령 Confirm·Save/Replay를 재사용한다. **기사 실제 배정·도로 통행·복귀는 기존 상태에 없으므로 이번 위치 계산만으로 완료했다고 표시하지 않는다.** 기존 ActorStableId는 주문 실행자일 수 있어 배달 기사로 자동 해석하지 않는다.

## H 조립과 좌표 표본

아래 ID는 이 표본 내부 이름이다. 새 canonical H 채택이나 실제 World 좌표가 아니다. 단위는 미터, 평면 X/Z, 높이는 E5 지형/Collider 검사에서 결정한다.

| 후보 | 구성 | 기존 참조 |
| --- | --- | --- |
| 음식점 앞 블록 H2 | 기사 대기·픽업·정차·도로 진입 H1 | `h1-stock:road-facility-access`, `h1-stock:town-order-packing` 재사용 적합성 검토 |
| 주거 블록 H2 | 주택 A/B 현관 인계·정차·보행 접근 H1 | `h1-stock:town-resident-pickup` 재사용 적합성 검토 |
| 연결 생활권 H3 | 두 H2와 차도 연결 | 새 지역/H4/H5 생성 없이 기존 경관 결속 후보로 인계 |

- 대기점 `(0,0)` → 음식점 정차 `(10,0)` → 회전점 `(20,0)` → `(20,20)`.
- 주택 A 정차 `(30,20)`, 현관 `(30,24)`.
- 주택 B 정차 `(10,20)`, 현관 `(10,24)`.
- 음식점 인계점 `(10,4)`. 차도와 현관 접근은 다른 경로다. 복귀는 해당 표본 경로의 역방향이며 실제 양방향 통행 승인은 E4 배치 검토에서 별도 확인한다.

E4 위치 계산은 명시적인 경로 점 사이를 길이 비례로 이동한다. 구간 단절/폐쇄는 차단하며 직선 지름길로 대체하지 않는다. 오토바이는 정차점에 남고 현관 접근은 기사에게만 적용한다. 도착 위치는 주문 완료 권한이 아니다.

## 확장과 제외

같은 경로·정차·인계 표현을 마트 수령과 창고 출고에 재사용하되 업무별 재고·품질·포장 규칙은 분리한다. 첫 버전에는 동시 다중 주문, 충돌 물리, 교통량, 경로 자동 최적화, LLM, 실제 GIS, 미접속 서버 진행을 넣지 않는다.

실패는 경로 단절·연결 불일치·중단으로 나누고 기존 주문을 삭제하거나 수령 처리하지 않는다. 복구는 동일 주문/경로 판본의 마지막 확인 상태에서 진행한다. 실행 상태에 경로 판본·진행·기사 배정을 저장하는 변경은 후속 권위 WI 명세에 먼저 결속한다.
