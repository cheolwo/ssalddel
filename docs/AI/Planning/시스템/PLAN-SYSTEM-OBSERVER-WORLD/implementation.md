# 관찰 세계 기반 구현 명세

- 기준: `observer-world.r1`, 승인 근거는 같은 폴더 README의 승인 근거.
- 승인 기획 SHA-256: `0EAC7B6EA455BCEEE227EABE09F11AC1745FAD6325F1CB67CAF478A6C0B4C6CD` (현재 UTF-8 파일 기준, 재인계 시 실제 바이트 재검증).
- 이번 지원 모듈: `관찰세계진행Policy` — 실행 엔진이 소비할 시간 구간을 판정하는 순수 정책. 새 WI나 실행 Goal을 등록하는 작업이 아니다.
- 정책 입력: 세계·소유자 ID, 마지막 정산 시각, 접속 여부와 마지막 종료 시각, 직접/자율 제어권.
- 정책 출력: 세계 경과 시간, 분신 활동 가능 시간, 개인 NPC 자원·생산 허용 시간, 대기 사유와 새 체크포인트.
- 저장: 체크포인트 DTO의 JSON 왕복. 입력 객체를 변경하지 않고 별도 Next를 반환하며 실행 구간은 읽기 전용이다. 실제 DB·세션 Save/Replay는 아직 소비하지 않으며 기존 저장 판본·hash를 변경하지 않는다.
- 정확 수정 경로: Application의 `관찰세계진행Policy.cs`, Tests의 `관찰세계진행PolicyTests.cs`, 이 기획·목차·README·현재 작업.

## 현재 구현 단위 — 허용 시간 구간의 명시적 분할

2026-09-06 관찰형 가상 운영의 구현을 계속하라는 요청에 따라 위 지원 모듈의 기존 출력 계약을 보강한다. 승인 기획 r1·24시간 상한·수정 경로를 유지하며 실행 WI·Goal·서버 실행기를 새로 만들지 않는다.

- 모듈 관계: 신뢰 시각과 체크포인트 → `관찰세계진행Policy` → 시간순 `ExecutionWindows` → 향후 효과별 실행기 → 작업 결과와 Next의 원자적 저장. 마지막 두 연결은 미구현이다.
- 각 실행 허용 구간은 UTC 시작·끝(시작 포함, 끝 제외), 분신 활동·자율 제어·개인 NPC 작업 허용을 읽기 전용으로 담는다. 출력된 구간에서는 세계 시간이 흐르며 개인 작업 권한과 구별한다. 미설정/비활성 정책과 0 경과 시간은 구간을 만들지 않는다.
- 미접속 24시간 상한을 넘으면 상한 전의 개인 작업 허용 구간과 상한 후의 세계만 진행하는 구간으로 나눈다. 기존 합산 시간·ReasonCode·PersonalWorkPaused는 유지한다. 마지막 대기 여부만 보고 앞의 허용 시간을 버리거나 전체 구간에 개인 효과를 적용하지 않는다.
- 접속·제어권 변경은 기존 상태의 구간을 먼저 반환한다. 변경된 `Next`를 과거 구간의 권한 판정에 다시 사용하지 않는다. 반환 후 Next를 수정하더라도 구간의 권한과 경계는 변하지 않는다.
- 검증: 상한 전후·정확 경계·재시도·접속/직접 제어 전환·UTC 정규화·최대 날짜·구간 합과 기존 합산 값 일치. 실제 NPC 소비·성장·저장·Unity 화면 증거는 포함하지 않는다.

## E7 → E1 영향 검토 / E1 → E7 검증

| 단계 | 논리 | 표현 |
| --- | --- | --- |
| E1 | 소유자·24시간·미접속 분신 정지 계약 | 관찰 기본·직접 조작 선택·변화 원인 판독 |
| E2 | 시각 입력과 불변 체크포인트를 받는 순수 정책 | 기존 카메라·NPC Presenter 재사용 후보, 미연결 |
| E3 | 경계·재시도·역행·왕복 저장·분할 정산 시험 | 미연결 |
| E4 | 세션 개인 효과·자원 분류와 접속 임대 결속 필요 | 창고 H·Graph Map·배치 맵·자산 판본 결속 필요 |
| E5 | 기존 Tick이 개인 효과를 함께 진행하므로 정책 검사 없는 실행 금지 | 실제 Scene 연결 미실행 |
| E6 | 재시작·작업 중단·복구·다중 접속 시험 필요 | 중단 사유·화면 판독 시험 필요 |
| E7 | 실제 자율 창고 운영·재접속 검증 필요 | Game View에서 관찰·정책 선택·결과 확인 필요 |

이 지원 모듈은 증거 승격 대상 WI가 아니며 정책 시험 통과만으로 Logic/Presentation E3 또는 통합 E를 선언하지 않는다. 실제 WI 인계는 기존 `WI-001`·`WI-002`의 준비된 주체와 E7 작업 명세를 확인하고 승인 기획 hash를 결속한 별도 변경으로 수행한다.

## 안전한 다음 연결 조건

세계별 직렬 실행과 트랜잭션 안에서 `기존 체크포인트 → 허용 구간 → 작업 결과 → 새 체크포인트`를 원자적으로 저장해야 한다. 출력 체크포인트만 저장하거나 결과 반영 전에 진행 완료로 처리하면 안 된다. 접속/종료 변경도 이전 구간 정산과 함께 저장한다. 불명확한 개인/세계 효과는 자동 실행하지 않는다.

주요 차단: 기존 전체 Tick의 개인 성장·소모 영향 분리가 확인되지 않았으며 활성 세션은 프로세스 메모리에 있다. 따라서 이번 순수 정책을 BackgroundService에 곧바로 연결하지 않는다. 서버·Unity·DB·공공데이터 호출은 미실행이다.

정적 근거: `경영SimulationSession.cs`의 `AdvanceWorldState`는 `AdvanceLearningFocus`, `EvaluateNpcRoutineWork`, `AdvanceNpcWorkforce`, `AdvanceDecisionWork`, `AdvanceFarmSurvival` 등을 한 번에 진행한다. 개인 효과를 단순히 마지막에 되돌리는 방식은 행위 기록·저장재생과 어긋나므로 금지한다. 다음 인계에서는 각 효과를 세계/개인 Actor/개인 자산 소유권으로 분류하고 허용 구간을 실제 소비하는 명령 경계를 먼저 만든다.
