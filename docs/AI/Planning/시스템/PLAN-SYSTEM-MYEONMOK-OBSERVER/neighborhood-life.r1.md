# 가상 동네 직업 중심 생활 — 30분 r1

상태: Approved. 승인 근거: 사용자가 직업 중심 생활과 장시간 표본을 선택하고, 1시간을 30분으로 변경한 최종 계획에 `Implement the proposed plan.`을 요청했다. 상위는 PLAN-ARCH-OPERATIONS-UNITY-TRANSFER, 기존 합성 주문 r4의 후속이다. 실제 면목동 지형이나 운영 업무의 증거가 아니다.

## 확정 범위와 권위

새 scenario:synthetic-neighborhood-life.r1 / synthetic-neighborhood-life.r1 / 전용 저장 슬롯만 1,800 Tick을 허용한다. 한 Tick은 관찰 1초이며 기존 프로필의 365 Tick·턴 날짜·저장·해시는 유지한다. 앱 종료 시간 따라잡기, 운영 DB/API, 실제 정산, 플레이어 성장은 없다. 종료 시 미완료 상태를 저장하고 정지하며 재고를 초기화하거나 완료로 바꾸지 않는다.

NPC는 직업을 유지한다. 420 Tick 근무 뒤 신규 배정을 중단하고 기존 업무를 마친 뒤 귀환하여 120 Tick 휴식한다. 주민 두 명은 60 Tick 차례마다 음식/마트를 번갈아 주문하되 미완료 주문 한 건만 가진다. 음식점은 가능한 주문을 자동 수락하며 기존 권한·조리 시간과 수락 다음 Tick 배차 규칙을 재사용한다. 마트는 포장 후 배차한다. 배달기사 세 명, 음식점 주인, 마트 작업자, 보충창고 작업자, 화물기사 한 명을 관찰한다. 공통 생활 상태는 Actor ID로 기존 업무 원장을 참조하며 주문 본문이나 재고를 복제하지 않는다.

업무 Command/Core가 결과를 소유하고 Unity는 동일 Revision 조회 사본을 표현한다. 주체·권한·정책은 기존 NPC 기반을 재사용하며 원장과 표현용 위치의 소유를 분리한다. 자동 업무·조리 시간·작업 우선순위·보충 기준·근무/휴식 설정은 저장 가능한 명령으로 적용하고 재생한다. 음식·창고·화물 배차는 개별 원장을 유지한다. Town 욕구 모듈의 시간만으로 주문 완료시키는 흐름은 이 표본에 켜지 않는다.

## 구현 순서와 직접 결과

P0 기존 r4 실행 기준선과 이관 대응 확인. P1 NPC 근무/휴식·업무 연결. P2 도로 구간·출입구·정차점 점유. P3 창고 검수·적치·출고 예약·피킹·포장. P4 화물차 상하차·마트 보충. P5 30분 관찰·정책·저장 검증. 기존 음식점 수락/조리, CITY 합성 배정/이동/픽업/전달/수령/귀환과 MART 예약/피킹/포장/인계 WI를 재사용한다. 추가 생활·보충 단계는 별도 CITY WI로 소유하고 각 Goal은 WI 하나만 소유한다.

선택은 자동 업무 중단/재개와 정책 변경이다. 대가는 처리량·대기 시간이며 실패는 담당 부재·재고/용량 부족·통로 점유다. 회복은 조건 해소 후 같은 업무 재개, 귀환은 대기점 또는 휴식점이다. 진행 중 작업은 정책 변경으로 취소하지 않는다. 음식점의 수락한 조리는 휴식 전에 끝내며 배달/화물은 인계를 끝내고 쉰다. 재고는 보충창고·운송 중·마트·예약·수령의 합으로 보존한다. 창고 출고 배분 Policy와 기존 피킹 순서·차량 적합성의 순수 조건을 재사용하되 DB 서비스 전체 이관을 주장하지 않는다.

## Required 공간 기준 — 제약 결속

기존 Accepted mart-center.r3 공간·역할색을 보존한다. 추가 합성 보충창고는 서쪽 (-26,-12) 중심, 폭16·깊이10의 지붕 없는 바닥으로 기존 마트와 분리한다. 서쪽 도로를 x=-36까지 명시적으로 연장하며 기존 음식점/주택/대기점은 유지한다. 창고 하역 정차 (-26,-3), 작업 접근 (-26,-8), 적재대 앞 (-30,-14),(-26,-14), 포장·대기 (-22,-14), 마트 보충 정차 (-14,-3), 입고 접근 (-14,-8)을 사용한다. 화물차는 정차점 연결로와 두 정차점 사이의 동서 도로만 사용한다. 창고·마트 사이 도보 지름길이나 건물 중심 통과는 없다. 창고 작업자와 마트 작업자의 각 시설 내부 통로는 독립한다.

구현 점검에서 정차 차량이 통행 도로를 가로막지 않도록 화물차 정차를 도로 중심 z=0에서 z=-3으로 분리했다. 같은 이유로 배달 픽업 정차는 음식점 (10,2.5), 마트 (-10,-2.5), 주택은 (10,22.5)/(30,22.5)로 결속한다. 건물·도로의 원래 중심은 바꾸지 않고 정차점 연결 구간과 교차점을 함께 점유한다. 창고 작업자는 인계 후 (-26,-14)를 거쳐 포장·대기점으로 돌아가 하역 접근점을 비운다. 이 수치는 합성 도형 표본의 배치 보완이며 실제 지형·차량 규격에 대한 승인이 아니다.

공간 실행 수용 조건: 새 도형의 비중첩, 작업점 접근, 기존 도로와 연결, 차량/도보 경계, 구간 양방향 충돌·출구 대기점 확인을 자동 좌표 시험으로 검토한다. 경로 후보의 RuntimeAuthorized=false를 true로 바꾸지 않는다. 합성 실행 경로는 명시한 좌표/점유 정책에만 결속한다. 좁은 통로는 안전 정차점 사이를 한 자원으로 두고 경로 자원과 목적 정차점을 함께 얻은 뒤 이동한다. 구간 묶음은 이동 구간 완료 뒤 해제하며 건물 접근 동안 도로를 계속 소유하지 않는다. 출입구는 진입~귀환 동안 한 명만 사용한다. 이것은 차선·신호등·물리 충돌·일반 교착 해결 엔진이 아니다.

공식 Scene은 SimulationWorldShell 하나다. 도형/밝은 번호판/업무·대기 사유를 사용한다. 실제 새 배치의 Renderer/Bounds·카메라·문자 판독은 별도 실행 검증 전까지 미검증이며 사전 좌표 검사를 Game View 증거로 승격하지 않는다.

## E7 명세·검증·인계

주체는 기존 음식점/NPC/기사/주문자와 합성 창고·화물의 안정 ID로 해석한다. 새 계약은 초기 상태·Revision·Copy·Save/Replay·해시에 함께 연결한다. Logic E7→E1: 30분 종료/재진입→자원 부족/근무 종료→LocalProcess/RemoteHost 공통 Core→이동·작업점→저장·명령→수락/예약/인계→역할/권한. Presentation E7→E1: 실제 판독→대기·귀환→Scene 결속→도형 후보→좌표→사본→역할 의미. 구현은 반대로 계약·규칙·시험·표현·실행 순서다.

검증: 1,800 Tick 상한, 기존 표본 회귀, 수락 전 배차 금지, 준비 전 픽업 금지, 담당/화물 중복 금지, 재고와 적재량 보존, 서로 다른 구간 동시 통행·동일 출입구 순차 사용, 휴식 중 신규 배정 금지, 부족 후 재개, 모든 상태 복제·저장·재생 해시, 정책 멱등/Revision, 저장 실패 정지. 코드·.NET·Unity EditMode·실제 Play·Game View·Hosted는 별도 보고한다. 자동 E 승격·commit·push 없음. 현 작업실은 합성 partial/contract/fixture/전용 시험/관찰 UI만 소유하며 다른 작업의 기존 dirty 변경을 보존한다.
