# 가상 배달 개발 통합 인계 r1

## 담당과 승인 범위

2026-09-07 사용자가 이 작업실을 배달 기능 통합 담당으로 지정하고 기존 변경을 보존하며 범위를 조율하는 질문에 `진행`으로 승인했다. 담당은 `01a06f87-43c4-7150-8138-3368d9744af5`다. [승인 기획](synthetic-observer.r2.md)과 [Accepted 공간 연구](synthetic-spatial-study.r1.md)의 게임 규칙은 바꾸지 않는다.

기존 조리 명세의 담당을 결속하고 겹치던 `Simulation음식배달Tests.cs` 쓰기 경로를 신규 `음식점조리인계Tests.cs`로 분리했다. 기존 시험의 이동·삭제·수정은 없다. 자동 수락 작업의 담당·상태나 다른 작업실은 변경하지 않았다. 이 조율이 배달 WI 등록이나 실제 실행 완료를 뜻하지 않는다.

## 코드 연결과 다음 구현 단위

| 단위 | 현재 확인된 소유자 | 다음 연결 |
| --- | --- | --- |
| 주문 접수·조리 | 공통 Session의 기존 음식점 수락·조리 모듈 | 기존 음식 주문 ID·시설 ID·주문자 ID 보존 |
| 기사 배정 | 새 표본에는 아직 없음 | 첫 전용 WI는 주문 하나와 기사 하나의 배정. 기존 시간 기반 `DispatchCandidateTick`을 실제 기사 정체성으로 대체 해석하지 않음 |
| 거리 진행 | Application의 `동네이동진행Engine` 후보 계산 | Core가 경로 판본·기사 위치·차단 상태를 소유하고 계산 결과를 검증해 적용 |
| 픽업·전달·수령·복귀 | 기존 시간 기반 Task는 있으나 새 경로 흐름에는 미연결 | 각각 다른 직접 결과로 분리. 도착 좌표만으로 주문 완료 금지 |
| 저장·재생 | 기존 Session Save/Replay | 새 기사·배정·경로 진행 상태와 명령을 같은 저장 판본에 포함, 과거 저장 호환 시험 |
| Unity 표시 | 기존 음식점 관찰 카드 | 위 상태 사본을 읽는 표현만 추가. GameObject는 주문·기사 권위 상태를 만들지 않음 |

신규 배달의 첫 WI 명세에는 구체 기사·주문 대상의 안정 식별자, 최초 상태 해석, 저장 정체성, 승인 기획/연구 hash, 정확한 수정 경로를 함께 결속한다. 신규 주체를 검증 없이 Ready로 올리거나 조리 WI 범위를 배달까지 확대하지 않는다. 한 번에 배정·픽업·수령 전체를 단일 WI로 등록하지 않는다.

## 이번 검증 범위

전용 조리 인계 시험은 서로 다른 두 목적지 주문을 생성하고 1·2·3·5 Tick에서 로컬 저장 슬롯을 이용해 재진입한다. 이후 동일 Tick 입력의 주문 상태 사본·revision이 원래 실행과 같고, 두 주문 모두 픽업 대기에서 멈추는지 확인한다. 실제 기사 이동·Unity 실행·새 배달 저장 형식 검증이 아니다.

담당·쓰기 경로 검사는 기존 `manage-development-handoff.ps1`의 Export 후 Check로 수행한다. 결과와 실행한 회귀 시험은 [현재 작업](../../../CURRENT_WORK.md)에 기록한다. 이후 신규 배송 WI 결속부터 이어가며 공간 승인이나 이번 담당 승인을 다시 묻지 않는다.
