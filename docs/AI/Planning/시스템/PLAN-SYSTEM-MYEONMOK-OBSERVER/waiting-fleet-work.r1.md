# 마트·도로변 대기 기사 표현 작업 명세 r1

Approved: 2026-09-07 사용자 “지금 구현을 진행해 봐”. 음식점1·주택2·기사3, 마트 주변과 도로변 별도 정차 자리, 배달 후 가까운 빈 자리, 마트 주문 제외. 공간 방향은 Accepted synthetic-spatial-study.r2.md를 계승한다. 기존 r1 슬롯·명세·hash를 유지한다.

현재 안전 조립 기준: 기존 도로에 별도 정차 자리5개를 연결한다. 마트 주변3개는 (-6,-4),(0,-4),(6,-4), 도로변2개는 (10,16),(30,16). 마트 외형은 (-3,-8). 음식점 정차점과 주택 정차점은 기존 좌표를 유지하며 도로 점유 대상이다. 초기 기사는 마트 자리3개에 각각 배치한다. 음식점/주택 방문 동안 정차·보행·인계·복귀를 하나의 공유 통행 묶음으로 예약하는 보수적 첫 구현을 사용한다. 따라서 첫 표본은 동시에 도로에 움직이는 차량1대이며 대기 기사들은 별도 정차 자리를 사용한다. 다중 차량 동시 통행 최적화·구간별 교착 해결을 완료했다고 하지 않는다.

주체·권위: 기존 합성 NPC 기사·차량·주문·수령자 ID와 WI ASSIGN/MOVE/PICKUP/DELIVER/RECEIVE/RETURN을 사용한다. Session Core가 위치·자리 예약·물품·주문·대기 순서를 소유한다. 후보 평가 후 같은 Tick에서 한 주문에 기사1명만 결속하고 음식 조리 완료·출입구 도착 후 픽업한다. 복귀 중인 기사는 다음 안전 정차 자리 도착 후 수행할 주문을 받을 수 있다. 현재 이동 중인 위치에서 순간이동하거나 경로를 교체하지 않는다.

Logic E7→E1: 두집 전달/복귀→대기/실패→Runtime→정차배치→저장재생→후보/점유→기사/자리 ID. Presentation E7→E1: 실제관찰→정지/재개→canonicalScene→기본도형→좌표시험→조회사본→표현비권위. 이번 E1→E7 조립은 공통 Core/사본/저장해시/전용r2슬롯→Unity기본도형→시험 순으로 진행하며 실제 실행은 별도 기록한다. E 자동 승격 없음.

수정 범위: Simulation 계약·Domain 합성 배달 partial/Session/Hasher, Unity 라이브러리 표본, Unity 저장소 합성 Controller·프로필·Scope, 전용 시험. 단일 담당이 기존 dirty 변경을 보존해 순차 수정한다. Save/Replay, 이동량, 자리 중복, 대기 중 재생, 기존 r1 회귀를 검증한다. 외부 운영 API·실제지도·마트 주문·플레이어 성장·무제한 실행은 제외한다.
