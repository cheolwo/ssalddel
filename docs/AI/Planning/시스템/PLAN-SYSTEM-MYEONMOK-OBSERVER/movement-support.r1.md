# 가상 동네 첫 이동 지원 모듈 r1

## 승인·범위

[기획 r2](synthetic-observer.r2.md)와 [Accepted 공간 기준 r1](synthetic-spatial-study.r1.md)을 입력으로 한다. 이번 단위는 기존 `동네이동경로Engine` 뒤에 붙는 독립 거리 진행·일시정지 시간 지원이다. 실제 WI 확정·새 Session 저장 schema·기사 배정·픽업·수령·복귀 명령은 아직 연결하지 않으며 이를 흉내 낸 별도 주문 원장을 만들지 않는다.

수정 경로: `Ssalddel.Simulation.Application/Neighborhood/동네이동진행Engine.cs`, `관찰시간누적기.cs`, `Ssalddel.Simulation.Tests/가상동네이동Tests.cs`, 시험 프로젝트의 신규 합성 fixture 참조, `eng/neighborhood/fixtures/synthetic-delivery-block.v1.json`, 관련 안내·기획·현재 작업·기존 생성기의 기능/책임 지도. 기존 공유 Core·Unity·저장 schema는 읽기만 한다. 개발 작업이 신규 파일을 소유한다.

## E7→E1 영향과 구현 순서

| 단계 | 논리 | 표현 |
| --- | --- | --- |
| E7 | 두 집 반복 배송의 선행 지원일 뿐 완주를 주장하지 않음 | 실제 화면 완주 미연결 |
| E6 | 차단 시 위치 유지·복구 후 같은 경로 재개 | 물건·탑승/보행 판독 미연결 |
| E5 | 기존 Session/명령·저장/재생 연결은 후속 | Scene·Renderer·Collider 미연결 |
| E4 | 승인된 합성 상대 좌표·차량5m/s·도보1m/s | 실제 배치 승격 없이 입력 표본만 구성 |
| E3 | 단일 Tick·중복 요청·경로 교체·유효하지 않은 복원·정지/재개 시험 | Core 상태를 바꾸지 않는 계산 결과 확인 |
| E2 | 불변 경로 후보→불변 진행 후보, 프레임 시간→최대 한 Tick 요청 | 추후 Presenter가 읽을 위치 계산 |

E1→E3까지만 이번 지원 모듈을 구현한다. `RuntimeAuthorized=false`와 후보 도달 이름을 유지한다. Scene·주체·WI가 연결되지 않은 상태를 승격하지 않는다. 후속 E7 정식 명세에서는 각 WI와 해당 Core 명령·행위 기록을 결속해야 한다.

## 인터페이스·검증 조건

- 경로 후보를 시작하면 지문·현재 거리0·Tick0의 불변 진행 후보를 반환한다. 지문에는 공간ID/판본, 이동 수단, 도로 ID, 전체 굴절점·길이가 포함된다.
- 한 요청은 다음 Tick 하나만 허용한다. 차량은5m, 도보는1m 진행하며 끝을 넘지 않는다. 같은 Tick/같은 차단 입력의 재처리는 같은 상태를 반환하고 내용이 다른 재처리는 거부한다.
- 차단은 현재 위치를 보존한다. 해제 후 정상 Tick 한 번만 진행하며 밀린 거리를 더하지 않는다. 경로 교체는 지문 불일치로 거부하고 다른 경로에 거리만 이식하지 않는다.
- 복원은 동일 경로 지문·유효 거리/정수 Tick/차단 값을 요구하고 위치는 경로에서 재계산한다. 이것은 지원 모듈 복원 시험이지 실제 Session Save/Replay 통합이 아니다.
- 시간 누적기는 재생 중·선행 명령 없음일 때만 1초 단위 Tick 요청을 반환한다. 프레임당 최대 하나, 정지/선행 명령 대기 때 누적 폐기. 호출자는 반환값으로 기존 Runtime 포트에 명령을 보낼 책임을 가진다. 현재 실제 포트에는 연결하지 않는다.
- 새 fixture는 건물3·노드9·도로8의 승인된 합성 지도다. 기존 큰 단위 시험 fixture와 별도이며 실제 면목동 자료를 덮지 않는다.

관련 시험·Fast·Task 결과를 현재 작업에 기록한다. 다음 구현은 실제 주문/기사 주체·WI 결속과 Core의 배정→이동 결과 적용이며 이 지원 모듈 자체는 배달을 완료하지 않는다.
