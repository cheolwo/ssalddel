# 작은 가상 동네 — 공간·표현 적용 연구 r1

- 연구 ID: `study:synthetic-delivery-observer-spatial.r1`
- 상태: `Accepted` (2026-09-07)
- 대상: [가상 배달 관찰 r2](synthetic-observer.r2.md). 배송 WI는 아직 미등록이며 등록 후 정확한 WI별 참조와 hash를 결속한다.
- 조사·검토: 현재 개발 작업, 2026-09-07. 아래 기준안 링크와 기본 도형 3동·명시적 도로/출입구·차량5m/s·도보1m/s·인계1초의 확정 질문에 사용자가 `계속일단진행`으로 답했다. 이를 해당 표본 기준의 승인으로 결속한다. 실제 구현·화면·E 승격 승인은 아니다.
- 질문: 실제 GIS 없이 작은 합성 공간에서 주행·정차·도보·픽업·수령·복귀를 구별할 수 있는가?

## 재고·대안

기존 `Ssalddel.Unity/Presentation/음식배달관찰경로.cs`에는 음식점·주택 A/B의 상대 경로가 있다. 공식 Scene의 기존 음식점 관찰 Bootstrap은 UI·수동 Tick만 연결한다. `Assets/Ssalddel/Presentation/ExhibitionObjects/Prefabs/음식픽업인계상자_A.prefab`은 파일 존재만 확인했으며 선택·접촉·실행 증거가 아니다.

실제 GIS는 권리·형상·출입구 검토가 필요하고, Synty 조합은 실제 자산 선택·Rig·배치 검토가 더 필요하다. 이번 후보는 사용자가 요청한 최소 표본에 맞춰 기본 도형을 직접 구성한다. Synty 원본·Blender·Humanoid Clip을 사용하지 않으며 이후 자산 교체 시 별도 연구를 연다.

## 승인 기준값

좌표는 실제 지리가 아닌 `SyntheticFixture`, 미터, X/Z 평면이다. 기존 경로의 안정 ID·판본은 보존하고 새 합성 배치 입력에서 그 상대 좌표를 참조한다.

| 항목 | 후보 기준 |
| --- | --- |
| 합성 지면 | X=-10~40, Z=-10~35, Y=0. 직접 만든 평면이며 실제 지형 평탄화가 아님 |
| 도로 | 기존 상대 경로의 명시적 선분, 폭 4m. 양방향·차량 1대 전용, 교차선 자동 연결 없음 |
| 대기점 | (0,0) |
| 음식점 | 정차 (10,0), 출입구 (10,4), 외형 중심 (10,7), 폭6×깊이6×높이4m |
| 주택 A/B | 정차 (30,20)/(10,20), 출입구 (30,24)/(10,24), 외형 중심 (30,27)/(10,27), 각각 6×6×4m |
| 도보 접근 | 정차점에서 출입구까지 4m, 폭1.5m. 실내 진입 없이 출입구 앞에서 인계 |
| 차량 | 기본 도형 1.2×2.4m, 5m/s. 도로에서 정차한 뒤에는 움직이지 않음 |
| 기사 | 캡슐 높이1.8m·지름0.6m, 도보1m/s. 탑승 상태에서는 보행 표현을 숨김 |
| 인계 판독 | 출입구에 도착한 뒤 픽업/전달에 각1 Tick. 음식 준비 전 픽업 금지, 수령 확인은 전달 이후 주문자 NPC의 별도 다음 Tick |
| 물건 | 0.35m 상자. 음식점→기사→주택의 상태별 위치 변경으로 소유 인계 표시. 실제 손 접촉 Clip을 입증했다고 하지 않음 |
| 카메라 | 전체 보기에는 전체 표본과 출입구가 보이는 사선 상공 관점, 기사 따라가기에는 현재 기사 위치를 추적. 시야 맞춤은 현재 화면 비율과 후보 Bounds에 5m 여백을 적용 |

차량·도보의 매 Tick 이동량과 경로 진행은 Core가 계산하며 화면 보간은 권위 위치를 바꾸지 않는다. 정차점→현관→정차점 이동을 각 방문에서 수행한다. 준비 전 도착한 기사는 현관 앞에서 기다린다. 길이 막히면 마지막 유효 위치에서 멈추고, 같은 연결이 복구됐을 때만 이어간다. 새 대체 길·순간이동·실제 교통 규칙은 만들지 않는다.

## 분야별 영향과 검증

- 건물 `Required`: 외형 치수와 출입구 경계만 대상. 3개 외형은 실내·공식 H 성장·실제 시설을 증명하지 않는다.
- 공간 `Required`: 위 상대 좌표·속도·대기/회복 방식이 이동 시간과 저장 상태에 영향을 준다. Core 시험에서 선분 길이·진행량·단절·정차/도보 전환을 검증한다.
- 배치 `Required`: 각 출입구·정차점·접근로의 관계와 Renderer/Collider가 필요하다. Scene 조립 전 동일 판본의 배치 입력과 경계 충돌을 검사한다. 기존 다른 영역 Root·Scene 저장을 덮지 않는다.
- 동작 판독 `Required`: 차량/보행/물건 상태 교체를 기본 표현으로 한다. 걷기·탑승·손 인계의 사실적인 애니메이션은 보류하고, 상태가 구별되는지는 실제 Game View로 확인한다.
- Save/Replay: 현재 주문·회차·경로 판본·구간·진행량·운반 상태·대기 사유를 같은 Core 저장 경계에서 복원한다. 기존 저장 슬롯에 새 값을 주입하지 않는다.
- 승인 이후 자동 시험과 실제 World 결속·Game View 검증을 나누며 연구 승인 자체로 E를 올리지 않는다.

## 무효화·다음 입력

실제 GIS 적용, 치수·속도·동선 변경, 실내 진입, 차량 복수화, 충돌 회피, 사실적인 Clip, 다른 H 관계가 필요하면 이 연구를 다시 검토한다. 실제 Scene 배치나 캡처는 아직 수행하지 않았다.

다음 작업: 승인된 기준으로 독립 이동 지원 모듈을 검증하고 배송 WI/주체·E7 작업 명세를 결속한다. 추가 승인 질문을 반복하지 않으며 위 무효화 조건이 발생한 경우에만 재검토한다.
