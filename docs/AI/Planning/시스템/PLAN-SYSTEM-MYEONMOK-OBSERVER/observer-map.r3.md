# 축소하지 않는 동네 관찰 맵 r3

상태: Approved / Required 공간 후보 Accepted (2026-09-07). 구현 범위는 아래 배경·관찰 카메라로 한정한다.

승인 근거: 사용자가 서버 검증 뒤 맵이 줄어든 느낌을 지적하고, 도로변 생활 주택·곳곳의 음식점·기사 이동을 볼 수 있도록 맵을 줄이지 말고 계속 넓히는 방향을 요청했다. [업무 서버 관찰 r2](observer-phone.r2.md)의 정상 API·검증300초·권위/저장 경계는 유지하고, 단일 도로·건물2개로 축소했던 **표현 공간만** 대체한다. 실제 지도나 영업 장소를 추가하는 작업이 아니다.

## 확정

- 검증할 업무가 주문1건이어도 맵 크기를 주문1건에 맞춰 줄이지 않는다. 현재 위치와 길을 보존하고 주변 동네 블록을 추가한다.
- 기존 로컬 동네의90×58 바닥 범위와 서버 관찰58×28 범위를 포함하는 더 큰 배경 공간을 구성한다. 기존 프로필1~5의 배치·행동·저장과 Scene 파일은 변경하지 않는다.
- 실제 서버 연결 음식점(0,6), 주문자 집(16,6), 도로 z=0, 가까운 기사 x=-8→0→16, 먼 기사 대기(-20,8)를 보존한다. 화면 크기를 키우기 위해 서버 좌표·배차 거리·속도·도착 판정을 변경하지 않는다.
- 주변에는 교차도로와 여러 주택·음식점, 기존 맥락의 마트/보충창고를 **미연동 배경 공간**으로 배치한다. 주체나 원장 수를 가짜로 늘리지 않고 현재 업무 연결 지점과 배경 지점을 구분한다.
- 바닥·도로·건물은 확장 가능한 배치 자료로 관리하고 기존 범위 포함/건물·도로 비중첩·접근로 연결을 시험한다. 이후 확장은 기존 지도 제거가 아니라 블록 추가를 기본으로 한다.
- 휴대폰을 열어도 맵 데이터/바닥을 축소하거나 교체하지 않는다. 남은 관찰 영역의 종횡비에 맞춰 전체 동네를 볼 수 있어야 하며, 필요하면 명시적인 전체 보기·확대 관찰을 제공한다.
- 기사 이동은 기존 서버 위치 결과의 표현만 유지한다. 배경 차량을 임의로 순회시켜 서버 배달이 수행된 것처럼 보이지 않게 한다.

## 범위와 다음 단계

이번 단계는 좁아진 서버 관찰 배경의 복구·확장이다. 여러 음식점에서 주문이 발생하고 여러 기사가 장시간 도로를 순회하는 서버 시나리오는 후속 단계다. 배경 건물을 먼저 늘린 것을 다중 음식점/NPC 생활 구현 완료로 보고하지 않는다.

신규 WI·H·Graph Map 의미, 실제 도로/출입 권한, 공공지도·Blender·운영 DB·API 계약·5분 검증 정책을 변경하지 않는다. 공식 Scene은 `SimulationWorldShell` 하나다. 기존 [마트 공간](mart-center.r3.md)·[동네 생활 공간](neighborhood-life.r1.md)은 원래 프로필에서 보존하며 새 배경은 업무 실행 경로가 아니다.

## 담당과 검증

개발 통합은 Hongdal의 이 기획·연결 작업 명세·현재 상태·시각 기록을 소유한다. 월드·공간·배치 담당은 별도 Unity 저장소의 배치 자료·표현 조립·관찰 카메라·집중 시험·실제 Game View를 소유한다. 서로 다른 저장소의 쓰기 경로를 하나의 상대 경로로 섞지 않는다.

공간 후보/배치 수치와 정확 쓰기 경로를 결속한 후 구현한다. Logic 영향은 NotApplicable(업무 상태/원장 불변), Presentation은 E1→E7의 공간 자료·배치·카메라·실제 두 해상도/휴대폰 열림·닫힘·관찰 입력을 검사한다. 이번에는 기존 완료 주문 GET으로 화면을 검증하며 새 주문 생성이나5분 서버 업무 재실행을 자동 포함하지 않는다. E 자동 승격·Scene 저장·commit·push 없음.
