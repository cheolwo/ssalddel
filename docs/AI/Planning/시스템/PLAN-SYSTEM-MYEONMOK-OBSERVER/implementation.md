## 원본 등록 후속 범위 (2026-09-07)

- 승인: 사용자가 `hongdal-mysql-1 / hongdal_dev`의 원본 출처·해시 저장 질문에 저장 후 계속 진행을 요청했다. 앞선 DB 대상 보류를 이 두 파일의 비공개 원본 등록에 한해 해제한다. 서버 기본 연결 설정은 변경하지 않는다.
- 경로 추가: `eng/Ssalddel.NeighborhoodSourceImport/`, `eng/neighborhood/` 안내, 기존 `동네공간SourceRegistration`과 관련 시험·이 문서·확보 기록·현재 작업. 기존 원본 등록 서비스의 `RegisterFileAsync`를 재사용하고 새 DB·migration·전체 서울 건물 정규화·시각 계획을 실행하지 않는다.
- 순서: 원본 두 파일 hash 재검증 → 기존 자료 ID와 GIS/정의서 ID 분리 → 지정 컨테이너·DB 사전 점검 → 원본 계보의 트랜잭션 저장 → 독립 조회 → 동일 입력 재처리·중복 방지. 검토보류를 수집 실행 기록에 남기고 공개·게임 적용 허용은 계속 비활성이다.
- 이어 할 수 있는 범위는 필드 계약·형상 준비의 읽기 전용 대조다. 도로/출입구·적용 권리·공간 연구 승인이 없는 실제 NPC/Scene 통합은 시작하지 않는다.

## 모듈 연결과 구현 순서

1. 기존 `ExternalDataSourceCatalog`에 수동 가져오기 출처를 등록한다. 자동 수집·재배포·API 자격 증명을 켜지 않는다. 기존 `VWorld건물통합정보ImportService`는 이름 있는 DBF 속성 계약을 읽고 원본 ZIP을 보존하지만 SHP 도형을 읽지 않는다. 실제 확보한 `AL_D010`의 `A0~A28` 계약과는 달라 직접 넣을 수 없다. 기존 건물 마스터 ID를 보존하면서 실제 GIS·정의서를 별도 자료 ID로 분리했다.
2. 원본 확보 → 기존 비공개 수집 원장/원본 보존 → GIS 전처리에서 실제 `.prj` 확인·미터 좌표계로 변환·경계 자르기 → 정규화 입력 검증 → `동네공간Snapshot`. 이번 C# 입력은 **전처리 후 전용 JSON**이다. SHP/NGI 파서나 좌표계 재투영기를 새로 구현했다고 주장하지 않는다. 날씨·가격의 `SimulationRealityContext` 계약에 도형을 섞지 않는다.
3. 공간 사본의 명시적 노드/도로 → `동네이동경로Engine` → 경로 후보·실패 사유. 연결되지 않은 가까운 점은 여전히 연결되지 않는다. 건물 윤곽은 이동망 생성의 근거가 아니다. 검토되지 않은 통행·일방통행·출입구 차량 접근은 차단한다.
4. 후속 승인된 Core가 경로 판본·기사 위치·진행·도달 결과를 소유한다. 그 상태 사본을 기존 `음식배달관찰경로`·Presenter·View로 전달한다. **이번 후보 계산기에는 배차 확정·이동 Tick·주문 완료·Unity 연결이 없다.**

실행 명령·입력 필드·제한은 [지도 사전 검사 도구](../../../../../eng/neighborhood/README.md)를 따른다.
