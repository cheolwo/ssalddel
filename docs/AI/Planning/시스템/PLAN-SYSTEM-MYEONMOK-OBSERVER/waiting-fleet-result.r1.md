# 마트·도로변 대기 구현 결과 r1

[작업 명세](waiting-fleet-work.r1.md) · [통합 공간 기준](synthetic-spatial-study.r2.md)

## 실행

Unity에서 `Ssalddel → 실행 프로필 → 마트·도로변 기사 대기`를 선택하고 기존 `SimulationWorldShell`을 Play한다. 기존 단일 기사 메뉴·저장 슬롯은 유지했다. 새 표본은 `scenario:synthetic-delivery.r2`, 전용 저장 슬롯은 `synthetic-delivery-r2-primary`이며 365 Tick 제한이다.

초기 기사3명은 마트 자리3개에서 기다린다. 음식점 주문2건이 발생하면 기존 공통 픽업 평가에 차량·보행 예상 시간을 넣어 배차한다. 가용성·합성 권역·시간·거리·대기 보정을 사용하고 기사별 상태와 선택 이유를 표시한다. 배달 완료 후 마트3개/도로변2개 자리 중 다른 기사가 사용하거나 예약하지 않은 가장 가까운 경로의 자리를 예약해 복귀한다. 복귀 중 새 주문을 받으면 현재 안전 정차를 마친 뒤 새 픽업으로 이동한다. 마트 자체 주문은 만들지 않는다.

## 현재 통행 제한

이번 작은 표본은 도로/음식점 진입을 하나의 보수적 통행 묶음으로 확보하고 배달·복귀 후 해제한다. 동시에 실제 도로를 이동하는 차량은1대다. 다른 기사는 자기 정차 자리에서 기다린다. 출입구도 동시에 사용하지 않는다. 이는 구간별 병렬 통행·교차로 교착 해결·충돌 회피 최적화가 아니다. 다음 개선에서 실제 경로/교차점별 예약으로 세분화할 수 있다.

## 코드·검증

- 공통 Session에 기사 목록·자리/복귀 예약·다음 주문·대기 사유·통행 소유자를 결속했다. 사본 복제·재생 해시를 추가하고 기존 r1 해시 경로는 보존했다. 명령/행위 ID는 r2에서 기사 ID도 포함한다.
- Unity는 새 프로필·전용 슬롯·기사/차량/상자3세트·마트 외형·대기 자리5개·연결로·기사별 따라가기·스크롤 패널을 추가했다. Scene 저장이나 운영 원장은 변경하지 않았다.
- Task `artifacts/local/validation/20260907-085659/`: 두 솔루션 build, Simulation1819/1819, Unity 라이브러리720/720, 코드/E 지도 통과. 신규 Core5개는 초기/중간 저장 복원,365 Tick 완주,동일 재생,단일 통행,이동량,서로 다른 복귀 자리와 사본 불변을 검증한다.
