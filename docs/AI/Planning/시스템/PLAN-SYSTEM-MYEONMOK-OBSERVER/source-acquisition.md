## 면목동 속성의 읽기 전용 검사

원본 해시를 다시 확인한 뒤 압축을 디스크에 풀지 않고 DBF 695,761개 레코드를 끝까지 읽었다. 삭제 표시는 0건이다. `.cpg`가 없고 DBF 언어 표시는 0이므로 **공급처의 문자 인코딩 확정 근거는 아직 없다**. A4 지역명에 대한 엄격한 CP949 해독은 모두 성공했고 UTF-8 해독은 모두 실패했다. 아래 집계는 CP949 후보 해독 결과이며 정규화 정책의 자동 승인이 아니다.

- A4가 `서울특별시 중랑구 면목동`인 속성 **13,389건**, A3 법정동코드는 모두 원본의 `1126010100`이다. A1 GIS 식별자는 비어 있지 않은 서로 다른 값 13,389개이고 A2는 모두 19자리 숫자 형식이다. 이는 이름으로 식별한 **면목동 전체 속성**이며 계획한 500m 구역·도형의 건수나 실제 고유 건축물 수를 인증하지 않는다.
- A16 높이(m): 양수 4,760건, **0은 8,628건**, 숫자로 읽을 수 없는 값 1건. 양수 범위는 원본 표기상 2.3~87.7m다. 0/잘못된 값을 실제 높이나 평탄화 근거로 쓰지 않고 후속 정규화에서 원본 값과 품질 사유를 보존해야 한다.
- A26 지상층수: 양수 12,280건, 0은 1,109건. 층수로 높이를 임의 보충하지 않았다.
- `dbf-aggregate-audit.json`은 합계만 보존한다. 행 단위 주소·건물명·형상·정규화 파일을 새로 저장하지 않았으며 SHP 개별 형상·높이의 실측 정확성·출입 가능성을 확인한 증거가 아니다.

## 적용 전에 해결할 차이

1. **필드 계약:** 받은 `AL_D010`은 `A0~A28`이다. 공식 전체데이터 정의에서 A0는 원천도형ID, A1은 GIS건물통합식별번호, A2는 고유번호, A3는 법정동코드, A16은 높이(m)다. 기존 `VWorld건물통합정보ImportService`는 `UFID`, `SGG_OID`, `PNU` 등 이름이 있는 다른 DBF 계약을 읽는다. `동네공간SourceRegistration`에서 두 자료를 분리했지만 변환기는 아직 연결하지 않았다. 이름만 바꾸거나 같은 건물 마스터로 적재하지 않았으며 코드 호환이나 정규화 완료로 보지 않는다.
2. **이용조건 표기 불일치:** 제공 화면과 펼친 설명은 `CC BY`라고 표시하지만, `CCL라이센스 바로가기`의 실제 링크는 [CC BY-NC-ND 2.0 KR](https://creativecommons.org/licenses/by-nc-nd/2.0/kr/)을 가리킨다. 어느 쪽이 적용되는지 단정하지 않는다. 원본 비공개 검토와 변경·재배포·상업적 게임 적용은 분리하고, 공급처 확인 전 적용·재배포 허용으로 승격하지 않는다. 문의 전송·권한 변경은 하지 않았다.
3. **서버 조회 연결은 별도:** 실행 중인 `hongdal-app-1`의 기본 연결 설정은 `mysql:3306 / ssalddel_dev`이며 이번에 승인받아 저장한 로컬 수집 원장은 `hongdal_dev`다. 이번 승인으로 원본 기록의 저장 대상 보류만 해제했다. 서버 설정은 변경하지 않았으므로 서버 API가 새 기록을 조회하거나 Unity에 제공한다고 주장하지 않는다.

`--import-vworld-building-master`는 자동 migration·전체 건물 속성 적재·분류·시각 계획 생성까지 호출하므로 원본 보존 명령으로 실행하지 않았다. 기존 `RegisterFileAsync`의 원본 계보 등록만 사용했다.

## 다음 작은 작업

권리 표기·문자 인코딩 확인 → AL_D010 전용 필드·높이 품질 처리와 SHP 형상 검증 → 검토된 500m 범위 전처리. 도로·출입구는 별도 원본을 확보하고 공간 연구를 재결속한다. 건물 중심이나 교차선으로 출입구·통행망을 만들지 않는다.

원본 보존·계보 DB 저장·재조회·중복 방지와 속성 합계 검사를 완료했다. 도형 정규화·NPC 실행·Unity/Play Mode/Game View·E 승격·커밋·푸시는 하지 않았다.
