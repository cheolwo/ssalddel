# 살뜰마트 배송센터 — 기획·공간 기준·수직 작업 명세 r3

상태: Approved. 승인 근거: 사용자의 살뜰마트 자체 배송센터 설명, 음식점 빨강·주문자 파랑·창고 하양·기사 검정 지정, 내부 작업자 한 명의 피킹·포장 선택 및 후속 `Implement the proposed plan.`. 기존 r1/r2 기획과 저장은 보존한다. 이 판본은 마트 주문·개방형 내부를 제외하던 종전 범위만 확장한다.

## 주체와 직접 결과

가상 살뜰마트 하나, 적재대 두 개와 각 상품 초기 수량 2, 작업자 한 명, 기존 기사 세 명과 주택 두 곳을 사용한다. 전부 합성 Session Core가 소유하며 운영 DB/API와 다른 Area의 화물을 요구하지 않는다. 사용자는 재생·정지·단계 진행·기사 관찰을 선택한다. 부족 재고와 가용 기사 부재는 대기 사유로 보이며 시간을 건너뛰어 성공시키지 않는다. 표본 종료 뒤 새 표본 선택으로 초기 재고를 복구한다. 재생되지 않은 시간은 진행하지 않는다.

첫 365초 표본은 음식점 주문2건과 마트 주문3건이다. 마트 주문은 두 상품을 한 개씩 요구하므로 2건을 배송하고 나머지1건은 재고 부족으로 대기한다. 정상 경로와 실패 대기를 동시에 관찰하며 자동 재입고·무한 주문 생성은 하지 않는다.

작업 명세는 WI별 독립 단위다: `WI-CITY-SYNTHETIC-MART-RESERVE`(주문→재고 예약), `WI-CITY-SYNTHETIC-MART-PICK`(작업자→적재대 수집), `WI-CITY-SYNTHETIC-MART-PACK`(작업자→포장), `WI-CITY-SYNTHETIC-MART-STAGE`(작업자→인계대). 기존 ASSIGN/MOVE/PICKUP/DELIVER/RECEIVE/RETURN의 픽업 출처만 확장한다. 이 네 WI의 작업 명세와 주체를 등록하고 현 작업실에서 순차 구현하며, 다른 대기 Goal 활성화나 E 승격을 뜻하지 않는다.

## Required 공간 기준 — Accepted

승인된 개방형 도형 공간의 구현 치수: 마트 바닥 중심(-3,-12), 폭18·깊이10, 지붕 없음. 적재대(-8,-14),(-4,-14), 포장대(0,-14), 인계대(-10,-8), 기사 정차(-10,0), 도보 인계(-10,-8). 기존 주택·음식점·대기 자리 좌표는 보존하며 서쪽 도로와 바닥만 확장한다. 내부 작업자는 초당1m, 기사는 기존 차량5m/도보1m를 유지한다. 피킹·포장은 각각2초. 보관 물건은 적재대, 수집 물건은 작업자, 포장 완료 물건은 인계대, 픽업 뒤 물건은 기사에 표시한다. 기존 단일 통행 묶음으로 기사 진입을 직렬화한다.

역할 색상은 음식점 빨강, 주택 파랑, 마트/작업자 하양, 기사/차량 검정. 번호와 상태는 글자로 구분하며 미정인 오행 대응은 추가하지 않는다. 검정 기사에는 밝은 번호판을 붙인다. 기존 기본 도형을 주 후보로 사용하고 Blender·새 Scene·Collider 기반 상태 판정은 제외한다.

## 조립·검증과 소유

현 작업실이 합성 계약·Session partial·Hasher·표본, Unity 합성 Controller·프로필, 전용 시험을 소유한다. 기존 dirty 변경은 보존한다. 새 시나리오/저장 슬롯 r3만 추가한다. 서버의 출고 계획→피킹→포장 완료 후 배차 대기 의미를 재사용하되 DB 의존 engine을 Unity로 복제/호출하지 않는다. 기사 후보 평가와 점유는 기존 공통 Policy를 사용한다.

WI별 Logic E7→E1 영향: 재진입/재고보존→실패대기→공통 Runtime→위치·시간→Save/Replay→원자예약·상태전이→주체/주문 ID. Presentation E7→E1 영향: 관찰/귀환→물품 판독→공식 Scene 조립→도형/색 후보→좌표시험→상태 사본→역할 의미. E1→E7 조립은 계약·상태전이·재생→배달 연결→Unity 도형→시험 순서다. 행위 기록과 동일 Revision 사본을 연결하며 플레이어 성장은 NotApplicable(관찰용 NPC 업무). 자동 시험은 실제 입력·Game View·E 승격의 대체물이 아니다.

검증: 주문 완료 순서, 원자 예약/재고 부족, 피킹·포장 시간, 포장 전 배차 금지, 가용 기사 부재, 중복 진행/인계, 물품 보존, 이동량, 각 단계 저장·재진입·해시, 기존 r1/r2 회귀, Unity 색/좌표/읽기 전용 사본. 운영·Hosted·실제 화면 검증은 별도 기록한다.
