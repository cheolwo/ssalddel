## 사용

`Ssalddel → 실행 프로필 → NPC 직업 생활 · 30분` → `SimulationWorldShell` Play → 오른쪽 아래 `휴대폰` → `동네` → `재생`.

휴대폰을 닫거나 앱을 이동해도 진행은 유지한다. `동네`에서만 명시적으로 재생/정지/한 단계/저장/전체 보기를 요청한다. 시뮬레이션 시각이 30:00(1800 Tick)에 도달하면 정지하며 새 표본은 확인을 한 번 더 거친다. 현재 저장 병목 때문에 실제 30분 안에 이 시각에 도달하지는 못한다. 앱 종료 시간 따라잡기와 운영 서버 연결은 없다.

| 앱 | 확인·선택 |
| --- | --- |
| 동네 | 진행 시간, 주문 수령·NPC·보충 요약, 재생/정지/저장, 전체 보기 |
| 주문 | 음식·마트 원장 → 담당 NPC → 카메라 따라가기·관련 시설 |
| NPC | 업무·근무/휴식·통행 대기, 관련 주문·시설 |
| 창고 | 마트/보충창고 재고·예약·입고 대기와 보충 운송 물품 |
| 정책 | 자동 업무·조리·우선순위·보충 기준·근무/휴식 초안 → 적용 또는 취소 |

정책은 현재 지원하는 두 가지 값 사이를 전환하는 카드다. 자유 숫자 입력이나 새 업무 정책은 아니다. 편집 중에는 세계의 다음 상태가 초안을 덮지 않는다. 적용 성공 뒤 재생을 유지하고 실패하면 정지·저장 재시도를 요구한다. 저장 중에도 앱 탐색·초안 편집·정지 요청은 가능하다. 정책 적용/수동 저장은 현재 저장 뒤 한 건만 대기하며 반복 클릭은 추가로 쌓지 않는다. 이 입력 대기는 주문/배차 원장과 별개다. 원장 ID와 저장 소요 시간은 개발 정보를 펼쳐 확인한다.

## 코드 관계

```text
동네관찰휴대폰View (버튼·앱·초안·재사용 행)
  → 동네관찰휴대폰Binding (입력 연결)
    → 동네관찰SessionController (시간·단일 명령·조회·저장·실패)
      → I동네관찰SessionPort / 동네관찰RuntimeAdapter
        → 기존 LocalSimulationRuntime / Sessions / 정책 / 전용 슬롯
      ← 같은 Session 상태 사본
    → 동네관찰Presenter → 휴대폰 조회 모델
    → 기존 가상배달관찰Controller / 가상동네생활View → 도형·카메라
```

입력·시간 조정은 Hongdal `Ssalddel.Unity/Runtime/Observation`의 UnityEngine 비의존 코드다. Runtime Adapter와 View/Binding은 별도 Unity 저장소에 둔다. 기존 r1~r4의 OnGUI·슬롯·실행 분기는 유지하고 새 생활 프로필의 OnGUI 정책 처리만 제거했다. 매 Tick 저장을 유지하며 저장/명령 소요 시간과 저장 횟수를 표시한다. 순수 Core/파일 검증은 worker에서 실행하고 await 이후 Unity 컨텍스트에서만 View/Transform을 갱신한다. 기존 Runtime gate와 관찰 입력 gate는 동시에 상태를 바꾸지 못하게 한다. 저장 중 경과는 현재 1초 주기까지만 인정하며 밀린 여러 Tick이나 앱 종료 시간을 따라잡지 않는다. UI는 상태 사본이 바뀔 때 모델을 만들고 같은 행 객체를 재사용한다.

## 발견한 성능·통합 보완

초반 실제 저장 약 0.4~0.85초가 기준선 Tick412에서 약 2.34초로 늘었다. 현재 `SaveSlotAsync`는 새 저장 식별자의 패키지를 메모리에 보존하고, 파일 쓰기 전 Replay 복원 검증 → JSON 쓰기 → 임시 파일 재조회·checksum·Replay 복원 검증 → 교체를 수행한다. 이는 소스에서 확인한 호출 순서이고 각 단계의 개별 CPU 비중은 아직 측정하지 않았다. worker 분리는 UI의 주스레드 정체를 해소하는 조치이며 저장 계산량 자체를 줄이지 않는다. 전체 Replay/패키지 보존 비용과 1초 관찰 주기의 관계를 우선 점검해야 한다. 이번 구현은 저장 빈도·검증을 낮추지 않는다.

기존 하단 영역 전환 탭은 휴대폰과 겹치지 않아 보존했다. 새 UI로의 전체 모듈 통합이나 도형 시각 마감이 완료된 것은 아니다.

후속 우선순위는 다음과 같다. 이번 UI 범위를 넘어서는 저장 구조 변경은 별도 설계·호환 검증 후 수행한다.

1. 저장 단계별 CPU·시간·메모리 계측 → 전체 이력 검증과 저장 패키지 보존의 비용 분리 → 체크포인트/증분 검증·보존 상한 후보 검토. 매 Tick 내구성과 손상 탐지·재생 결정성·구형 슬롯 호환을 완료 조건으로 유지한다.
2. 키보드 뒤로 가기 재현 확인. 실제 화면의 `뒤로` 버튼은 정상이나 Escape 키는 화면 변화가 관찰되지 않아 Editor 포커스/입력 전달/코드 원인을 분리하지 못했다. 키보드 경로를 통과로 보고하지 않는다.
3. 기존 영역 탭과 폰의 역할 정리, 장시간 주문 목록의 필터·페이지 또는 가상화 검토. 현재 행 풀은 재사용하지만 전체 원장 수만큼 확장할 수 있다. NPC 휴식 상세에서 같은 상태/사유가 반복되는 문구도 후속 가독성 보완 대상이다. 도형 시각 마감과 새 업무 규칙은 별도 범위다.

기존 시나리오·저장 schema·r1~r4 저장을 변경하지 않았다. 23개 기존 WI 작업 명세에 공통 표현 영향 문서를 연결했으며 E0/승격 비활성·기존 기획 hash를 유지했다. 신규 업무 Goal/실제 운영 효과·Scene 저장·커밋·푸시 없음.
