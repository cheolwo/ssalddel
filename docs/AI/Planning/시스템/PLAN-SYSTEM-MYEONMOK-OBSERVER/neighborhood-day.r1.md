- 기획: `PLAN-SYSTEM-MYEONMOK-OBSERVER` / 사용자 구현 승인 / 구현·검증 진행 중
- 기준: [기존 생활 표본](neighborhood-life.r1.md). 같은 Scene·Actor·도로·주택·저장 슬롯을 재사용한다.
- 주체: 기존 주민 두 명, 음식점 주인, 마트 작업자, 배달 기사 세 명. 보충창고·화물 기사 업무는 삭제하지 않는다.
- 시간: 새 표본의 선택적 압축 하루. 아침 0~299, 낮 300~1049, 저녁 1050~1499, 밤 1500~1799 Tick. 무한 반복하지 않는다.
- 직접 결과: 기존 근무·휴식 → 저녁 신규 배정 중단 → 이미 맡은 일 마무리 → 승인된 통로로 도보 귀가 → 주택 앞 식사·휴식·수면 표시. 차량은 주차 위치에 남긴다.
- 두 주택은 공동 주거동이다. 주민의 기존 집을 유지하고, 대상 근로자는 안정 ID 순서로 교대 배정한다. 가족관계를 추론하지 않는다.
- 주민 식사는 실제 합성 음식 수령 기록이 있을 때 표시한다. 근로자 식사는 생활 표현이며 주문·식품 재고를 새로 소비하지 않는다.
- 선택·대가: 기존 저장은 종전 근무 반복을 유지한다. 새 하루 표본에서 저녁 이후 새 주문·배정을 멈추므로 늦은 미배정 주문은 남을 수 있다.
- 실패·회복: 통로가 점유되면 기다리고 점유 해제 후 재개한다. 업무 지연은 마무리 상태로 남기며, 순간이동·가짜 완료·강제 주문 취소로 귀가시키지 않는다.
- 귀환: 같은 Actor가 일터와 집에서 이어진다. 상세 주거 내부·농어업 확장·정교한 애니메이션은 제외한다.

- 표현: 기존 도형 및 휴대폰 조회에 시간대·상태·주거·다음 행동·오늘 기록을 연결한다. 새 Scene·모드·NPC 복제 없음.

- 무효화: 주택·도로·출입구 좌표나 주체 ID 변경 시 이동 경로 및 표현 검증을 다시 연다.

## 코드 우선·배치 후행 작업 순서

2026-09-08 사용자 조정: 기능마다 Unity 씬을 열어 배치하지 않는다. 기존 공간을 코드와 배치 정의로 관리하고, 검증 가능한 변경 묶음이 준비된 뒤 실제 씬에 반영한다.

1. 주체·상태·행동·시간표·경로·표현 연결을 코드로 정의한다.
2. 정상 진행, 미완료 업무, 통로 대기, 자원 보존, 저장/재생과 기존 기능 회귀를 자동 시험한다.
3. Unity 소비 코드의 컴파일·정합성까지 확인하고 준비된 범위와 미검증 항목을 남긴다.
4. 준비된 변경을 기존 공식 Scene에 묶어서 적용하고 실제 화면·이동·겹침을 확인한다. 이번에는 이 단계를 실행하지 않는다.

기존 코드·씬·모드는 보존한다. 실제 배치 전에는 화면 품질이나 E5 성립을 선언하지 않는다. 다음 코드 검증에서는 점유 통로의 대기·재개 집중 시험과 Unity 소비 코드 컴파일을 보충한다.
