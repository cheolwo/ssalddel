# 한스 농장 — 신티 기반 정교한 양식화

- 기획 ID: `PLAN-VISUAL-HANS-FARM-001`
- 분야: 표현·자산·환경
- 판본: `hans-farm-refined-stylized.r1`
- 상태: `ApprovedForImplementation / VisualAcceptancePending`
- 승인: 사용자가 목표 화풍 `정교한 양식화`를 선택하고 제안 계획의 구현을 명시 요청했다.
- 상위: [수뢰둔 기획](../../스토리/PLAN-STORY-HEX03-CAMPAIGN-001/README.md)
- 기준: [구조 후보 r3 검토](../../../../Reports/한스농장-자연경관-시각검토-2026-09-05.md)
- 관련 WI: `WI-NATURE-20`의 표현을 보존하는 공간 지원. 신규 WI·회복·성장 규칙은 추가하지 않는다.
- Graph Map 영향: 기존 주체·통행·상호작용 관계 유지. 표현 후보 판본과 실제 자산 결속만 필요한 범위에서 갱신한다.
- 플레이 순서: 수뢰둔 농장 장면의 표현 지원이며 캠페인 진행은 변경하지 않는다.
- 다음 단계: 공간 담당 구현·개발 검증 반환 후 사용자가 시각 표본을 검토한다.

## 승인된 목표와 범위

신티의 간결한 형태와 모듈을 유지하면서 Mirror 고유의 재질·조명·환경 표현을 만든다. 표본은 한스 농가주택·앞마당·진입로·울타리·작은 밭이다. 농장 밖 전체 월드 확장, 반실사 교체, 새 자산 구매, 렌더 파이프라인 교체, 애니메이션·권위 상태 변경은 제외한다.

플레이어는 낡았지만 운영되는 농장에 접근하며 진입로·집·경작 구획·수리 대상을 구별할 수 있어야 한다. 시각 표현은 판단을 돕는 보조 층이며 회복 결과나 기능 완료의 권위를 갖지 않는다.

## 구현 순서와 기준

1. 원본 재질 슬롯·UV·색상 연결을 조사하여 집 전체가 단색으로 뭉치거나 다른 표면이 잘못 같은 재질을 쓰는 문제부터 해결한다. 목재·지붕·금속·흙을 구분하고 따뜻한 갈색과 차분한 녹색을 기본 팔레트로 둔다.
2. 기존 URP에서 방향광·환경광·그림자와 노출을 조정한다. 진단용 조명과 실제 게임 조명을 구분하고 검토 카메라의 밝기만 바꿔 제품 개선으로 보고하지 않는다. 효과는 필요할 때만 추가하고 과도한 Bloom·안개·피사계 심도로 결함을 가리지 않는다.
3. 흙길·지면·건물 접점을 자연스럽게 연결한다. 집 하단 흙먼지, 지붕 풍화, 길의 사용 흔적처럼 위치와 원인에 맞는 변화를 절제해 적용한다. 지형 자동 평탄화는 하지 않는다.
4. Blender로 주택 지붕 두께·처마·깨진 판재·울타리 지주를 표본 보강한다. 단순 폴리곤 증가가 목적이 아니며 동일 H1 정체성·크기·피벗·상호작용 기준점을 보존한다. 원본 신티와 기존 r3은 수정하지 않고 프로젝트 소유 파생 파일로 저장한다.
5. 큰 풀의 체감 크기를 줄이고 나무·관목·낮은 풀을 군집으로 구성한다. 경로·문·작업 구획을 가리지 않는다. 정상·손상·수리 상태는 같은 객체의 공통 외형/재질 체계를 공유한다.

## 기존 체계와 검증 상한

기존 Graph Map→배치 맵→Blender→Unity 경로를 재사용한다. 새로운 배치 엔진이나 공식 Scene을 만들지 않는다. 모델·재질 후보는 E4, 실제 월드 결속은 E5 검토 자료로 분리하며 E를 자동 승격하지 않는다. H2/H3 시각 승인도 사용자 표본 검토 전 Pending이다.

서버 API·Simulation 상태·기존 WI의 선택/비용/실패/회복·고유 식별자는 불변이다. 공통 Presenter 수정이 필요하면 개발 소유자와 먼저 조율한다. 대상 환경의 `AGENTS.md`와 기존 작업명세를 확인하고 해당 표현 지원 판본/hash를 결속한 뒤 구현한다.

## 확인할 증거

- 같은 카메라·해상도·조명 조건의 전후 비교, 실제 플레이 눈높이 및 조감도; Blender는 보조 자료.
- 지붕 손상·주택 재질·울타리 지주·흙길 경계의 판독, 부유/매몰/관통/통로 차단 없음, 수리 대상 유지.
- 저장·재개방·재진입 중복 없음과 해당 조립/Presenter 집중시험.
- 동일 환경의 프레임 시간·그리기 호출·메모리 변화. 수집할 수 없는 지표는 미측정으로 명시하며 개선을 추정하지 않는다.
- 실제 UI/Player 입력 여부, Scene/Prefab 관찰, WI 통합, Console 경고를 구분한다.
- 승인 전에 다른 H1으로 일괄 확대하지 않는다. 커밋·푸시는 수행하지 않는다.

## 미정과 반환

사용자 시각 채택과 전면 적용은 미정이다. 구현 시도 결과와 부족한 품질을 별도 결과 보고에 남겨 이 승인 본문/hash는 보존한다. 표본이 기준을 만족하지 못하면 부분 구현/실패를 그대로 반환한다.
