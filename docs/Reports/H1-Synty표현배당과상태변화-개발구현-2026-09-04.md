# H1 Synty 표현 배당과 상태 변화 — 개발 구현 결과

## 결과

기획에서 요구하는 H 공간과 실제 보유 Synty Prefab 사이를 전수 조회하는 별도 표현 배당 대장을 구현했다.
H 의미 원본은 변경하지 않았고 후보 배당·시각 승인·서버 Draft·Unity World 배치·E5를 서로 분리했다.

- 기획 48개: 직접 H 참조 6, WI 간접 참조 9, 직접 영향 없음 33.
- H1 85개: 상호작용 공간 53, 표현 패턴 32.
- H2 38개: 필수 H1 후보 충족 38, 직접 Prefab 배당 0.
- 실제 Unity `Assets/Synty` 조사: Prefab 4,221개.
- H1 후보: `PendingVisualReview` 84, `BlenderRequired` 1, `NoCandidate` 0, `ExactCandidate` 0.
- 상태 변화: 기존 E4 계약 결속 1, `PendingStateContract` 64, 정적 20.
- 서버 역할별 시각 구성 Draft 반입: 0. 시각 검토를 통과한 `ExactCandidate`가 아직 없기 때문이다.

기능 대장의 Prefab 4,211개와 이번 파일 조사 4,221개는 모집단 정의가 다르므로 10개 누락이나 초과로 단정하지 않았다.
GUID 집합과 기능 모듈 대조는 후보의 시각 검토 단계에서 별도 수행한다.

## 구현 경계

- 정책은 H1 의미·역할·출처 팩에 따라 실제 Prefab 이름 후보를 결정적으로 좁히며, 주 후보 하나와 대안 최대 두 개를 기록한다.
- 후보마다 Unity 상대 경로, `.meta` GUID, Prefab SHA-256, meta SHA-256을 동결한다.
- 표현 패턴 H1과 상호작용 H1을 구분하고 H2는 H1 조립 상태만 계산한다.
- 상태 변화는 `Static / Growth / Condition / Occupancy / Inspection / Seasonal` 조사 범주로 분류한다. 기존 WI 상태 계약이 없으면 전·중·후 값을 권위 상태로 확정하지 않고 질문으로 남긴다.
- 기존 Presentation E4의 농장 생활주택 수리만 현재 H1 상태 계약과 직접 결속했다. 나머지 벌목 Actor·나무 낙하는 H1 주체가 아니므로 임의 연결하지 않았다.
- 실제 이미지 적합성, 크기, pivot, Renderer/Collider/Bounds, 통행, Anchor, 입력은 이번 정적 조사에서 입증하지 않았다.

## 발견된 드리프트

현행 H 카탈로그가 참조하는 정의 hash와 현재 정의 파일이 다른 항목을 자동 수정하지 않고 보존했다.

- H1 2개: `h1-stock:farm-tool-storage`, `h1-stock:farm-worker-waiting`.
- H2 14개: Farm 3, Hub 3, Nature 4, Town 4.
- `catalog.v3.json`의 선언 요약 H2 수와 실제 `h2DefinitionRefs` 수 역시 일치하지 않는다. 이번 대장은 실제 참조 38개를 조사 대상으로 사용했다.

이 드리프트는 후보 파일 조사를 막지는 않지만 동일 판본의 배치·E5 진입 전에 카탈로그와 정의를 재결속해야 한다.

## 검증

- 전용 관리자 `Survey / Write / Check / Query` 경로를 구현했다.
- 실제 Unity 파일·meta 재검산과 Survey 결정성을 포함해 전용 회귀 11개가 통과했다.
- 중복 H1, H2 직접 Prefab 배당, 상태 변화 전·중·후 결손을 각각 실패로 차단했다.
- 기존 Presentation E4 후보 풀에 새 관리 기획을 `NotApplicable`로 등록해 기획 48개 분류를 유지했고 기존 회귀 18개가 통과했다.
