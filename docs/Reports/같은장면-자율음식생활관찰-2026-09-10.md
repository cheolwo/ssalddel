# 같은 장면 자율 음식 생활 관찰 구현·검증

- 기준 기획: `PLAN-SYSTEM-MYEONMOK-OBSERVER / same-scene-food-life-observation.r1`
- 관찰 프로필: `observation-profile:synthetic-neighborhood-food-life.v1`
- 실행 Scene: `SimulationWorldShell`
- 자료 경계: 기존 합성 동네. 실제 면목동 GIS·실제 주문·실제 기사 위치가 아니다.

## 구현 결과

운영 앱과 Unity 생활 관찰을 별도 다대다 목록으로 만들었다. `OrdererApp`, `RestaurantDeskApp`, `FoodDeliveryDriverApp`은 첫 음식 생활 프로필과 `SimulationAnalog`로 연결되지만, 프로필은 `SimulationSession / AutonomousNpcWorld / observationPresentationOnly`이며 운영 행위를 허용하지 않는다.

Unity 휴대폰은 주문별 주문자·음식점·배달 기사와 현재 단계를 한 카드에서 보여 준다. 카드 선택은 상세 탐색만 수행하고, 주체 상세의 `이 NPC 따라가기` 또는 시설 위치를 사용자가 다시 선택해야 카메라가 이동한다.

- 이관 대장 구조 회귀: 34/34
- .NET `동네관찰Tests`: 25/25
- .NET `가상동네생활Tests`: 10/10
- .NET `오행음식배달생활관찰Tests`: 1/1

- Unity `가상동네생활Tests`: Runtime 정리 뒤 3/3. 실제 Play 직후 첫 실행은 남아 있던 정적 Runtime 때문에 2/3이었으며 `Reset` 뒤 동일 묶음이 통과했다.
- 실제 Play Mode: 격리 저장의 프로필 5에서 휴대폰 재생 버튼을 한 번 호출하고 주문·정책 입력 없이 진행했다. Tick 50에 첫 음식 주문은 `수령확인`, 담당 기사는 `Idle`, 담당 기사의 현재 주문 ID는 빈 값이었다.

- Unity Console 오류: 0건
- 문서 범위 표준 `Fast`와 이번 변경 파일의 `git diff --check`는 통과했다. 코드 범위 표준 `Fast`와 `Task`는 빌드·시험 전에 이번 변경 밖 기존 E 책임 미분류 8건에서 동일하게 중단됐다. 기능별 직접 빌드·집중 시험 결과는 위 통과 수치로 별도 확인했다.

## 변경하지 않은 범위

운영 API·DB·실제 주문·기사 위치·정산, 새 WI·Goal·공식 Scene은 변경하지 않았다. `SimulationWorldShell.unity`는 저장하지 않았으며 별도 Unity 작업트리에 이미 있던 변경을 보존했다. 실제 마우스 클릭, 운영 서버 연결, 배포 빌드, commit, push는 수행하지 않았다.
