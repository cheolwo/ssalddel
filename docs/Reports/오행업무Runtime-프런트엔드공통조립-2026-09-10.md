# 오행 업무 Runtime 프런트엔드 공통 조립

## 결과

주문·음식점·배차·배송·창고를 웹·모바일·Unity가 같은 업무 의미로 소비하도록 `I오행업무Runtime`과 다섯 역할 포트를 추가했다. 이 계층은 상태나 업무 규칙을 새로 소유하지 않고 기존 `LocalSimulationRuntime`, 음식 주문 Runtime, 물류 Runtime과 `I오행업무규칙Engine`을 조립한다.

## 구현 경계

| 실행 위치 | 조립 | 상태 권위 | 네트워크 |
| --- | --- | --- | --- |
| `LocalProcess` | 한 `LocalSimulationRuntime`을 음식 주문·물류 Adapter로 공유 | 같은 프로세스의 기존 Session Aggregate | 필요 없음 |
| `RemoteHost` | 음식 주문·물류 HTTP Adapter를 한 facade로 조립 | Simulation Server가 실행하는 기존 Core | 필요 |

- 공통 계약: `I주문업무Runtime`, `I음식점업무Runtime`, `I배차업무Runtime`, `I배송업무Runtime`, `I창고업무Runtime`, `I오행업무Runtime`
- 웹·모바일: scoped `I오행업무Runtime` 한 인스턴스에서 다섯 역할 포트를 해석한다.
- Unity Solo: `SimulationWorldLocalRuntimeScope.BusinessRuntime`이 기존 `Runtime`과 같은 인스턴스를 감싼다.
- Unity 첫 소비: `음식점관찰AutoBootstrap`이 기존 세션·정책 포트는 유지하면서 음식 주문 포트만 `BusinessRuntime.Orders`로 `음식점관찰SceneController`에 전달한다.
- 원격 Adapter: 기존 Simulation Server의 음식 주문, 음식점 응답, 수령 확인, 물류 이동, 화물 배차 경로만 호출한다.
- 자동 fallback: 없다. Local/Remote 선택과 `HttpClient` 인증·수명은 조립자가 소유한다.

## 검증

- `오행업무RuntimeCompositionTests`와 기존 음식 주문 Runtime/음식 배달 시험: 37/37 통과, skip 0. Local·Remote 중복 등록을 거부하고 원격 오류를 Local 실행으로 자동 전환하지 않는다.
- `Ssalddel.Simulation.Tests`: restore와 build 성공, warning 0/error 0.
- `Ssalddel.WebApp`, `SsalddelApp`, `OrdererApp`, `RestaurantDeskApp`: build 성공, warning 0/error 0.
- `DriverApp`: build 성공, error 0. 기존 AndroidX NuGet 의존 범위 경고 9건은 이번 조립 오류와 분리한다.
- Unity 생성 project에 새 Contracts/RuntimeCore 링크 소스를 별도 targets로 주입한 `Assembly-CSharp` 비-Editor compile: error 0. 기존 nullable·폐기 API·Synty sample 경고 2,293건은 이번 변경 오류와 분리한다.
- DI 시험에서 facade와 다섯 역할 포트가 한 scope에서 같은 객체임을 확인했다.
- 원격 경로 시험에서 음식 배달, 음식점 응답, 화물 배차, 물류 이동의 실제 route를 확인했다.
- 문서 범위 Fast 검증은 통과했다.
- 코드 범위 표준 Fast는 이번 빌드·시험 전에, 작업 시작 시부터 수정 상태였던 `simulation-unity-code-map` 생성물과 현재 메타데이터의 불일치에서 중단됐다. 다른 작업의 생성물을 `--write`로 덮지 않았으며 위 직접 build·test로 이번 코드 범위를 검증했다.

시험 결과 파일은 `artifacts/local/validation/five-element-frontend-runtime-20260910/simulation-runtime.trx`에 있다.

## 아직 검증하지 않은 것

- Unity Editor가 asmdef 변경을 읽고 프로젝트 파일을 다시 생성하는 실제 import/compile 과정
- Play Mode·Game View의 기사 이동과 다수 NPC 생성·해제
- 실제 Simulation Server 인증과 네트워크 연결
- 모바일 앱의 실제 기기 실행
- 운영 주문 DB·배차·배송에 대한 외부 효과

따라서 이번 완료 범위는 공통 계약·Local/Remote 조립·웹/모바일 등록·Unity 소스 연결, 생성 project compile과 자동 시험이다. 실제 Editor import, 생활 장면 완성이나 운영 연결 성공으로 승격하지 않는다.
