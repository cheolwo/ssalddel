# 사가정 공간과 LH 연결 조사·제한 리팩토링

## 확인된 구조

- Unity `공간동적MapWindowPlanner`: 이동 중심과 상세/활성/선행 반경을 계산한다. L/H와 독립된 순수 계산기다.
- `공간LHStreamingEngine`: 계획을 받아 준비·활성·캐시·해제를 처리하고 표면 격자로 Mesh/Collider를 만든다. LH는 주소나 건물 의미를 생성하는 엔진이 아니다.
- `I공간동적표면Provider`: 높이/경사 공급 교체 경계가 있다. 로컬 조립은 평면 또는 결정적 노이즈를 선택한다. 노이즈는 실제 DEM이 아니다.
- `SimulationWorldStreamingService`: 현재 대관령 중심 EPSG:5186, 500m L2 타일과 검증된 산출물 읽기를 제공한다. 자료 없으면 대기한다. 사가정의 WGS84 ENU 좌표를 이 타일 키에 그대로 넣을 수 없다.
- `공간TileStreamingCompositionRoot.InitializeAsync`는 음식점 관찰 요청에서 일찍 반환한다. 따라서 기존 프로필5 사가정 참고 화면은 LH 서버 스트리밍과 아직 연결되지 않았다.

## 이번에 수정한 범위

- 기존 OSM 변환 결과를 r3로 올리고 건물 이름, 도로명, 건물번호, 호수 원문, 층수 원문, 건물 분류를 보존했다. 기존 602개 중 주소580·이름106·층수33개, 호수0개다. 주소로 동/호수/높이를 생성하지 않는다. 원문 높이와 미상4m 기호값은 유지한다.
- Unity `공간참고자료.cs`로 화면 내부 데이터 형식을 분리했다. 건물 고유 식별자와 판본도 소비한다.
- `공간참고건물WindowQuery`는 기존 LH 동심 창 계산기를 재사용한다. ENU 배치 좌표에서 500m 단위 창을 계산하며 건물 외곽과 교차하는 셀을 조회한다. 경계 건물은 쪼개거나 중복하지 않는다. 음수 좌표는 floor로 계산하고 비정상 좌표·중복 식별자·과도한 반경은 거부한다.
- 기존 사가정 화면은 이 조회로 전체 1km 건물들을 조립한다. 기존 동네·Scene·도로선분·업무 상태는 보존한다. 아직 이동마다 재조립하거나 인접 자료를 내려받는 기능은 아니다.

## 다음 연결의 필수 조건

1. 사가정 DEM의 실제 출처·이용조건·수평 좌표계·수직 기준·해상도·NoData·판본/hash를 확인하고 동결한다. 이번에는 새로운 DEM을 수집하거나 실제 고도를 확인하지 않았다.
2. 기존 검증된 타일 산출물 경로에서 자료를 읽고 ENU 배치 좌표와 높이 기준을 명시적으로 연결한다. 대관령 공급 범위를 사가정으로 위장하지 않는다.
3. 검증된 높이 공급자를 기존 LH 표면 계약에 연결한다. 누락/범위 밖은 자료 대기로 남기고 평면/노이즈로 조용히 대체하지 않는다.
4. 프로필5에는 관심 위치→LH 조회→같은 Root의 표시 갱신을 좁게 결속한다. 기존 업무 상태와 떨어진 표시 수명만 관리한다. 원문 수집을 Update/Tick에 넣지 않는다.
5. 지형 경계 높이·건물 접지·도로 경사·중복 없는 재방문을 검사한 뒤 실제 Play를 확인한다. 자료 없는 인접 구역과 가상 채움은 분리한다.

## 증거 범위

- 이번 작업은 조회·데이터 보존의 제한 리팩토링이다. 실제 DEM 배치, 이동형 자동 확장, 건물 클릭 UI, 동/호실 생성, 출입구·배달 경로, 서버 연결, E 승격을 완료했다고 보지 않는다.
- 별도 CLI 시험은 열린 Editor와 프로젝트 점유 충돌로 시작하지 못했다. Editor를 강제 종료하지 않고 연결된 Pipeline 시험으로 전환했다. 최종 시험 결과는 CURRENT_WORK의 최신 항목을 따른다.
- Play Mode를 종료하고 재컴파일했다. 기존 Scene을 저장하지 않았으며 commit·push 없음.
