## 4. 다음 작은 회차의 관문·소유

1. **개발:** 문답 보고와 동일84 ID/현재 정의를 소유하고 후보·과거 이미지의 차이/공유/미확보를 기록한다. 새 도구가 필요할 때만 정확 소스/출력/연구·명세/보호목록을 먼저 결속한다.
2. **공간 담당:** 기존 이미지·manifest·조립기·승인 연구의 대응을 읽기 검토한다. 현행 동등성이 필요한 소수 대상만 새 격리 촬영안으로 제안하고, 개발의 단독 Editor 슬롯 통보 뒤 실행한다. 이번 첫 반환은 재사용이며 Editor/로드/렌더0.
3. **새 촬영 전:** source/Prefab/Scene/Save/Packages 및 미소유 dirty·카메라/선택/Preview/Graph 기준선, 정확 소유 객체·출력/CreateNew·실패 조기중단·자기정리를 정한다. 읽기만으로 안전하다고 단정하거나 기존 전체 Builder/Scene 저장을 호출하지 않는다.
4. **대상 순서:** 정확 식별된 농업생산/작업마당의 현행 대응→독립 harvest-staging 자료→shelter 전체/방문자·제작 역할→exploration-buffer 채집 판독. 한 대상의 결손은 해당 행에 남기고 다른 독립 후보를 막지 않는다. H1목차 번호는 게임 이동 순서가 아니다.
5. **모바일 반환:** 원본을 바꾸지 않고 대화에 한 이미지씩 표시하고 짧은 설명을 붙인다. 실기기 확인이 없으면 '표시 시도/모바일 수신 미검증'으로 반환한다. 로컬 HTML은 보조이며 공개 호스팅·외부 업로드·구매·설치는 하지 않는다.
