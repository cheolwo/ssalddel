# 화물 배달 운영 기사와 Unity 관찰 경계 보완

## 결과

- 서버 수락 시 추천 라운드와 최신 DB 원장을 다시 읽고 차량·혼적·구간 적재량·전체 시간창을 재평가한다.
- 이미 수락한 운송 수를 추천 노출 제한에서 제거했다. 추천 잠금 수만 기존 노출 한도를 사용한다.
- 기사별 process Gate와 `Serializable` 트랜잭션을 사용하고, 같은 기사·의뢰의 수락 재시도는 멱등 응답으로 끝낸다.
- 화물 기사 작업공간 API를 추가해 활성 운송 전체와 다음 행동 하나, 정렬된 경로 정차점, 근거 상태를 반환한다.
- DriverApp은 별도 `IDriverFreightWorkspaceStore`로 작업공간을 읽고, 추천 경고가 있으면 명시 확인 전 수락 버튼을 비활성화한다.
- Unity 기존 물류 Presenter에 `가상 화물 NPC 관찰 · 실제 화물 운송 없음`을 표시한다.

## 경계

Unity는 `api/v1/driver/*`를 호출하지 않고 실제 GPS·상차·하차·정산을 확정하지 않는다. DriverApp은 운영 화물 기사 앱이며 Simulation Runtime을 조립하지 않는다. 이번 변경은 Scene/Prefab을 새로 만들거나 공공데이터 디오라마 공간을 승격하지 않는다.

## 검증 기록

서버 수락·화물 조율·작업공간·현재 행동·앱 경계 집중 시험 33/33과 DriverApp Windows build 오류 0을 확인했다. Unity 물류 EditMode는 10/10 통과했고 결과는 `artifacts/local/validation/freight-driver-boundary/unity-editmode-2.xml`에 남겼다. 앞선 범위 Fast는 솔루션 build를 통과했고 200개 중 195개가 통과했으나 이번 변경 밖 기존 역할별 Controller metadata 5건 때문에 전체 통과하지 않았다. 최종 재실행은 다른 생성 문서의 후행 공백 4줄로 전역 diff 관문에서 중단됐고, 이번 변경 파일만의 `git diff --check`는 통과했다. 실제 운영 서버·다중 host DB 경쟁·현장 운행·Unity Play Mode/Game View는 별도 검증 대상이다.
