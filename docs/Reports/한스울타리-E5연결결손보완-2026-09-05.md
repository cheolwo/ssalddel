# 한스 울타리 E5 연결 결손 보완

## 범위와 현재 판정

기획 확장보다 작은 기능의 실제 완결을 우선한다. 이번 대상은 `WI-NATURE-20` 첫 울타리 수리이며 기존 도끼 회수·벌목·목재 수집을 재사용한다. Animation은 E6, H2·H3 시각 확정은 별도다. **Logic E5 / Presentation E4 / 통합 E4**를 유지한다. 실제 World 검증 전 E5를 선언하지 않는다.

## 우선순위별 결과

1. 컴파일·명령 경로 복구: Unity 비호환 private record를 일반 불변 클래스로 바꾸고 Local 저장소의 캠페인 재시도 교체 계약을 구현했다. WI-NATURE-19·20의 실행 대장 누락을 보완했다. 승인된 성장 프로필이 없으므로 해당 두 WI의 분야 성장은 사유 있는 NotApplicable로 명시하고 보상을 임의로 추가하지 않았다.
2. 최소 플레이 연결: 기존 Nature Controller 입력에서 도끼 회수와 울타리 수리를 권위 Runtime에 전달하고 같은 조회 상태를 Presenter에 반영한다. Presenter는 재조회마다 객체를 재생성하지 않으며 안정 식별자의 입력 표식을 유지한다. 수리 조건 거부·목재 2개 소비·세 구간 복구·중복 수리 거부·저장 후 복원을 통합 시험했다.
3. 검증 프로필 분리: `SSALDDEL_HANS_FENCE_E5=1` 프로세스 환경으로 `HansFenceE5`를 선택한다. 저장 슬롯은 `hans-fence-e5-r6-primary`다. 검토 시 `SSALDDEL_LOCAL_SAVE_ROOT`도 새 전용 경로로 지정한다. 기존 플레이 저장·공식 Scene은 대체하지 않는다.
4. 관리 정합화: 원본 기획 r28과 상세 설계 r1의 서로 다른 해시를 각각 검사한다. WI19 레거시 Goal은 보존하고 WI20의 별도 주체 결속 Goal을 등록했다. Goal 개수 검사는 고정 숫자 대신 원장으로 계산한다. 생성 상태판은 관리 도구로 갱신했다.
5. 실제 월드·입력 검토: 기존 월드·공간·배치 담당에게 canonical `SimulationWorldShell`의 손상/복구 화면·접지·Collider·Bounds·입력·Console 증거를 요청했다. 반환 전에는 미완료다.

## 검증

- Unity 컴파일 및 Presenter·Core Runtime Adapter EditMode: **18/18 통과**. 결과: `artifacts/local/validation/hans-fence-e5-integration.xml`.
- .NET 집중 회귀: **64/65 통과**. 결과: `artifacts/local/validation/hans-fence-e5-regression.trx`.
- 실패: `WorldInteractionDownwardModuleSkeletonTests.E책임검증기는_현재Application후보의_무사유누락을허용하지않는다`. 캠페인의 `ISimulationHexagramCampaignAttemptStore`, `ISimulationHexagramCampaignRuntime`, `InMemorySimulationHexagramCampaignAttemptStore`, `SimulationHexagramCampaignService`에 대표 E 책임 또는 사유 있는 제외가 없다. 검사를 완화하지 않았으며 별도 보완 대상으로 남긴다.
- 한스 E5 정적 계약 검사: **34사례 통과**. 이 검사의 NotRun 출력은 해당 스크립트가 Unity를 실행하지 않는다는 뜻이다.
- 주체·상호작용 개발 체계 회귀: **통과**.
- 문서 범위 Fast와 이번 Unity 변경 경로의 diff 검사는 통과했다. 코드 범위 Task는 생성 코드 지도가 현행 메타데이터와 달라 사전 검사에서 중단됐다(`artifacts/local/validation/20260905-211154/code-map-check.log`). 따라서 Task의 전체 build/test 통과는 주장하지 않는다. 공유 생성물 전체를 다른 스레드 변경과 함께 재생성하지 않았다.
- 실제 Play Mode·Game View·canonical 배치: **미검증**. EditMode의 실제 Core 실행을 사용자 입력/화면 증거로 대체하지 않는다.
- 원격 서버 연결·운영 DB·AnimationClip·E6/E7 인증·커밋·푸시: 수행하지 않았다.

## 변경 경계

서버 측은 캠페인 서비스의 Unity 호환 내부 형식, WI 실행 대장, 성장 미적용 결속과 회귀 기대값을 수정했다. Unity 측은 Local 저장소 계약, Nature의 선택적 한스 인터페이스/Adapter/Controller, E5 Presenter, 분리 실행 프로필과 EditMode 시험을 수정했다. 공개 API나 운영 데이터의 권위는 변경하지 않았다.
