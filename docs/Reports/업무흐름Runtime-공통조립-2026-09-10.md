# 업무 흐름 Runtime 공통 조립

## 결과

주문·음식점·배차·배송·창고를 웹·모바일·Unity가 공통으로 소비하는 `Ssalddel.BusinessWorkflow` 프로젝트와 `IBusinessWorkflowRuntime` facade를 구성했다. 실행 타입과 파일 이름에서는 오행 용어를 제거했고, 오행·괘상 값은 실행 권위가 없는 선택적 `WorkflowClassificationMetadata`로 격리했다.

## 구현 범위

- 공통 다섯 포트와 facade: `Ssalddel.BusinessWorkflow`
- 순수 규칙: `BusinessWorkflowRuleEngine`, `BusinessObjectInteractionResolver`
- Local 조립: `LocalBusinessWorkflowRuntimeFactory`
- Remote 조립: `RemoteBusinessWorkflowRuntimeFactory`
- 웹·모바일 DI: `AddRemoteBusinessWorkflowRuntime`
- Unity Solo 조립: `SimulationWorldLocalRuntimeScope.BusinessWorkflow`
- Unity 음식점 관찰 소비: 같은 Local Session을 사용하는 `BusinessWorkflow.Orders`
- 물류 공통 계약: `ISimulationLogisticsRuntime`을 Application 구현에서 `Ssalddel.Simulation.Contracts`로 이동

공통 Runtime assembly는 `HttpClient`, ASP.NET DI, Unity, MongoDB에 의존하지 않는다. Local·Remote adapter가 환경별 기술 의존성을 소유하며 원격 실패를 로컬 실행으로 자동 전환하지 않는다.

## 분류 메타데이터 경계

기존 객체·업무의 오행·괘상 값은 설명·검색·계보를 위한 메타데이터로 보존한다.

- `WorkflowClassificationMetadata.IsExecutionAuthority=false`
- 규칙 판정과 객체 결속은 분류 값 없이도 동일하게 수행
- 기존 JSON 분류 필드는 호환 입력으로만 변환
- 분류 불일치를 일반 업무 실행 실패 조건으로 사용하지 않음

## 검증

- 공통 Runtime 조립 집중 시험: 8/8 통과
- 규칙 엔진·객체 결속 집중 시험: 14/14 통과
- `Ssalddel.v3.5.slnx` build: 오류 0, 경고 70
- 경고는 기존 `DriverApp` AndroidX 의존 범위와 기존 nullable/xUnit analyzer 경고이며 이번 공통 Runtime의 컴파일 오류는 아니다.

공통 project, 규칙 project, Local/Remote factory, 웹·모바일 등록과 서버 guard가 함께 컴파일됐다. Unity 외부 프로젝트에는 새 package·asmdef·manifest 연결과 소비 소스를 반영했지만 Unity Editor import, Play Mode, Game View는 실행하지 않았다.

## 변경하지 않은 범위

- 운영 주문·배차·배송 DB와 실제 외부 효과
- 공개 API route와 저장 schema
- Unity Scene·Prefab·Save·게임 권위 상태
- 기존 기획·분류 원장의 역사 stable ID
- 실제 서버 인증과 네트워크 연결

commit과 push는 수행하지 않았다.

## 남은 실제 검증

1. 별도 Unity 검증 슬롯에서 package/asmdef import와 컴파일을 확인한다.
2. LocalProcess 생활 장면에서 같은 Session/Revision을 유지한 채 여러 NPC 수명과 상태 사본 소비를 확인한다.
3. RemoteHost는 실제 인증된 Simulation Server 연결과 오류 정책을 별도로 검증한다.
