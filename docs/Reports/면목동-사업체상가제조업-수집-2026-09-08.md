# 면목동 사업체·상가·제조업 수집 결과

- 요청: 기존 음식점·의료·주택·생활시설에 면목동 상가와 등록 제조업체를 보강하여 밀도 있는 공간 참고 자료를 만든다.
- 실제 결과: 기존 로컬 Docker `hongdal-mysql-1 / hongdal_dev`에 **상가 5,411행 + 등록공장 126행 = 신규 관측 5,537행** 저장·독립 재조회. 비공개 `PendingHumanReview`이며 고유 사업체 5,537개나 현재 영업 확정이 아니다.
- 기존 2,006행 사본과 합친 참고 목록은 7,543행. 원천별 기록은 유지하며 이름·주소 중복 후보를 자동 병합하지 않는다.
- Unity/Scene/Assets/Play/화면 변경·게시·새 키·활용신청·commit·push 없음. 새 주소 연결 파일은 검토용이며 기존 Unity 패널의 동결 입력을 교체하지 않았다.

## 1. 출처와 수집 범위

두 공식 메타데이터에서 무료·이용허락범위 제한 없음을 확인했다. 공개 다운로드를 사용했으며 사용자 로그인·비밀값을 파일이나 로그로 가져오지 않았다. 전국 ZIP은 원본 보존용 컨테이너일 뿐 전국 DB 반입이 아니다. 서울 외 CSV는 해석하지 않았고 면목동 외 관측은 정규화 DB에 넣지 않았다.

상가 선택은 `시군구코드=11260` 및 `법정동코드=1126010100`에 이름/주소 일치까지 검사했다. `면목로`라는 도로명만으로 면목동이라고 판정하지 않는다. 공장은 주소의 명시 `(면목동)`으로 선택했다. 역세권 반경이나 행정동 경계를 임의 생성하지 않았다.

수집일은 2026-09-08이며 기준일과 별도로 보존했다. 상가는 분기, 등록공장은 연간 갱신으로 제공된다. 파일 내 개인 대표자·전화·사업자등록번호를 새로 요구하거나 수집하지 않았다. 상가업소번호는 사업자등록번호가 아니다.

## 3. 중복과 건물 대응

- 새 자료 중 기존 의료·음식점 사본과 정규화 이름+도로명주소가 같은 **994행**을 중복 후보로 기록했다. 같은 업체 확정·삭제·자동 병합은 0이다. 불일치는 새 업체 확정이 아니다.
- 새 자료끼리 이름+주소가 같은 묶음은 38개다. 서로 다른 공급원·업종·지점이 있을 수 있어 별도 기록을 유지한다.
- 기존 주소 정규화와 사가정 r3 OSM 건물 연결을 재사용했다. 새 자료 588행은 단일 주소 후보, 60행은 복수 건물, 4,889행은 현재 지도에 정확 주소 없음이다.
- 기존 213행/121건물과 합하면 **801관측/204건물 후보**다. 건물관리번호를 OSM 객체 ID와 같은 것으로 해석하지 않았다.
- 현재 지도는 사가정 중심 1km 정사각형이며 면목동 전체가 아니다. 미연결은 건물 부재가 아니며 가까운 건물에 강제 배치하지 않았다.

## 4. 실제 저장과 재조회

기존 `평창군공공공간원본등록Service`와 `EfExternalDataIngestionStore`를 그대로 소비했다. 새 DB/테이블/마이그레이션/HTTP 서버는 없다. Compose 프로젝트·서비스·작업 경로·컨테이너·13306 포트·DB를 확인한 기존 비밀값 소비 경계를 재사용했다.

| 확인 | 실제 결과 |
| --- | --- |
| 최초 반입 전 | 새 대상 RecordKey 0행 |
| 최초 트랜잭션 | 신규 5,537 / 갱신 0 |
| 동일 원문 재입력 | 신규 0 / 기존 5,537 / 갱신 0 |
| 별도 연결 재조회 | 5,537행 내용·식별·원본 hash·날짜·검토상태 일치 |
| 이전 음식점·의료/주택 결합 | 기존 DB 이름/주소 또는 원문 내용과 동결 사본 대조 |

동일 입력 재처리에서 관측 LastSeen 갱신은 허용하는 기존 저장소 의미를 유지했다. 원본/선택/receipt의 고정 hash가 달라지면 자동 재동결하지 않고 거부한다. 검토보류 관측을 승인된 게임/운영 결과로 바꾸지 않았다.
