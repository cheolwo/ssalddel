# 면목동 축적 자료의 같은 지도 표현

- 사용자 요청: DB에 축적된 면목동 정보가 기존 실제 Play 카메라에서도 드러나게 한다.
- 기존 사업체 자료의 `business-verify`를 읽기 전용으로 재실행했다. 로컬 `hongdal-mysql-1 / hongdal_dev`에서 상가5411·제조126 = 5537행 검증, DB 쓰기0. 이전 음식점·의료·주택을 결합한 동결 연결 사본은 7543자료 중 801자료/204건물 단일 주소 후보다. 미연결6742행은 임의 배치하지 않는다.
- 기존 `주소공간연결검사`에 정확 사업체 입력/hash 프로필을 추가했다. 이전 사본용 기본 검사와 테스트는 보존하고, 새 사본을 명시적으로 선택할 때만 새 고정hash를 허용한다. 지도판본/원본/내용 검사는 유지한다.
- `면목동주소연결View`는 최신 비공개 `myeonmok-business-20260908-r1/connection.json`을 Editor에서만 읽는다. DB 연결정보나 비공개 원본을 Resources/배포에 넣지 않는다.
- 같은 건물 지붕 위에 참고 윤곽을 표시한다. 음식점 빨강, 상가/시장 주황, 의료 초록, 주택 청록, 제조 흰색, 여러 종류가 연결된 주소는 보라다. 기존 건물/도로 Mesh와 업무 상태는 변경하지 않고 Collider·NPC·주문을 만들지 않는다.
- 의료 비정상 이력은 기존 기본 필터를 유지한다. 윤곽은 기본 표시 자료 기준이며 이력 토글은 목록에만 적용한다. 지도 숫자는 주소별 관측 수이지 점포 수가 아니며 공급원 간 중복 후보도 별도 관측으로 남긴다. 현재 입주/영업·용도 확정은 아니다.
- 기존 패널에서 주소/이름 검색, 자료 이름·종류·원주소·원천 상태·기준일·출처를 볼 수 있다. 상가와 제조업도 별도 한글 분류로 표시한다.
- 최초 변경에서 `Application` 이름 충돌로 컴파일 실패 후 `UnityEngine.Application`으로 수정했다. 그 이전 테스트 결과는 이전 컴파일 결과일 수 있으므로 최종 증거로 사용하지 않는다. 실제 재컴파일·시험·Play 결과는 CURRENT_WORK의 최신 기록을 따른다.
- 새 Scene·DB 쓰기·공개 게시·commit·push 없음. 지리 자료 출처는 © OpenStreetMap contributors / ODbL 1.0이며 기존 사가정 지도 계보를 유지한다.

## 최종 화면 확인

- 최종 표식 겹침 개선 후 재컴파일 `completed/failed=false/errors=[]`, 실제 Play `801자료/204건물/204윤곽` 재확인. 필터 `겸재로30길 42`와 해당 주소 선택을 검증 스크립트로 설정했다. 실제 UI를 포함하는 `ScreenCapture` 결과에서 공동주택 면목마젤란21, 원주소, 운영상태 미확인, 기준/관측일, 출처가 표시되는 것을 판독했다. 실제 마우스 입력 테스트는 아니다.
- 최종 PNG: Unity 저장소 `Documentation/Changes/2026-09-08-myeonmok-data/live-ui.png`. `screenshot` 명령은 다른 기본 카메라를 선택해 이번 증거에서 제외했다. `capture_game_view`는 관찰 카메라 지정이 가능하지만 IMGUI는 제외되므로 패널 증거는 위 실제 프레임 캡처만 사용한다.
- 실제 고도·주소미연결6742행·배달/WI·자동 타일 확대는 이번에 추가하지 않았다. 전체 지도에서는 윤곽이 작고 색상 구분이 약해 근거리 시점/선택 강조는 후속 판독 개선 대상이다. Play는 위 주소 패널을 연 상태로 남겼다.
