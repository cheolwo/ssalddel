# 면목동 주소 중심 현실 공간 레이어·디오라마 r1

## 결론

면목동 현실 관측을 `주소 → 건물 외곽 → 활동 관측`으로 꿰는 비공개 색인과, Unity가 개인정보 없이 읽을 수 있는 표현 투영을 구현했다. 이번 판본은 현실 자료를 게임 상태로 바꾸지 않는다. 건물 입주·현재 영업·출입구·보행 가능·공식 건물 결속도 확정하지 않는다.

주소는 모든 정보를 한 행에 합치는 키가 아니라 서로 다른 근거를 만나는 중심점이다. 원천 식별자, 주소 후보, 공간 포함, 필지와 도로 관계는 별도 관계로 보존한다. 충돌하거나 미확보인 관계를 좌표 근접으로 덮지 않는다.

## 구현 결과

### 1. 비공개 공간 색인

`diorama-build`가 기존 동결 자료만 읽어 다음을 CreateNew로 생성했다.

- `private-spatial-index.json`: 주소 204개, 활동 관측 801개, 토지 표본 30개
- `presentation-projection.json`: Unity용 개인정보 제거 투영
- `manifest.json`: 입력·출력 hash와 범위

비공개 색인은 이름·주소·원천 계보를 보존한다. 표현 투영은 이름·상세 주소·건물관리번호·원천 관측 ID를 제거하고 업종 범주, 연결 상태, 운영 근거 상태, 건물 종류 후보만 전달한다. 세 파일은 `distributionApproved=false`, `gameStateConnected=false`, `privateReviewOnly=true` 경계를 가진다.

출력 SHA-256은 다음과 같다.

| 파일 | SHA-256 |
| --- | --- |
| private-spatial-index.json | `75541D0B0C1C6E80872F71CACDCA5CAAB68DFB6E36FB2B0164ABF7CFDCC6F81A` |
| presentation-projection.json | `01C06DB91774612D4DAA988ADC03216835563B7490E880011E3AD52F544E6FB0` |
| manifest.json | `5B15E35A6E78D55A8EE09E445A0997E27C4E72FB4C5B09BA6563120A606ED413` |

동일 입력으로 다시 생성하면 기존 출력 때문에 거부한다. DB·HTTP·Unity 쓰기는 없다.

### 2. Graph Map과 Placement Map

`jungnang-myeonmok-reference.v2`를 추가했다. 주소 색인은 현실 근거 계층, Unity 투영은 그 비공개 파생 계층이며 `PrivacyProjectionOf` 관계로 연결된다.

- Graph Map: 47노드, 47관계
- Placement Map: 36타일, 주소 기반 건물 overlay 204개
- 관측 집계: 상가 5,411, 공장 602, 음식점 2,397, 활동 801, 지적 6,742, 용도지역 10
- 표본 연결: 공식 건물 0, 주소 단일 후보 14, 복수 후보 8, 연결 불가 8

기존 v1은 45노드·44관계·overlay 0으로 그대로 재검증했다. v2를 만들었다는 사실은 공식 건물 결속이나 Unity 배치 완료를 뜻하지 않는다.

### 3. Unity 표현 소비자

Unity에는 개인정보 제거 투영 DTO·검사기와 기존 면목동 주소 검토 View 소비를 연결했다.

- 기본 화면: 업종 범주, 관측 수, 연결 상태, 영업 근거 상태, 높이 의미만 표시
- 명시 토글: 로컬 상세 주소·상호 검토를 켠 경우에만 기존 비공개 원천을 표시
- 독립 표시 토글: 도로·교통, 건물 외곽·건물 종류, 업종 관측
- 자료에는 7개 논리 레이어가 있으나 지역 타일·필지·게임 시나리오는 이번 화면 표본에 독립 도형이 없다.

Marker는 기존 관찰 Root 아래의 비충돌 표현이며 Collider·업무 객체·Camera·Scene을 만들지 않는다. DB 저장, Reality Context 승인, 게임 사업체·NPC 생성도 하지 않는다.

## 검증

| 검증 | 결과 |
| --- | --- |
| 디오라마 생성기 빌드 | 경고 0, 오류 0 |
| 디오라마 자체검사 | 12/12 통과 |
| 생성물 재검증 | 204주소·801관측·30토지표본, 개인정보 제거 통과 |
| 중복 생성 거부 | 통과 |
| Graph/Placement v1·v2 회귀 | v1/v2 기준선과 10개 거부 사례 통과 |
| Unity Runtime·Bootstrap·EditMode 어셈블리 컴파일 | 오류 0; Runtime 74, Bootstrap 852, 최종 EditMode 의존 트리 1,100 경고 |
| Unity EditMode 실행 | 미실행 |
| Play Mode·Game View | 미실행 |

Unity Editor는 기존 별도 작업에서 연결 불가 상태였으므로 재시작하거나 Scene을 열지 않았다. 따라서 레이어 토글과 실제 디오라마 화면은 코드 준비·어셈블리 컴파일까지만 검증됐으며 실제 화면 성공으로 승격하지 않는다.

## 다음 순서

1. 공식 건물 외곽과 건물관리번호 대응 자료를 확보해 `공식식별연결` 0건을 먼저 해소한다.
2. 필지·도로 도형을 현재 30개 표본과 연결하되, 접함을 출입 가능으로 해석하지 않는다.
3. Editor가 정상화된 별도 승인 슬롯에서 기존 Scene을 저장하지 않고 레이어 토글·카메라·전신 공간 판독을 확인한다.
4. 그 뒤에만 Unity용 건물 외형 후보와 실제 배치 규칙을 별도 승인한다.

현재 산출물은 비공개 검토용 현실 관측과 표현 준비다. 게임의 면목동, 현재 영업 중 사업체, 권위 주소·주거·가격·NPC 상태가 아니다.
